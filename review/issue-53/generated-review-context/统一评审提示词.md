### 必须范围（in_scope）

- `generic_agent_core`：Python Agent Core/Host/Runtime 保持业务中立，新增业务不要求修改 Core 业务路由或状态机。
- `unified_plugin`：唯一 Plugin Manager、Plugin Package、IPC 和 Event/Delivery/Tools Extension 分发。
- `skill_import_selection`：已发布 Skill 包导入、Core-owned SkillCatalog、when 选择和 Continuation 优先。
- `published_assurance`：消费外部 Compiler 发布的 Assurance Artifact；Agent 不内置、不调用 Compiler。
- `runtime_action_boundary`：Deterministic 与 LLM-guided 共用 Runtime Action Boundary 和 Tool Plugin 路径。
- `owner_outcome_semantics`：Receipt、Commit Proof、Outcome、UNKNOWN、Wait/Resume/Reconcile 的正确语义。
- `event_binary_handoff`：SBI JSON/multipart、Content-ID、N1/N2 原始二进制与 Host-owned Artifact Handoff。
- `business_neutrality_e2e`：Echo 后接入 OpenAMSM，验证新增业务不要求修改 Agent Core，并完成声明的 Demo E2E。
- `runnable_examples_acceptance`：新增外部可观察机制必须有可运行 Example 和自动化 Acceptance。

### 始终必须满足的正确性要求（always_required）

- `basic_validation`：基本输入、Schema、版本、Manifest、引用和路径校验；错误明确并 fail-closed。
- `runtime_scope_checks`：Runtime 必须检查所选 Skill 声明的 Capability/callable scope；LLM 不得绕过 Runtime 直接调用 Plugin。
- `owner_commit_proof`：需要 Owner 提交证明的 mutation 不得由 HTTP/IPC 成功或模型文本判定为 COMMITTED；UNKNOWN 保持 UNKNOWN。
- `continuation_and_replay`：重复 Event、Continuation 和旧消息不得导致重复 mutation 或推进错误 Run。
- `binary_payload_fidelity`：原始 N1/N2 字节、Content-ID 关联和 artifactRef 的来源及传递边界必须正确。
- `evidence_integrity`：DESIGN、IMPLEMENTED、PASS、NOT_RUN、BLOCKED 必须按真实证据区分，不得虚报测试或 E2E。
