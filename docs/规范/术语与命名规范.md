## 1. 统一术语

| 术语 | 统一含义 | 不应混淆为 |
|---|---|---|
| Agent / Agent Core | 通用 Agent 的推理、选择和执行协调核心 | OpenAMSM 业务 Agent |
| Host | 管理 Event、Run、Context、Artifact 和模型循环的 Python 运行宿主 | Plugin Manager |
| Runtime | 执行 Action 范围检查、分发、Outcome/Evidence 和续跑的执行控制点 | LLM Model Loop 或 Skill Admission |
| Plugin | 由唯一 Plugin Manager 管理的包/独立进程单元 | Tool Operation |
| Extension | Plugin 对 Host 暴露的接口类型 | 独立 Manager |
| Tool Plugin | 导出 tools Extension 的 Plugin | 每个 Tool 一个进程 |
| Tool | Interface Package 中可调用的 Operation | Plugin、Capability 或 Manager |
| Capability | 一组能力身份/调用范围，可包含多个 Operation | 单个进程或 Tool 实例 |
| Operation | Capability 下的具体可调用操作 | 独立 Plugin |
| ToolCatalog | 可发现 Tool/Capability 的只读视图 | 生命周期 Registry |
| Skill | 面向任务的指导与可选 Assurance 组合 | Plugin 或业务服务 |
| SKILL.md | Agent-facing 的自然语言指导和使用说明 | 第二份执行图 |
| Assurance | Skill 可选的确定性执行资产 | 所有 Skill 的必需层 |
| Contract | Assurance 内的输入、Context、依赖、Capability 和 when 声明 | 独立 Contract Package |
| when | Contract 中可选的纯 CEL Skill 选择表达式 | predicates 或执行期 Predicate |
| PredicateSet | CA-SL 执行期业务事实判断集合 | Skill 选择器 |
| Procedure | 唯一确定性执行图 | SKILL.md 中的自然语言流程 |
| SkillCatalog | Core/Host 拥有的进程内 Skill 快照和代际 | Plugin Manager Registry |
| Published Artifact | 外部 Compiler 发布、Agent 消费的运行时 Skill Artifact | 作者源或 Agent 本地编译产物 |
| Run | Host 关联和管理的一次执行实例 | HTTP/2 stream |
| Event | 外部 Push 输入的规范化事件 | Tool READ Observation |
| Observation | Tool READ 返回的带来源观察 | 模型生成文本 |
| Evidence | 支持执行结果判断的 Owner Receipt/Commit Proof 等证据 | IPC 成功或 HTTP 200 |
| Artifact | Host 管理的二进制/文件产物及其引用 | Plugin 私有数据库文件 |
| artifactRef | Host 颁发、由 Runtime 控制使用的 opaque 引用 | 文件系统路径 |
| Owner | 对业务状态和提交结果负最终责任的系统/契约拥有者 | Agent Host |
| Interface Package | Tool Callable、Schema、Effect、Capability 和 Owner 语义的权威发布包 | Plugin Manifest |

## 2. 标识命名规则

- Plugin 使用稳定 Plugin ID。
- Skill 身份由 Skill 包身份定义，不额外创建重复身份层。
- Callable ID、Capability ID 以其 Interface Package 为准。
- Run ID、Event ID、Invocation ID、Delivery ID、Response Obligation ID、IPC Message ID 和 Correlation ID 严格区分。
- Protocol operation 使用 3GPP 标准 Service Operation 名称；NAS/NGAP/PFCP 使用标准消息名，必要时补充类型值。
- CA-SL、Plugin API、IPC 等机器标识保留精确原文，不在 Next 内另造别名。

## 3. 文件与文档命名

普通文档文件名使用中文主题名。固定技术文件名、标准文件名和代码符号保留原文，例如 README.md、Agent.md、SKILL.md、plugin.yaml、contract.yaml、procedure.yaml、predicates.yaml。

## 4. 同义词约束

同一概念不得在不同文档中交替使用 Provider Manager / Tool Manager、Skill Registry / Catalog、Task Contract / Skill Contract 等不同术语。若外部仓历史名称不同，首次出现时注明外部原名及其当前映射，后文统一使用本规范术语。

## 5. Capability / Callable 术语

| 术语 | 规范含义 | 不得混淆为 |
|---|---|---|
| Capability | Skill-facing 业务能力 ID；由 Contract Grant 并在 Procedure 阶段引用 | Callable ID、backendOperationId、权限系统 |
| Callable | Owner / Provider Package 发布的稳定调用身份；由 Compiler 静态链接，Runtime 内部派发 | Skill 作者可选的 Tool 列表、Provider 私有 handler |
| Capability Binding | Compiler 从唯一 Capability export 解析出的 Capability→Callable 编译绑定 | Runtime 临时发现、模型选择、动态授权 |
| Operation Stage | Procedure Node 中执行 kind=operation Callable 或本地 Script 的阶段 | 独立 Operation ID |
| Observation Stage | Procedure Node 中执行 kind=observation、Effect=READ Callable 的阶段 | 任意读取工具、Mutation |
| backendOperationId | Provider 内部私有后端路由身份；可由一个 Callable 内部按封闭 Schema selector 选择 | 公开 Callable ID、Skill Capability |
| Reconcile Callable | 由 Runtime Coordinator 按原 Mutation 身份专用调用的内部 READ 目标 | 普通 Skill-facing Capability |

Capability 与 Callable 的 Skill-facing 映射必须一对一。一个 Capability 可被多个 Skill / Procedure 节点引用；这不改变 Package 中的一对一映射。一个 Callable 不得被多个 Skill-facing Capability 共享。

**1.6.0-only 设计评审硬门槛：** Capability 一对一仅适用于 1.6.0；历史只读留档，绝不兼容旧语法。 此章节仅描述目标设计，外部代码/Release/E2E 均 NOT_RUN。
