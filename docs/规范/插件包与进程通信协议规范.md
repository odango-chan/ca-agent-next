## 1. 唯一 Plugin 机制

Plugin 是由唯一 Python Plugin Manager 管理的独立包/进程单元。一个进程可以导出一种或多种 Extension：

| Extension | 方向 | 含义 |
|---|---|---|
| event.ingress | Plugin → Host | 发布规范化外部 Event |
| event.delivery | Host → Plugin | 向原协议响应方交付结构化响应 |
| tools | Host → Plugin | 导出可调用 Tool Operation |

Tool 是 Plugin 导出的 Operation，不是独立进程、Package、Manager 或 Runtime。Tool Plugin 是导出 tools Extension 的 Plugin。不存在独立 Provider Manager、Tool Registry、Event Registry、Delivery Manager 或 Codec Manager。

Plugin Manager 管理生命周期、握手、IPC framing、correlation 和 Extension 分发；不选择 Skill、不授权 Action、不判断 Owner 是否提交。

## 2. 包结构

~~~text
plugins/<plugin-id>/
  plugin.yaml
  bin/<plugin-executable>
  schemas/
  resources/
~~~

Manifest 使用 YAML。Tool 定义不复制进 Manifest；Callable ID、IO Schema、Effect、Capability 和 Owner outcome 由权威 Tool Interface Package 定义。

## 3. Manifest 规范

~~~yaml
apiVersion: connectionagent.io/plugin-package/v1alpha1
kind: Plugin
metadata:
  id: urn:connectionagent:plugin:openamsm
  version: 0.1.0
process:
  executable: bin/ca-openamsm-plugin
  args: [serve]
  protocol: connectionagent.io/plugin-ipc/v1alpha1
extensions:
  event.ingress:
    events: []
  event.delivery:
    responses: []
  tools:
    interfacePackage: <canonical-interface-package-reference>
~~~

字段规则：
- apiVersion 和 process.protocol 使用唯一固定版本，不设 alias/fallback。
- executable、Schema 和资源路径必须位于安装包根目录内。
- extensions 至少声明一种能力；一个进程可声明多种。
- Event Schema 描述规范化输入，不包含 Skill ID、Goal、执行模式或授权 Grant。
- Artifact slot 声明 slot、mediaType、required，必须与 3GPP/OpenAMSM 与 Host Artifact Handoff 一致。
- event.delivery 按 eventType 声明响应 Schema；Host 创建 responseObligation。
- tools.interfacePackage 只引用已发布 Tool Interface Package，不复制 Callable 定义。
- 未知字段、重复 YAML key、无效 Schema 引用、路径逃逸或不支持版本导致加载失败。

Manifest 不是业务 Contract、ToolCatalog、Skill Descriptor 或授权文件。

## 4. 加载与生命周期

启动时唯一 Plugin Manager：
1. 严格解析 plugin.yaml，拒绝重复 key。
2. 校验版本、身份、Extension 和包内路径。
3. 校验 Event Schema，解析 Tool Interface Package。
4. 启动进程并发送 host.initialize。
5. 接收 plugin.ready，核对 Plugin ID、版本、IPC 版本和 Extension。
6. 完全匹配后才注册 Extension。

状态为 CONFIGURED → STARTING → READY / NOT_READY → STOPPING → STOPPED。失败 Plugin 不得部分注册。Demo 通过显式部署配置和 Host 重启更新，不要求 Marketplace、在线安装、自动升级或热更新。

## 5. IPC v1alpha1

Native Plugin 使用 UTF-8 NDJSON over stdin/stdout。Host 写 stdin，Plugin 写 stdout；stdout 只承载协议帧，诊断写入 stderr。

每帧包含 apiVersion、messageId、可选 correlationId、type、payload。messageId、correlationId、eventId、externalRequestId、responseChannelId、runId、invocationId、deliveryId 和 responseObligationId 必须分开。

消息清单：

| 方向 | type | 用途 |
|---|---|---|
| Host → Plugin | host.initialize | 初始化 Plugin 与 staging |
| Plugin → Host | plugin.ready | 握手完成 |
| Plugin → Host | ingress.event | 发布规范化 Event |
| Host → Plugin | ingress.ack | 接收、重复关联、冲突或拒绝 |
| Host → Plugin | tools.invoke | Runtime 放行的 Tool 调用 |
| Plugin → Host | tools.result | Tool 结果或错误 |
| Host → Plugin | delivery.dispatch | 响应交付 |
| Plugin → Host | delivery.result | delivered / failed / unknown |
| Host → Plugin | host.cancel | 取消请求 |
| Plugin → Host | plugin.cancelled | cancelled / too_late / unsupported |
| Host → Plugin | host.shutdown | 优雅关闭 |
| Plugin → Host | plugin.stopped | 停止确认 |

所有回复按 correlationId 关联原请求。未知消息、错误版本、关联不匹配、非法 JSON 或 Payload 无效时 fail closed。

消息 Payload 的必要边界：
- ingress.event 由 Plugin 提供 eventId、ingressId、eventType、externalRequestId（若外部协议提供）、responseChannelId、source、normalized payload 和 Artifact staging 描述符；不得提供 Skill ID、Run ID 或 Capability Grant。
- ingress.ack 由 Host 返回 eventId、accepted / duplicate / rejected 状态和安全诊断；不得返回 Run ID、Skill identity 或 Host 内部 artifactRef。
- delivery.dispatch 由 Host 发起，按 responseObligationId / responseChannelId 指定响应义务，并仅给出本次出站 staging 文件描述符。
- delivery.result 只表达 delivered / failed / unknown 和安全诊断，不改变 Owner outcome。
- tools.invoke / tools.result 的公开 Callable、参数 Schema、Effect、Capability、Owner result 和 Artifact IO 由 [F03.05](../设计说明书/F03-Plugin平台/Tool%20Interface%20与%20Provider%20集成设计说明书.md) 定义；Plugin IPC 不复制这些契约。

## 6. Event 与 Skill-first 边界

Event Plugin 解析外部协议，发布 Event ID、ingress ID、Event type、externalRequestId、responseChannelId、source、payload 和 artifacts。Host 分配 Run ID 与 responseObligationId。

Plugin 不得提供 Skill ID、指定 Run 或选择执行模式。每个新业务 Event 由 F02 Resolver 选择 Skill。Continuation 恢复原 Run，不重新选择。重复 externalRequestId 只有在原请求身份和内容可证明相同的情况下才可关联原 Run；冲突必须拒绝。

## 7. Tools 与 Owner 结果边界

tools.invoke 使用 Tool Interface Package 中精确 Callable ID 和 Schema。Runtime 在调用前检查 Skill Scope、Run、Effect、参数和 Artifact refs。Plugin 传输成功不等于业务 COMMITTED；Owner Receipt/Commit Proof 由 Runtime 按 Owner 契约解释。

ca-client-tools Provider v2 通过单一 Plugin Manager 的 tools Extension Driver 适配，不新增第二个 Provider Manager。Codec 如果正式发布，也是普通 Tool Callable。

## 8. Artifact Handoff

原始二进制不进入 NDJSON，不使用 Base64。Event Plugin 把入站字节写入 Host 提供的 inbound staging directory，提交相对 stagingPath 描述符；Host 校验并导入 Host-owned ArtifactStore，发放 opaque artifactRef。Tool Plugin 只接收当前 Invocation 已授权的 artifactRef；Delivery 输出由 Host 写入 outbound staging。

不增加 Plugin 自有 Artifact 数据库、独立 Artifact Service 或额外 SHA-256。

Event / Delivery 与 Host 之间的本地 staging 是本协议的一部分；Host → Tool Plugin 的二进制传输是另一条独立 Channel。`ca-host.artifact-store/v1` 已在 ca-agent contract pin `2c0b07f2eaff3bc1020bfc6775ef9bf09e3052ae` 冻结；ca-client-tools Provider v1.2.0 已实现 consumer 与共享 fixtures，ca-agent Go Host main `447d0cce` 的 P1 外部验收为 43/43（read-only 11/11），real-NF multipart 仍 NOT_VERIFIED。以上不是 Next 实现证据：Next Python Host channel server 尚未实现，SR-010 通过共享 fixtures 前，artifact-bearing binding 必须 NOT_CONFIGURED 并在远端 I/O 前拒绝。不得把 Event stagingPath 传给 Provider，也不得通过 NDJSON/Base64 传递原始 bytes。

## 9. 错误与重试

错误对象包含 code、message、retryable 和可选 details。retryable 只是传输重试提示，不证明 mutation 未提交。Plugin 进程崩溃、Tool timeout、Delivery unknown、Cancel too_late 均不得伪造成功或自动重放 mutation。业务 mutation 重试必须遵循 Runtime/Owner 的 originalInvocationId 和 Receipt 语义。
