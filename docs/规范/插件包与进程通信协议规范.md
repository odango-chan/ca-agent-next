## 1. 唯一 Plugin 机制

Plugin 是由唯一 Python Plugin Manager 管理的独立包/进程单元。一个进程可以导出一种或多种 Extension：

| Extension | 方向 | 含义 |
|---|---|---|
| event.ingress | Plugin → Host | 发布规范化外部 Event |
| event.delivery | Host → Plugin | 向原协议响应方交付结构化响应 |
| tools | Host → Plugin | 导出可调用 Tool Operation |

Tool 是 Plugin 导出的 Operation，不是独立进程、Package、Manager 或 Runtime。Tool Plugin 是导出 tools Extension 的 Plugin。不存在独立 Provider Manager、Tool Registry、Event Registry、Delivery Manager 或 Codec Manager。

Plugin Manager 管理生命周期、握手、IPC framing、correlation 和 Extension 分发；不选择 Skill、不授权 Action、不判断 Owner 是否提交。

## 2. 包结构

~~~text
plugins/<plugin-id>/
  plugin.yaml
  bin/<plugin-executable>
  schemas/
  resources/
~~~

Manifest 使用 YAML。Tool 定义不复制进 Manifest；Callable ID、IO Schema、Effect、Capability 和 Owner outcome 按 §7 所列发布方契约解释。

## 3. Manifest 规范

~~~yaml
apiVersion: connectionagent.io/plugin-package/v1alpha1
kind: Plugin
metadata:
  id: example.echo
  version: 1.0.0
process:
  executable: bin/echo-plugin
  args: [serve]
  protocol: connectionagent.io/plugin-ipc/v1alpha1
extensions:
  event.ingress:
    events:
      - type: echo.request
        requestSchema: schemas/echo-request.json
  event.delivery:
    responses:
      - eventType: echo.request
        responseSchema: schemas/echo-response.json
  tools:
    interfacePackage: urn:example:echo:interface
~~~

这是用于 SR-003 的合成 Echo 包；两个 JSON Schema 均声明闭合 object、必需字符串 `text`。测试 Interface Package 导出 `echo.read`，参数和结果都使用该对象。部署按精确 Package ID 解析已安装快照。`event.ingress` 在每个 Native 包中最多一个；本设计以该包 `metadata.id` 标识这一输入，Host 同时核对进程实例及 Event type。二进制场景用 `events[].artifacts.input[]` 和 `responses[].artifacts.output[]` 声明 `{slot, mediaType, required}`，描述符沿用 F05。字段规则：
- apiVersion 和 process.protocol 使用唯一固定版本，不设 alias/fallback。
- executable、Schema 和资源路径必须位于安装包根目录内。
- extensions 至少声明一种能力；一个进程可声明多种。
- Event Schema 描述规范化输入，不包含 Skill ID、Goal、执行模式或授权 Grant。
- Artifact slot 声明 slot、mediaType、required，必须与 3GPP/OpenAMSM 与 Host Artifact Handoff 一致。
- event.delivery 按 eventType 声明响应 Schema；Host 创建 responseObligation。
- tools.interfacePackage 只引用已发布 Tool Interface Package，不复制 Callable 定义。
- 未知字段、重复 YAML key、无效 Schema 引用、路径逃逸或不支持版本导致加载失败。

Manifest 不是业务 Contract、ToolCatalog、Skill Descriptor 或授权文件。

## 4. 加载与生命周期

启动时唯一 Plugin Manager：
1. 严格解析 plugin.yaml，拒绝重复 key。
2. 校验版本、身份、Extension 和包内路径。
3. 校验 Event Schema，解析 Tool Interface Package。
4. 启动进程并发送 host.initialize。
5. 接收 plugin.ready，核对 Plugin ID、版本、IPC 版本和 Extension。
6. 完全匹配后才注册 Extension。

状态为 CONFIGURED → STARTING → READY / NOT_READY → STOPPING → STOPPED。失败 Plugin 不得部分注册。Demo 通过显式部署配置和 Host 重启更新，不要求 Marketplace、在线安装、自动升级或热更新。

## 5. IPC v1alpha1

Native Plugin 使用 UTF-8 NDJSON over stdin/stdout。Host 写 stdin，Plugin 写 stdout；stdout 只承载协议帧，诊断写入 stderr。

每帧包含 apiVersion、messageId、可选 correlationId、type、payload。messageId、correlationId、eventId、externalRequestId、responseChannelId、runId、invocationId、deliveryId 和 responseObligationId 必须分开。

消息清单：

| 方向 | type | 用途 |
|---|---|---|
| Host → Plugin | host.initialize | 初始化 Plugin 与 staging |
| Plugin → Host | plugin.ready | 握手完成 |
| Plugin → Host | ingress.event | 发布规范化 Event |
| Host → Plugin | ingress.ack | 接收、重复关联、冲突或拒绝 |
| Host → Plugin | tools.invoke | Runtime 放行的 Tool 调用 |
| Plugin → Host | tools.result | Tool 结果或错误 |
| Host → Plugin | delivery.dispatch | 响应交付 |
| Plugin → Host | delivery.result | delivered / failed / unknown |
| Host → Plugin | host.cancel | 取消请求 |
| Plugin → Host | plugin.cancelled | cancelled / too_late / unsupported |
| Host → Plugin | host.shutdown | 优雅关闭 |
| Plugin → Host | plugin.stopped | 停止确认 |

所有回复按 correlationId 关联原请求。未知消息、错误版本、关联不匹配、非法 JSON 或 Payload 无效时 fail closed。

消息 Payload 的必要边界：
- ingress.event 由 Plugin 提供 eventId、ingressId、eventType、externalRequestId（若外部协议提供）、responseChannelId、source、normalized payload 和 Artifact staging 描述符；不得提供 Skill ID、Run ID 或 Capability Grant。
- `ingress.ack` 的 **payload 严格 allowlist** 为 `eventId`、`disposition`（accepted、duplicate_attached、conflict 或 rejected）以及仅在 conflict/rejected 时的安全 `error`（不得自由透传 `details`）；禁止 `runId`、`skillId`、`artifactRef`、`responseObligationId`、`deliveryId`、`responseChannelId` 及其任何嵌套形态。**帧顶层** `correlationId` 只用于 IPC 回复匹配原 `ingress.event.messageId`，不是业务 Event 的 `correlationId`。
- `delivery.dispatch` 由 Host 发起。其 payload 必须包含 `deliveryId`、Host 创建的 `responseObligationId`、Plugin-local `responseChannelId`、`eventType`、`statusCode`、`headers`、`body` 和本次出站 staging 文件描述符。`responseObligationId` 是 Host-owned opaque token，Plugin 只在处理当前 dispatch 的调用期间瞬时接收，不生成、不解释为 Run/执行身份、不持久化、不跨请求缓存、不转发，也不在 `delivery.result` 中回传；Plugin 只使用 `responseChannelId` 选择当前 HTTP/2 stream waiter。
- `delivery.result` 由 Plugin 返回，必须包含 `deliveryId` 与 `disposition`（`delivered` / `failed` / `unknown`），可包含 `statusCode` 和安全诊断；不得回传 `responseObligationId`、`responseChannelId` 或 `runId`，且不改变 Owner outcome。
- tools.invoke / tools.result 的公开 Callable、参数 Schema、Effect、Capability、Owner result 和 Artifact IO 由 [F03.05](../设计说明书/F03-Plugin平台/Tool%20Interface%20与%20Provider%20集成设计说明书.md) 定义；Plugin IPC 不复制这些契约。

### 5.1 两个进程可独立实现的消息字段

下例是 SR-003 的一条可重放测试记录。每一行是一帧。在这条串行示例中，奇数帧为请求，偶数帧回复前一请求。Host 发送 m1、m4、m5、m7、m9、m11；Plugin 发送 m2、m3、m6、m8、m10、m12，其中 m3 为主动发起的 ingress.event。正文中的业务名称只属于 Echo fixture。单进程实例内 messageId 唯一。并发时以 correlationId 查找未完成请求，再核对类型及 operation 身份，不依赖行序；关闭或进程退出后清理该实例所有挂起请求。

~~~jsonl
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m1","type":"host.initialize","payload":{"pluginId":"example.echo","expectedVersion":"1.0.0","ipcVersion":"connectionagent.io/plugin-ipc/v1alpha1","config":{}}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m2","correlationId":"m1","type":"plugin.ready","payload":{"pluginId":"example.echo","pluginVersion":"1.0.0","ipcVersion":"connectionagent.io/plugin-ipc/v1alpha1","extensions":["event.ingress","event.delivery","tools"]}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m3","type":"ingress.event","payload":{"eventId":"evt1","ingressId":"example.echo","eventType":"echo.request","externalRequestId":"client-1","responseChannelId":"ch1","source":{"protocol":"echo","peerId":"test-peer"},"payload":{"text":"hello"},"artifacts":[]}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m4","correlationId":"m3","type":"ingress.ack","payload":{"eventId":"evt1","disposition":"accepted"}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m5","type":"tools.invoke","payload":{"invocationId":"inv1","callableId":"echo.read","arguments":{"text":"hello"},"invocationContext":{},"artifactRefs":[]}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m6","correlationId":"m5","type":"tools.result","payload":{"invocationId":"inv1","result":{"text":"hello"}}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m7","type":"delivery.dispatch","payload":{"deliveryId":"del1","responseObligationId":"obl1","responseChannelId":"ch1","eventType":"echo.request","statusCode":200,"headers":{},"body":{"text":"hello"},"artifacts":[]}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m8","correlationId":"m7","type":"delivery.result","payload":{"deliveryId":"del1","disposition":"delivered","statusCode":200}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m9","type":"host.cancel","payload":{"targetOperationId":"inv1","reason":"caller_cancelled"}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m10","correlationId":"m9","type":"plugin.cancelled","payload":{"targetOperationId":"inv1","disposition":"too_late"}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m11","type":"host.shutdown","payload":{"gracePeriodMs":1000}}
{"apiVersion":"connectionagent.io/plugin-ipc/v1alpha1","messageId":"m12","correlationId":"m11","type":"plugin.stopped","payload":{"inFlightCount":0}}
~~~

字段约束以示例中的拼写为准。ID 为非空字符串，extensions 是无重复的字符串数组，与 Manifest 的 extension 键集合相等。config 为对象，带二进制 slot 时 initialize.payload 另含 F05 的 artifactStaging。source 含 protocol 和部署可识别的 peerId；externalRequestId 在协议提供稳定身份时填写。独立 Event 不携带 correlationId，外部业务 Continuation 的原 Run 由 Host 查找。`ingress.ack` payload 只回 `eventId`、`disposition`，冲突或拒绝时可加严格筛选的安全 `error`；所有 disposition 均禁止回传 `runId`、`skillId`、`artifactRef`、`responseObligationId`、`deliveryId`、`responseChannelId`，亦不得通过 `error.details` 或嵌套字段夹带这些身份。帧顶层 `correlationId` 只匹配 IPC 请求的 messageId，不得混入 Event payload。相同逻辑请求、字节相同但响应通道不同，Host 将新通道绑定新响应义务，复用原执行。

tools.invoke 的 arguments 按公开 Schema 校验，invocationContext 只允许 binding 声明的字段，artifactRefs 只允许该调用已授权的引用；可选 deadlineMs 为整数毫秒。tools.result 必须有匹配的 invocationId，result 与 error 二选一。Host 使用 `responseObligationId` 标识本次响应义务；Plugin 仅使用 `responseChannelId` 精确选择当前 HTTP/2 stream waiter，两者必须同时与当前 `deliveryId` 绑定。`statusCode` 为 HTTP 整数状态，headers 为对象、body 按该 Event 的 responseSchema 验证；无 body 的响应使用 null。`delivery.result` 只回传 `deliveryId`、`disposition`、可选 `statusCode` 和安全诊断，不得回传 `responseObligationId`、`responseChannelId` 或 `runId`；未收到可确认结果时 disposition 为 `unknown`。Host 不向 Event/Delivery Plugin 发送 `runId`。

host.cancel 的 targetMessageId、targetOperationId 二选一，reason 为字符串；plugin.cancelled 的 correlationId 关联 cancel 帧，回显所用目标字段，disposition 为 cancelled、too_late、unsupported 之一。取消回复与原操作终态分开处理。shutdown 的 gracePeriodMs、stopped 的 inFlightCount 为非负整数。超时后终止该进程并注销全部 Extension；已派发且可能产生副作用的操作交给 Runtime 保留不确定状态。

负例从上述记录单点变异：ready 删除 tools、result 改成无挂起请求的 correlationId、ack 注入 runId / responseObligationId / deliveryId / artifactRef（含嵌套 error.details）、Delivery 回错 deliveryId、迟到的终态回复再次到达。分别断言握手失败且零注册、请求未被错误完成、无 Host 身份外泄、原义务未标记 delivered、原操作不重复完成。stderr 承担诊断输出。

字段来源为 [PR #1 固定中文规范](https://github.com/odango-chan/ca-agent-next/blob/9f88814f624f957e1f2fafe95e4f18e5970e3c5e/docs/规范/插件包与进程通信协议规范.md)。有关 ack、Delivery 与 staging 的字段按本分支 F05 §7～9 收窄。

## 6. Event 与 Skill-first 边界

Event Plugin 解析外部协议，发布 Event ID、ingress ID、Event type、externalRequestId、responseChannelId、source、payload 和 artifacts。Host 分配 Run ID 与 responseObligationId。

Plugin 不得提供 Skill ID、指定 Run 或选择执行模式。每个新业务 Event 由 F02 Resolver 选择 Skill。Continuation 恢复原 Run，不重新选择。重复 externalRequestId 只有在原请求身份和内容可证明相同的情况下才可关联原 Run；冲突必须拒绝。

## 7. Tools 与 Owner 结果边界

调用 Provider 公开 READ 时从 Provider Interface Package 解析；调用 MAS Owner Operation 时从 Owner Contract Package 解析精确 Callable ID 和 Schema。Runtime 在调用前检查 Skill Scope、Run、Effect、参数和 Artifact refs。Plugin 传输成功不等于业务 COMMITTED；Owner Receipt/Commit Proof 由 Runtime 按 Owner 契约解释。

ca-client-tools Provider v2 通过单一 Plugin Manager 的 tools Extension Driver 适配，不新增第二个 Provider Manager。Codec 如果正式发布，也是普通 Tool Callable。

## 8. Artifact Handoff

原始二进制不进入 NDJSON，不使用 Base64。Event Plugin 把入站字节写入 Host 提供的 inbound staging directory，提交相对 stagingPath 描述符；Host 校验并导入 Host-owned ArtifactStore，发放 opaque artifactRef。Tool Plugin 只接收当前 Invocation 已授权的 artifactRef；Delivery 输出由 Host 写入 outbound staging。

不增加 Plugin 自有 Artifact 数据库、独立 Artifact Service 或额外 SHA-256。

Event / Delivery 与 Host 之间的本地 staging 是本协议的一部分；Host → Tool Plugin 的二进制传输是另一条独立 Channel。`ca-host.artifact-store/v1` 已在 ca-agent contract pin `2c0b07f2eaff3bc1020bfc6775ef9bf09e3052ae` 冻结；ca-client-tools Provider v1.2.0 已实现 consumer 与共享 fixtures，ca-agent Go Host main `447d0cce` 的 P1 外部验收为 43/43（read-only 11/11），real-NF multipart 仍 NOT_VERIFIED。以上不是 Next 实现证据：Next Python Host channel server 尚未实现，SR-010 通过共享 fixtures 前，artifact-bearing binding 必须 NOT_CONFIGURED 并在远端 I/O 前拒绝。不得把 Event stagingPath 传给 Provider，也不得通过 NDJSON/Base64 传递原始 bytes。

## 9. 错误与重试

错误对象包含 code、message、retryable 和可选 details。retryable 只是传输重试提示，不证明 mutation 未提交。Plugin 进程崩溃、Tool timeout、Delivery unknown、Cancel too_late 均不得伪造成功或自动重放 mutation。业务 mutation 重试必须遵循 Runtime/Owner 的 originalInvocationId 和 Receipt 语义。
