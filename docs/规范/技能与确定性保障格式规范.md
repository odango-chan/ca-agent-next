# 技能与确定性保障格式规范

> 文档类型：Skill 包结构与运行时消费规范  
> 状态：v1alpha5 作者格式保持冻结；v1alpha6 Capability-first 为 Next 候选设计，尚未发布  
> 文档版本：0.1.5    
> 全局评审范围：继承根目录 Agent.md 的 review_scope    
> 本文局部非目标：以本文范围与非目标章节为准；无额外扩展  
> 修订日期：2026-11-26  
> 适用范围：ca-agent-next 的 Skill 导入、选择与执行模式派生

关联需求项见 [IR-003](../IR/IR%20总登记册.md#ir-003)。

## 1. 基本规则

1. 每个 Skill 必须有 SKILL.md。
2. assurance/ 是可选的确定性执行资产目录。
3. 没有 Assurance Artifact 的 Skill 只能 LLM-guided。
4. 存在有效发布 Assurance Artifact 的 Skill 同时支持 Deterministic 和 LLM-guided。
5. 包声明或携带 Assurance、但发布 Artifact 缺失、格式不支持、必需文件不全或依赖无法解析时，整个 Skill 导入失败，不得静默降级。
6. Skill 选择先于执行模式选择。
7. CA-SL v1alpha5 是唯一作者语言基线；不做旧版本兼容或自动迁移。

## 2. 作者源结构

~~~text
skills/<skill-id>/
├── SKILL.md
└── assurance/                 # 可选
    ├── contract.yaml
    ├── procedure.yaml
    └── predicates.yaml
~~~

SKILL.md 面向 Agent，描述 Skill 的目的、使用指导和语义适用性。其 Front Matter 字段与内容格式遵循当前 Skill 作者规范；Next 不新增第二份 Skill Descriptor。

assurance/ 只在需要确定性执行时存在。contract.yaml、procedure.yaml、predicates.yaml 属于 CA-SL 作者源；无 Predicate 时仍保留空 predicates.yaml。CA-SL 语法、Schema、Procedure 图和 CEL 规则由 ca-skills / ca-skill-compiler 维护，Next 不重写。

## 3. Contract 与 when

Contract 位于 assurance/contract.yaml，是可选 Assurance 的一部分，不是所有 Skill 的必需文件，也不是独立 Contract Package。

when 是 Contract 中唯一的正式 Skill 选择表达式：

~~~yaml
when: 'event.type == "nsmf.create-sm-context" && input.requestType == 1'
~~~

规则：

- when 是纯 CEL 布尔表达式，只用于 Skill 选择。
- event.type 是规范化 Event 类型。
- input 类型来自 Contract.requestSchema。
- when 读取 input 字段时必须声明 requestSchema，由外部 Compiler 在发布前做静态类型检查。
- when 不得调用 Tool、读取 Observation、访问可变 Host 状态或产生副作用。
- predicates.yaml 只用于执行期业务事实判断，不参与 Skill 选择。
- SKILL.md 不增加第二个 CEL 字段。
- 不增加 activation.yaml、constraint.yaml、applicability.yaml、supportedModes、第二份 LLM Contract、Domain Contract Package 或 TaskContract Package。

## 4. 运行时发布包

Agent 只消费外部发布的运行包：

~~~text
published-skills/<skill-id>/
├── SKILL.md
└── <Compiler-generated runtime Artifact files>
~~~

Artifact 文件清单、Manifest、Procedure 投影、CheckedExpr 和类型数据以 Compiler 正式发布契约为准。作者源 assurance/ 不等于运行时 Artifact。

Agent 不调用 Compiler Check/Build/Inspect/Verify，不重新执行 CA-SL 静态检查、链接或 Artifact 自校验，也不设置独立 Skill Admission。Agent 只做消费端基本检查：必需文件、格式标识、相对路径、引用完整性、CEL/type data 可加载和 Tool/Capability 依赖解析。

## 5. 执行模式派生

| 发布包状态 | 模式 |
|---|---|
| 只有 SKILL.md | LLM-guided only |
| SKILL.md + 有效发布 Assurance Artifact | Deterministic 或 LLM-guided |
| Artifact 不完整、格式错误或依赖不完整 | 导入失败 |

不使用 supportedModes 字段，不允许根据模型判断、Event 类型或 Plugin 类型推断 Deterministic 能力。

## 6. when 的加载与求值

- 外部 Compiler 在发布前完成 when 解析、G.4 静态检查和 CheckedExpr 生成。
- Agent 在 Skill 导入时加载发布 Artifact 中的已检查程序和类型数据。
- Agent 使用固定版本的 Python CEL Runtime 反序列化一次，并将 Program 与类型环境保存在 SkillCatalog generation 中。
- 每个新 Event 使用当前 event.type/input 独立求值。
- 不缓存不同 Event 的 true/false/error 结果。
- Event 热路径不读取 Skill 文件、不扫描目录、不解析 CEL 源字符串、不调用 Compiler。
- continuation 复用原 Run 和其 Catalog generation，不重新求值 when。

当发布程序无法反序列化、类型数据缺失或输入结构不符合声明时，必须显式失败并 fail-closed，不得退化为 DynType 或自制 CEL Interpreter。

## 7. LLM 作者流程

LLM 可以创建或编辑 SKILL.md-only 包，并通过普通导入流程更新 Catalog。

LLM 若创建或编辑 Assurance 作者源，该源在经过外部 Compiler/发布流程生成新的运行时 Artifact 之前不可执行。Agent 不把未发布源码临时编译，也不为单个 LLM Action 创建 Procedure 或调用 Compiler。

## 8. 规范权威与变更

- SKILL.md 的作者格式由当前 Skill 包规范维护。
- CA-SL v1alpha5 语言语义和 Assurance 源字段由 ca-skills 正式规范维护。
- Artifact Manifest、编译输出、CheckedExpr 和依赖闭包由 ca-skill-compiler 正式契约维护。
- Agent 的导入、Catalog、选择和模式派生由本仓架构与设计说明书维护。

本规范只定义 Next 消费边界，不复制 CA-SL 的完整语法或 Compiler Artifact 的字段级 Schema。

## 9. 发布语义与候选变更

[CA-SL 语言基线与版本规范](CA-SL语言基线与版本规范.md)登记冻结版本。`Contract.when` 已随 CA-SL v1alpha5 发布。规范提交为 `18d8184367982ccbc835756136c4a53f9096c3a0`。带 when 的运行包仍需 SR-013 的正式 Compiler 发布资产。作者工具构建源码，Next Host 消费已发布产物，作者规范按 SR-023，Compiler 产品按 SR-013，外部 Bundle 组装与发布按 SR-027 移交。

## 11. Capability-first 作者源目标（v1alpha6 候选）

### 11.1 Contract 只声明 Capability

~~~yaml
dependencies:
  mas: urn:openamsm:mas:tool-contracts
capabilities:
  - mas.sc.context.create
  - mas.se.establishment-event.record
~~~

Capability ID 是包发布的业务能力身份。dependencies 仍负责固定依赖包；作者源不写 Callable ID，也不通过 alias::Callable 选择 Provider / Owner 内部入口。

### 11.2 Procedure 只引用 Capability

~~~yaml
record-session-establishment-event:
  operation:
    capability: mas.se.establishment-event.record
    arguments:
      ue_identity: context.supi
      psi: context.request.pduSessionId
      event: "ESTABLISHED"
      sessionKeys: create-sm-context.operation.output.session_keys

emit-release-event:
  operation:
    capability: mas.se.release-event-marker.write
    arguments:
      ue_identity: context.supi
      psi: context.request.pduSessionId
      ev: "RELEASED"

read-sm-context:
  observation:
    capability: openamsm.smf.mas.context.read
    arguments:
      contextKind: sc
      supi: context.supi
      pduSessionId: context.request.pduSessionId
~~~

- operation.capability 只能链接 kind=operation；observation.capability 只能链接 kind=observation。
- Contract.capabilities 必须包含 Procedure 使用的全部 Capability ID；未声明的引用、无法解析的引用和未使用的 Grant 均报错。
- 每个 Capability 必须唯一映射一个公开 Callable；同一个公开 Callable 不得被多个 Skill-facing Capability 重复归属。
- Callable ID、backendOperationId、Owner handler、Provider 路由、服务地址和凭据不得出现在 Skill 作者源或模型可选择的 Action 参数中。
- 该语法只适用于 languageTarget=connectionagent.io/v1alpha6。v1alpha5 的 tool 字段保持原义；不得将 tool 当作 capability 别名，也不得自动改写旧作者源。

### 11.3 版本与发布

v1alpha6 是候选设计而非当前发布版本。作者规范、Compiler Link、Runtime Artifact、ca-skills Bundle 和 Studio LSP 必须按同一版本切换；任何一个环节未发布或未验收时，停止发布，不回退到 v1alpha5 或 Development Artifact。
