# 技能与确定性保障格式规范

> 文档类型：Skill 包结构与运行时消费规范  
> 状态：**设计待评审**（唯一新目标 CA-SL 1.6.0；全链路不兼容任何旧作者语法、Build DTO、Artifact、Bundle；1.6.0 产品未发布）
> 文档版本：0.1.19    
> 全局评审范围：继承根目录 Agent.md 的 review_scope    
> 本文局部非目标：以本文范围与非目标章节为准；无额外扩展  
> 修订日期：2026-11-27  
> 适用范围：ca-agent-next 的 Skill 导入、选择与执行模式派生

关联需求项见 [IR-003](../IR/IR%20总登记册.md#ir-003) / [IR-008](../IR/IR%20总登记册.md#ir-008)。

作者写作、Skill / Capability / Node 粒度、共享 Schema / Script 资源、Host Resource Read / Script Execution 和注释原则以 [SKILL 作者规范](SKILL作者规范.md) 为准；CA-SL 1.6.0 §6～§8 是 Node / routes / arguments / PredicateSet / Script I/O / Evidence 的语法权威。本文定义包结构与导入消费边界，不另造语言语法。CA-SL 1.6.0 仍为中央设计待评审稿。

## 1. 基本规则

1. 每个 Skill 必须有 SKILL.md。
2. assurance/ 是可选的确定性执行资产目录。
3. 没有 Assurance Artifact 的 Skill 只能 LLM-guided。
4. 存在有效发布 Assurance Artifact 的 Skill 同时支持 Deterministic 和 LLM-guided。
5. 包声明或携带 Assurance、但发布 Artifact 缺失、格式不支持、必需文件不全或依赖无法解析时，整个 Skill 导入失败，不得静默降级。
6. Skill 选择先于执行模式选择。
7. 新 Assurance 作者语言唯一目标为 **CA-SL 1.6.0**（尚未发布）；历史 v1alpha5 保留原始冻结语义和发布身份，不做旧版本兼容或自动迁移。

## 2. 作者源结构

~~~text
skills/<skill-id>/
├── SKILL.md
├── schemas/                    # 可选，共享 Schema；YAML 1.2 JSON Schema 数据模型
├── scripts/                    # 可选，共享 Script 源码
│   ├── manifest.yaml           # 存在可执行 Script 时必需
│   └── *.py
├── references/                 # 可选
├── assets/                     # 可选
└── assurance/                  # 可选
    ├── contract.yaml
    ├── procedure.yaml
    └── predicates.yaml
~~~

SKILL.md 面向 Agent，描述 Skill 的目的、使用指导和语义适用性。其 Front Matter 以 [Agent Skills Specification](https://agentskills.io/specification) 为格式权威，**不属于 CA-SL 1.6.0 Assurance 语言语法**；Next 不新增第二份 Skill Descriptor。

assurance/ 只在需要确定性执行时存在，且只包含 contract.yaml、procedure.yaml、predicates.yaml；无 Predicate 时仍保留空 predicates.yaml。schemas/、scripts/、references/ 和 assets/ 是 Package 根目录共享资源，无论是否存在 Assurance 都可使用。Schema 文件使用 YAML 1.2 表示 JSON Schema 数据模型，路径相对 Package 根目录。Script Registry `scripts/manifest.yaml` 声明 Script ID、精确入口、purpose、输入/输出 Schema；它是资源索引，不是第二份 Skill Descriptor 或业务 Capability Grant。LLM 可调用 Registry 中登记的全部 transform / predicate Script；purpose 只约束 Assurance 静态引用位置，不构成 LLM 权限过滤。Script 输入、Predicate Evidence 投影、输出和异常契约遵循 CA-SL 1.6.0 §8。

### 2.1 SKILL.md Front Matter

Front Matter 必须是 YAML mapping，位于文件开头的 `---` 分隔符之间，之后是 Markdown 正文。按 [Agent Skills Specification](https://agentskills.io/specification)：

| 字段 | 要求 |
|---|---|
| `name` | 必需；1～64 字符；仅小写 ASCII 字母、数字和连字符；不得以连字符开头/结尾或包含连续连字符；必须与 Skill 包根目录名一致 |
| `description` | 必需；1～1024 字符非空字符串；描述 Skill 能做什么以及何时使用 |
| `license` | 可选字符串 |
| `compatibility` | 可选字符串；1～500 字符 |
| `metadata` | 可选 string→string mapping |
| `allowed-tools` | 可选空格分隔字符串；Agent Skills 规范标记为实验性 |

CA-Agent 不扩展 SKILL.md Front Matter 的 `when` 字段；Front Matter 出现 `when` 按未知字段拒绝。`when` 是 `assurance/contract.yaml` 的可选顶层 CEL 布尔字段，只用于选择期过滤，不授予 Capability / Callable 权限。无 Assurance Skill 没有 Contract，因此不声明 `when`。Next 的严格消费策略：拒绝其他未知顶层字段、重复/冲突的必需字段、错误 YAML 类型和无效目录名；保留已支持可选字段，但 `allowed-tools` **只作元数据**，不授予 Tool/Callable/Capability 权限。执行权限仍由有效 Assurance Artifact 与 Owner/Provider 契约决定。

SKILL.md 正文是 Markdown 指导内容，不由 CA-SL Parser 解析。导入时保留原文；Skill 被激活时加载正文。LLM 通过 F05 §2.1 定义的只读 `host.skill-resource.read` 按需读取当前 Run 固定 Package snapshot 中的 UTF-8 文本资源；读取 Script 源码与执行是两个动作。LLM 可通过 Host-owned `host.skill-script.execute` 调用当前 Skill Registry 中登记的全部 transform / predicate Script，与 Assurance 共用同一 Script Runner。没有逐脚本可调用标记或额外 Host 开关。模型不能提交代码、路径、模块名、函数名、Evidence 或命令。

## 3. Contract 与 when

Contract 位于 assurance/contract.yaml，是可选 Assurance 的一部分，不是所有 Skill 的必需文件，也不是独立 Contract Package。它声明可选顶层 `when`、requestSchema、contexts、dependencies、capabilities、precondition 和 limits。

`when` 是 `assurance/contract.yaml` 的可选顶层字段，仅当 Skill 存在 Assurance 时可选声明；无 Assurance Skill 没有 Contract，不声明 when。它是唯一的正式 CEL Skill 选择表达式：

~~~yaml
# assurance/contract.yaml
when: 'event.type == "nsmf.create-sm-context" && has(input.requestType) && input.requestType == "INITIAL_REQUEST"'
requestSchema: schemas/create-sm-context-request.schema.yaml
~~~

规则：

- when 是纯 CEL 布尔表达式，只用于 Skill 选择。
- event.type 是规范化 Event 类型。
- input 类型来自 Contract.requestSchema。
- when 读取 input 字段时必须声明 requestSchema，由外部 Compiler 在发布前做静态类型检查；可选 / nullable 字段必须先通过 `has(input.field)` 或相应的显式非空守卫，并依赖 CEL 左到右短路事实后再读取。
- when 不得调用 Tool、读取 Observation、访问可变 Host 状态或产生副作用。
- predicates.yaml 只用于执行期业务事实判断，不参与 Skill 选择。
- `when` 不属于 Agent Skills Specification 的标准 Front Matter 字段；它是 `assurance/contract.yaml` 的可选顶层 Contract 字段，仅有 Assurance 的 Skill 可以声明；无 Assurance Package 没有 Contract/when。
- 不增加 activation.yaml、constraint.yaml、applicability.yaml、supportedModes、第二份 LLM Contract、Domain Contract Package 或 TaskContract Package。

## 4. 运行时发布包

Agent 只消费外部发布的运行包：

~~~text
published-skills/<skill-id>/
├── SKILL.md
├── schemas/                    # 若有，原始共享 Schema 资源
├── scripts/                    # 若有，原始 Script 源码与 manifest.yaml
├── references/                 # 若有
├── assets/                     # 若有
└── <Compiler-generated runtime Artifact files>  # 仅 Assurance Skill 存在
~~~

共享资源文件随 Bundle 保留原始字节，LLM 资源读取与 Host Script Execution 使用同一 Package snapshot。存在 Assurance 时，Artifact 文件清单、Manifest、Procedure 投影、CheckedExpr、Script 引用闭包和类型数据以 Compiler 正式发布契约为准；无 Assurance 时不生成 Compiler Artifact，但仍可发布共享资源。作者源 assurance/ 不等于运行时 Artifact。

Agent 不调用 Compiler Check/Build/Inspect/Verify，不重新执行 CA-SL 静态检查、链接或 Artifact 自校验，也不设置独立 Skill Admission。Agent 只做消费端基本检查：必需文件、格式标识、相对路径、引用完整性、CEL/type data 可加载和 Tool/Capability 依赖解析。

### 4.1 Runtime Artifact API 支持边界

必须区分 CA-SL `languageTarget` 与 Compiler `apiVersion`；二者不是同一个版本号。

| 输入 | 当前契约状态 | Next 消费规则 |
|---|---|---|
| 无 Assurance Package（含 SKILL.md，可选共享资源） | Agent Skills Specification；无 `assurance/contract.yaml`，无 `when`；Front Matter `when` 按未知字段拒绝 | 导入并检查共享资源；不调用 Compiler，只能 LLM-guided 语义选择 |
| 冻结 Compiler Artifact `connectionagent.io/compiler-artifact/v1alpha5` | Compiler v2.1.0 冻结；不包含新版 Request Schema 根/闭包和 when CheckedExpr/DescriptorSet | 不作为当前通用 Assurance Runtime Bundle；SR-004 拒绝该 API，不猜测缺失语义 |
| Development Artifact `connectionagent.io/compiler-development-artifact/v1alpha1` | `executionStatus=NOT_ADMITTED` | 必须拒绝，不得运行 |
| CA-SL 1.6.0 正式 Runtime Artifact（未发布） | ca-skills 1.6.0 + SR-029 Capability Binding + Compiler #61 / SR-013 联合交付；准确 languageTarget 待冻结 | 唯一新增 Assurance 输入目标；仅按正式发布的 Manifest/Binding 契约消费 |
| 未知 Artifact API / 历史非 1.6.0 运行包 | 当前新运行时不支持 | 必须拒绝；不得自动降级或做兼容映射 |

Compiler v2.1.0 的冻结 Artifact v1alpha5 不携带 F08 要求的 Request Schema 发布快照/闭包，也不包含 when CheckedExpr/DescriptorSet。由于发布 Bundle 不携带 Assurance 作者源，Agent 无法从旧 Manifest 证明作者源未声明 requestSchema；因此旧 Artifact 不能作为本规范定义的通用 Assurance Runtime 输入。**CA-SL 1.6.0** Runtime Artifact 的精确 `languageTarget`、apiVersion、Capability→Callable Binding、字段和路径由 ca-skills / SR-029 / Compiler #61 / SR-013 联合正式 Release 冻结，Next 不得采用尚未批准的候选值。

### 4.2 Bundle 与导入边界

- Published Skill Bundle 的组装、Skill 与 Runtime Artifact 的关联及 Release 资产由 ca-skills / SR-027 拥有；Agent 不自造第二种 Bundle Manifest。
- Importer 接收调用方已物化的 Skill 包根目录，不负责网络下载或压缩包解包。
- Importer 只返回已验证的 import candidate；SkillCatalog generation、原子激活、失败保留旧代际和 Invocation pinning 由 SR-005 负责。
- 存在 Assurance 作者源但没有受支持的已发布 Runtime Artifact 时必须失败；不允许降级为无 Assurance Package。
- Agent 只做消费端基本结构、必需文件、相对路径、共享资源和 Script Registry 引用完整性、类型数据可加载和本地依赖检查；不重跑 Compiler Verify，不新增签名或额外包完整性机制。无 Assurance 的 Package 由 Host Importer 检查 scripts/manifest.yaml、脚本入口文件和其引用的 schemas/*.schema.yaml；这不是 Compiler Check / Build。

## 5. 执行模式派生

| 发布包状态 | 模式 |
|---|---|
| SKILL.md（可附共享资源，无 Assurance） | LLM-guided only；可通过 Host Resource Read 读取共享文本资源；当前 Skill Registry 有登记脚本时，可调用全部登记 Script |
| SKILL.md + 有效发布 Assurance Artifact（可附共享资源） | Deterministic 或 LLM-guided；两种模式共用同一份 Schema / Script 资源 |
| Assurance Artifact 不完整、格式错误或依赖不完整 | 导入失败，不得降级 |
| Script Registry / Schema / 入口引用无效 | 对应 Package 导入失败；不得暴露 Host Script Execution Capability |

不使用 supportedModes 字段，不允许根据模型判断、Event 类型或 Plugin 类型推断 Deterministic 能力。

## 6. when 的加载与求值

- 外部 Compiler 在发布前完成 when 解析、G.4 静态检查和 CheckedExpr 生成。
- Agent 在 Skill 导入时加载发布 Artifact 中的已检查程序和类型数据。
- Agent 使用固定版本的 Python CEL Runtime 反序列化一次，并将 Program 与类型环境保存在 SkillCatalog generation 中。
- 每个新 Event 使用当前 event.type/input 独立求值。
- 不缓存不同 Event 的 true/false/error 结果。
- Event 热路径不读取 Skill 文件、不扫描目录、不解析 CEL 源字符串、不调用 Compiler。
- continuation 复用原 Run 和其 Catalog generation，不重新求值 when。

当发布程序无法反序列化、类型数据缺失或输入结构不符合声明时，必须显式失败并 fail-closed，不得退化为 DynType 或自制 CEL Interpreter。

## 7. LLM 作者流程

LLM 可以创建或编辑没有 Assurance 的 Skill Package；Package 可包含 schemas/、scripts/、references/ 和 assets/。LLM 通过 `host.skill-resource.read` 按 F05 §2.1 读取当前 Package snapshot 的共享文本资源；可通过 `host.skill-script.execute` 以 scriptId + JSON input 调用当前 Skill Registry 登记的全部 transform / predicate Script。LLM 与 Assurance 共用同一 Script Runner；不设置逐脚本标记或额外 Host 开关。Predicate Script 的直接调用只返回普通计算结果，不产生 Evidence 或 Assurance Outcome。该能力不接受模型代码、路径、模块、函数、Evidence 或命令。

LLM 若创建或编辑 Assurance 作者源，该源在经过外部 Compiler/发布流程生成新的运行时 Artifact 之前不可执行。Agent 不把未发布源码临时编译，也不为单个 LLM Action 创建 Procedure 或调用 Compiler。

## 8. 规范权威与变更

- SKILL.md Front Matter 的字段由 [Agent Skills Specification](https://agentskills.io/specification) 维护；CA-Agent 不增加 `when` 扩展。
- CA-SL 1.6.0 定义 assurance/ 作者语言；`when` 位于 `assurance/contract.yaml` 顶层，不属于 SKILL.md Front Matter。
- 新 Assurance 作者语义目标为 **CA-SL 1.6.0**，由 ca-skills 规范发布与 Issue #40 / SR-029 共同固定；历史 v1alpha5 的字段只供旧源追溯。
- Artifact Manifest、编译输出、CheckedExpr 和依赖闭包由 ca-skill-compiler 正式契约维护；SR-004 只消费正式发布 API，不接受冻结 v1alpha5 或 Development v1alpha1 作为当前 Assurance Runtime Bundle。
- Published Skill Bundle 的组装、关联与发布由 ca-skills / SR-027 维护；Bundle 规范尚未正式发布时，Next 不自造布局或成功样本。
- Agent 的导入、Catalog、选择和模式派生由本仓架构与设计说明书维护。

本规范只定义 Next 消费边界，不复制 CA-SL 的完整语法或 Compiler Artifact 的字段级 Schema。CA-SL 1.6.0 不定义 Skill 层 Wait / await / polling / `wait.output`；异步完成由 Tool / Provider / SMF Operation 与 Host Runtime 负责。**下一语言目标直接 CA-SL 1.6.0，不引入 v1alpha6**；其新作者源只写 Capability ID，公开 Capability 与 Callable 一对一，Runtime 消费已编译的唯一 Binding。历史 v1alpha5 的 `tool: alias::CALLABLE_ID` 语义保持冻结，只供追溯、不作新 Runtime 输入。

## 9. 发布语义与候选变更

[Agent Skills Specification](https://agentskills.io/specification) 定义标准 SKILL.md Front Matter（本次核对日期 2026-11-26）；CA-Agent 不扩展 Front Matter `when`。CA-SL 1.6.0 的 `when` 是 `assurance/contract.yaml` 的可选顶层字段，Compiler 从 Contract 读取并编译；无 Assurance Skill 不声明 when。历史 CA-SL v1alpha5 的入口只用于历史审计，不作为 1.6.0 的双入口兼容依据。但 Compiler v2.1.0 尚未发布对应的新 Runtime Artifact API，Compiler #61 / SR-013 仍未完成；ca-skills / SR-027 也尚无匹配的正式 Skill Bundle。语言规范发布不代表 Runtime Artifact 或 Bundle 已发布。作者工具构建源码，Compiler 负责 Runtime Artifact，ca-skills 负责 Bundle 组装与发布，Next Host 只消费正式 Bundle。
