# 技能与确定性保障格式规范

> 文档类型：Skill 包结构与运行时消费规范  
> 状态：待评审；明确 CA-SL v1alpha5 作者格式与 Compiler Runtime Artifact API 的消费边界；CA-SL 语言细节以 ca-skills 正式规范为准  
> 文档版本：0.1.5    
> 全局评审范围：继承根目录 Agent.md 的 review_scope    
> 本文局部非目标：以本文范围与非目标章节为准；无额外扩展  
> 修订日期：2026-11-26  
> 适用范围：ca-agent-next 的 Skill 导入、选择与执行模式派生

关联需求项见 [IR-003](../IR/IR%20总登记册.md#ir-003)。

## 1. 基本规则

1. 每个 Skill 必须有 SKILL.md。
2. assurance/ 是可选的确定性执行资产目录。
3. 没有 Assurance Artifact 的 Skill 只能 LLM-guided。
4. 存在有效发布 Assurance Artifact 的 Skill 同时支持 Deterministic 和 LLM-guided。
5. 包声明或携带 Assurance、但发布 Artifact 缺失、格式不支持、必需文件不全或依赖无法解析时，整个 Skill 导入失败，不得静默降级。
6. Skill 选择先于执行模式选择。
7. CA-SL v1alpha5 是唯一作者语言基线；不做旧版本兼容或自动迁移。

## 2. 作者源结构

~~~text
skills/<skill-id>/
├── SKILL.md
└── assurance/                 # 可选
    ├── contract.yaml
    ├── procedure.yaml
    └── predicates.yaml
~~~

SKILL.md 面向 Agent，描述 Skill 的目的、使用指导和语义适用性。其 Front Matter 字段与内容格式遵循当前 Skill 作者规范；Next 不新增第二份 Skill Descriptor。

assurance/ 只在需要确定性执行时存在。contract.yaml、procedure.yaml、predicates.yaml 属于 CA-SL 作者源；无 Predicate 时仍保留空 predicates.yaml。CA-SL 语法、Schema、Procedure 图和 CEL 规则由 ca-skills / ca-skill-compiler 维护，Next 不重写。

## 3. Contract 与 when

Contract 位于 assurance/contract.yaml，是可选 Assurance 的一部分，不是所有 Skill 的必需文件，也不是独立 Contract Package。

when 是 Contract 中唯一的正式 Skill 选择表达式：

~~~yaml
when: 'event.type == "nsmf.create-sm-context" && input.requestType == 1'
~~~

规则：

- when 是纯 CEL 布尔表达式，只用于 Skill 选择。
- event.type 是规范化 Event 类型。
- input 类型来自 Contract.requestSchema。
- when 读取 input 字段时必须声明 requestSchema，由外部 Compiler 在发布前做静态类型检查。
- when 不得调用 Tool、读取 Observation、访问可变 Host 状态或产生副作用。
- predicates.yaml 只用于执行期业务事实判断，不参与 Skill 选择。
- SKILL.md 不增加第二个 CEL 字段。
- 不增加 activation.yaml、constraint.yaml、applicability.yaml、supportedModes、第二份 LLM Contract、Domain Contract Package 或 TaskContract Package。

## 4. 运行时发布包

Agent 只消费外部发布的运行包：

~~~text
published-skills/<skill-id>/
├── SKILL.md
└── <Compiler-generated runtime Artifact files>
~~~

Artifact 文件清单、Manifest、Procedure 投影、CheckedExpr 和类型数据以 Compiler 正式发布契约为准。作者源 assurance/ 不等于运行时 Artifact。

Agent 不调用 Compiler Check/Build/Inspect/Verify，不重新执行 CA-SL 静态检查、链接或 Artifact 自校验，也不设置独立 Skill Admission。Agent 只做消费端基本检查：必需文件、格式标识、相对路径、引用完整性、CEL/type data 可加载和 Tool/Capability 依赖解析。

### 4.1 Runtime Artifact API 支持边界

必须区分 CA-SL `languageTarget` 与 Compiler `apiVersion`；二者不是同一个版本号。

| 输入 | 当前契约状态 | Next 消费规则 |
|---|---|---|
| SKILL.md-only | CA-SL v1alpha5 正式支持 | 导入，不调用 Compiler，只能 LLM-guided |
| 冻结 Compiler Artifact `connectionagent.io/compiler-artifact/v1alpha5` | Compiler v2.1.0 冻结；不包含新版 Request Schema 根/闭包和 when CheckedExpr/DescriptorSet | 不作为当前通用 Assurance Runtime Bundle；SR-004 拒绝该 API，不猜测缺失语义 |
| Development Artifact `connectionagent.io/compiler-development-artifact/v1alpha1` | `executionStatus=NOT_ADMITTED` | 必须拒绝，不得运行 |
| 新版正式 Runtime Artifact API | Compiler #61 / SR-013 交付；`languageTarget=connectionagent.io/v1alpha5` | 目标支持；仅按正式 Release 的 API、Manifest Schema 和文件布局消费 |
| 未知 Artifact API / 未来 v1alpha6 | 未受当前 v1alpha5 导入契约支持 | 必须拒绝；不得自动降级或做兼容映射 |

Compiler v2.1.0 的冻结 Artifact v1alpha5 不携带 F08 要求的 Request Schema 发布快照/闭包，也不包含 when CheckedExpr/DescriptorSet。由于发布 Bundle 不携带 Assurance 作者源，Agent 无法从旧 Manifest 证明作者源未声明 requestSchema；因此旧 Artifact 不能作为本规范定义的通用 Assurance Runtime 输入。新版 Runtime Artifact API 的精确 apiVersion、字段和路径由 Compiler #61 正式 Release 冻结，Next 不得采用尚未批准的候选值。

### 4.2 Bundle 与导入边界

- Published Skill Bundle 的组装、Skill 与 Runtime Artifact 的关联及 Release 资产由 ca-skills / SR-027 拥有；Agent 不自造第二种 Bundle Manifest。
- Importer 接收调用方已物化的 Skill 包根目录，不负责网络下载或压缩包解包。
- Importer 只返回已验证的 import candidate；SkillCatalog generation、原子激活、失败保留旧代际和 Invocation pinning 由 SR-005 负责。
- 存在 Assurance 作者源但没有受支持的已发布 Runtime Artifact 时必须失败；不允许降级为 SKILL.md-only。
- Agent 只做消费端基本结构、必需文件、相对路径、引用、类型数据可加载和本地依赖检查；不重跑 Compiler Verify，不新增签名或额外包完整性机制。

## 5. 执行模式派生

| 发布包状态 | 模式 |
|---|---|
| 只有 SKILL.md | LLM-guided only |
| SKILL.md + 有效发布 Assurance Artifact | Deterministic 或 LLM-guided |
| Artifact 不完整、格式错误或依赖不完整 | 导入失败 |

不使用 supportedModes 字段，不允许根据模型判断、Event 类型或 Plugin 类型推断 Deterministic 能力。

## 6. when 的加载与求值

- 外部 Compiler 在发布前完成 when 解析、G.4 静态检查和 CheckedExpr 生成。
- Agent 在 Skill 导入时加载发布 Artifact 中的已检查程序和类型数据。
- Agent 使用固定版本的 Python CEL Runtime 反序列化一次，并将 Program 与类型环境保存在 SkillCatalog generation 中。
- 每个新 Event 使用当前 event.type/input 独立求值。
- 不缓存不同 Event 的 true/false/error 结果。
- Event 热路径不读取 Skill 文件、不扫描目录、不解析 CEL 源字符串、不调用 Compiler。
- continuation 复用原 Run 和其 Catalog generation，不重新求值 when。

当发布程序无法反序列化、类型数据缺失或输入结构不符合声明时，必须显式失败并 fail-closed，不得退化为 DynType 或自制 CEL Interpreter。

## 7. LLM 作者流程

LLM 可以创建或编辑 SKILL.md-only 包，并通过普通导入流程更新 Catalog。

LLM 若创建或编辑 Assurance 作者源，该源在经过外部 Compiler/发布流程生成新的运行时 Artifact 之前不可执行。Agent 不把未发布源码临时编译，也不为单个 LLM Action 创建 Procedure 或调用 Compiler。

## 8. 规范权威与变更

- SKILL.md 的作者格式由当前 Skill 包规范维护。
- CA-SL v1alpha5 语言语义和 Assurance 源字段由 ca-skills 正式规范维护。
- Artifact Manifest、编译输出、CheckedExpr 和依赖闭包由 ca-skill-compiler 正式契约维护；SR-004 只消费正式发布 API，不接受冻结 v1alpha5 或 Development v1alpha1 作为当前 Assurance Runtime Bundle。
- Published Skill Bundle 的组装、关联与发布由 ca-skills / SR-027 维护；Bundle 规范尚未正式发布时，Next 不自造布局或成功样本。
- Agent 的导入、Catalog、选择和模式派生由本仓架构与设计说明书维护。

本规范只定义 Next 消费边界，不复制 CA-SL 的完整语法或 Compiler Artifact 的字段级 Schema。CA-SL v1alpha5 的 `tool: alias::CALLABLE_ID` 语义保持冻结；Next Issue #40 / 计划 SR-029 的 Capability-first 是未来 v1alpha6 候选，不得回写或兼容映射到 v1alpha5。

## 9. 发布语义与候选变更

[CA-SL 语言基线与版本规范](CA-SL语言基线与版本规范.md)登记冻结版本。`Contract.when` 已随 CA-SL v1alpha5 发布，规范提交为 `18d8184367982ccbc835756136c4a53f9096c3a0`。但 Compiler v2.1.0 尚未发布对应的新 Runtime Artifact API，Compiler #61 / SR-013 仍未完成；ca-skills / SR-027 也尚无匹配的正式 Skill Bundle。语言规范发布不代表 Runtime Artifact 或 Bundle 已发布。作者工具构建源码，Compiler 负责 Runtime Artifact，ca-skills 负责 Bundle 组装与发布，Next Host 只消费正式 Bundle。
