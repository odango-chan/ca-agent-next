## 1. 仓库根目录

~~~text
ca-agent-next/
├── README.md
├── Agent.md
├── docs/
│   ├── 架构设计/
│   ├── 设计说明书/
│   ├── 规范/
│   ├── SR/                       # 独立编号的需求记录
│   ├── 决策记录/
│   ├── 治理/
│   ├── 验收与实施/
│   └── 参考与审计/
├── src/                       # Python Agent / Host / Runtime 实现
├── examples/                  # 可运行的垂直示例
└── tests/                     # 自动化测试
~~~

目录按实际内容创建，不创建空目录。README.md 提供导航；Agent.md 提供协作约束。所有正式文档进入 docs 下对应目录。

## 2. 文档目录规则

- docs/架构设计/ 只允许一份当前总体架构设计。
- docs/设计说明书/ 与 docs/架构设计/ 同级，承载详细机制设计。
- docs/规范/ 放置文件格式、公共契约、协议、术语、文档治理和 SR 管理规则。
- docs/SR/ 放置按 SR-NNN 编号的独立需求记录，不把需求正文散落在 Issue 中。
- docs/治理/ 维护文档总目录、SR 总索引、实施状态总览和收敛计划，不放机制设计正文。
- docs/验收与实施/ 维护验收标准、阶段计划、跨仓实施任务和执行结果；SR 不放在本目录。
- docs/参考与审计/ 保留外部依赖与既有代码审计，不得覆盖当前规范。
- 不重新引入 docs/architecture.md、docs/plugin-package.md 等英文散落结构，也不建立 docs/集成设计/、docs/实施计划/ 等与新目录重复的分区。

## 3. Skill 作者源目录

作者源由 ca-skills 或 Skill 作者管理。标准结构：

~~~text
skills/<skill-id>/
├── SKILL.md
└── assurance/                 # 可选
    ├── contract.yaml
    ├── procedure.yaml
    └── predicates.yaml
~~~

SKILL.md 必须存在。assurance/ 缺省表示没有确定性 Assurance。assurance/ 存在时必须有完整 CA-SL 源文件集合；无 Predicate 时 predicates.yaml 使用空 PredicateSet。Schema、脚本和 references 是否可用由 Skill 作者源规范声明，Next 不另造第二种目录语义。

## 4. Skill 运行时发布包目录

Agent 消费已发布的运行时包，而不是作者源：

~~~text
published-skills/<skill-id>/
├── SKILL.md
└── <Compiler-generated runtime Artifact files>
~~~

Artifact 内部文件和 Manifest 由 ca-skill-compiler 的正式发布契约定义。Next 只检查必需文件、格式、路径、类型数据和本地依赖，不调用 Compiler 命令，不自行重建 Artifact。

## 5. Plugin 包目录

~~~text
plugins/<plugin-id>/
├── plugin.yaml
├── bin/
│   └── <plugin-executable>
├── schemas/
└── resources/
~~~

plugin.yaml 是 YAML Manifest。可执行文件、Schema 和资源的引用必须相对包根目录。Plugin 可以声明 event.ingress、event.delivery、tools 中一种或多种 Extension。Tool 定义本身不复制到 Manifest，而由 Tool Interface Package 管理。

## 6. Example 目录

第一个垂直示例为 Echo，建议结构：

~~~text
examples/echo/
├── plugin/
│   ├── plugin.yaml
│   └── schemas/
├── published-skills/
│   ├── echo-assured/
│   │   ├── SKILL.md
│   │   └── <published Artifact files>
│   └── echo-guide/
│       └── SKILL.md
├── interface/                 # Compiler/Tool 所有者发布的 Interface Package fixture
└── scenarios/
    ├── deterministic/
    ├── llm-guided/
    ├── import-published-artifact/
    └── selection/
~~~

测试位于 tests/ 下并通过公开 Plugin/Skill/Runtime 边界运行。不得为了满足目录图创建空文件夹；只有真实存在的场景才建目录。

## 7. 文件命名规则

普通文档文件名使用中文主题名。固定技术文件名和协议强制文件名保留原文，例如 README.md、Agent.md、SKILL.md、plugin.yaml、contract.yaml、procedure.yaml、predicates.yaml、OpenAPI 文件和源代码文件。

SR 作为独立需求文档存放在 docs/SR/，使用 SR-NNN-中文主题.md 文件名；每项 SR 必须关联设计版本、依赖和 Acceptance。

目录名按本规范固定，不在各团队中自行增加同义目录。
