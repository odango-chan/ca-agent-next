## 1. 仓库职责与发布对象

| 组件 | 权威职责 | 不负责 |
|---|---|---|
| ca-skills | CA-SL 作者规范、SKILL.md、Package 根目录共享 schemas/、scripts/、references/、assets/、可选 Assurance 作者源、Script Registry、Skill Bundle 组装与发布 | 不维护 Compiler 内部实现 |
| ca-skill-compiler | Check、Schema/CEL 静态检查、Build、Verify、新版 Runtime Artifact Schema 与 Compiler Release | 不负责 Skill 业务内容、Agent 导入和运行时选择 |
| ca-agent-next | 项目群设计权威；F02/SR-004/005/006 消费发布 Bundle | 不内置、不调用 Compiler，不实现 Skill Admission |
| ca-agent-demo | 既有参考实现和测试证据 | 不改变 Next/Compiler 的契约所有权 |

必须区分三个产物：

1. **Compiler Runtime Artifact**：Compiler 生成的确定性运行时文件，包含 Procedure、所有已声明 Contract.requestSchema 的 dialect-aware 闭包描述、Assurance Procedure / Predicate 引用的 Script Registry entrypoint 与 I/O Schema 闭包，以及有 when Skill 的 CheckedExpr/DescriptorSet。本地 G.4 根及其本地 G.4 `$ref` 闭包可规范化后写入 Artifact；纯 `$ref` OAS3 根别名则只在 Manifest 中记录精确 Source Bundle dependency pin、根文件/JSON Pointer 和完整可达 OAS3 引用，不把外部 Schema 转换、投影或复制为 G.4 Artifact 文件。原版 OAS3 YAML bytes 由锁定的 Source Bundle 在 Published Skill Bundle 中保留一次，运行时离线读取该快照。Artifact 对共享资源只建立精确文件/Schema 引用，不要求复制第二份资源；LLM 可调用的完整 Script Registry 与所有登记 Script 源码由 Bundle 保留，不因其未被 Assurance 引用而裁剪。
2. **Published Skill Bundle**：ca-skills 发布流程始终组装 SKILL.md 与 Package 根目录共享资源；存在 Assurance 时再关联 Compiler Runtime Artifact。无 Assurance Bundle 不调用 Compiler，也不生成 Deterministic Artifact。
3. **Agent SkillCatalog**：Next 导入成功后在内存中形成的运行时快照，包含共享资源的只读 Package snapshot 与可选 Runtime Artifact，不是 Compiler 产物。

## 2. when 编译与发布路径

作者源位置固定为 skills/<skill-name>/assurance/contract.yaml 的可选顶层 `when`，且仅适用于存在 `assurance/` 的 Skill。SKILL.md Front Matter 不声明 when，出现时按未知字段拒绝；没有 Assurance 的 Skill 没有 Contract，不声明 when，也不调用 Compiler。predicates.yaml 只承载执行期 Predicate。

~~~text
ca-skills Author Source
  ├── SKILL.md                 # Agent Skills metadata and guidance only
  ├── schemas/                  # shared YAML Schema resources
  ├── scripts/
  │   ├── manifest.yaml         # exact Script IDs / entrypoints / Schema refs
  │   └── *.py
  ├── references/
  ├── assets/
  └── assurance/                # optional
      ├── contract.yaml         # optional when / Request Schema / contexts / dependencies / Capability grants
      ├── procedure.yaml
      └── predicates.yaml
            |
            v
ca-skill-compiler (single Go Core; only when assurance/ exists)
  ├── Parse / ContractAST / Procedure / PredicateSet
  ├── Parse Script Registry and validate exact entrypoints
  ├── Dialect-aware Schema Registry / Request + Script I/O Schema closure
  ├── CEL static check / guard analysis with dialect-aware Schema type environment
  ├── Local G.4 normalized closure OR exact pinned OAS3 Source Bundle references (if requestSchema is declared)
  ├── CheckedExpr + FileDescriptorSet (if when is declared)
  ├── Build versioned Runtime Artifact with exact resource references
  └── Verify / deterministic comparison
            |
            v
ca-skills Bundle Assembly
  ├── SKILL.md
  ├── shared schemas/ scripts/manifest.yaml scripts/ references/ assets/
  └── Compiler Runtime Artifact (only when assurance/ exists)
            |
            v
ca-agent-next Skill Importer
  ├── validates published Bundle shape and local references
  ├── constructs Program and type environment once from CheckedExpr/DescriptorSet
  └── returns validated candidate with Program, type environment and Schema closure
            |
            v
ca-agent-next SkillCatalog (SR-005)
  └── builds an immutable generation and atomically activates it after all candidates validate
~~~

Compiler 对 when 的静态检查、nullable lowering、Any type URL、DescriptorSet 和 Artifact 结构详见 [EC02 Compiler 设计说明书 §3–7](../EC02-Compiler/Compiler设计说明书.md)。Next 消费行为详见 [F02 §2–11](../F02-Skill管理与选择/Skill管理与选择设计说明书.md)；本设计不复制消费端逻辑。

## 3. Compiler Runtime Artifact 契约

- 已发布 Artifact v1alpha5 保持冻结字节和语义不变。
- Development Artifact v1alpha1 保持冻结并 NOT_ADMITTED，不得用于 Agent Bundle。
- 新版 Runtime Artifact 使用独立版本化 API，BuildResult 也使用独立版本化结果契约；建议候选分别为 connectionagent.io/compiler-artifact/2 与 connectionagent.io/compiler-build-result/2；**新 BuildRequest/BuildResult 只能面向 CA-SL 1.6.0**；旧 v1alpha5 DTO 不允许作为新构建入口，Compiler Owner 须提供唯一明确的版本化构建契约；**新语言目标改为 CA-SL 1.6.0**；机器版 `languageTarget` 由 ca-skills / Compiler 正式冻结，不在 Next 预先写死。新版 Artifact 必须含 SR-029 定义的 Capability→Callable Binding；既有 Compiler #61 v1alpha5 when 设计不自动构成 1.6.0 发行证据。新 Compiler 版本采用**仅支持 1.6.0 的固定 API 集**，不得在同一二进制中双轨解析/构建旧作者语法、旧 Build DTO 或旧/新 Artifact。
- EC02 当前建议候选为 connectionagent.io/compiler-artifact/2，必须由 Compiler Owner 在 AC-013-03 明确批准后才成为实现契约。
- 每个声明 Contract.requestSchema 的 Skill，无论是否声明 when，都必须在 Artifact 中携带可离线解析的 Request Schema 闭包描述，供 Host 按 M.3 验证 Event payload。若入口解析为本地 G.4 根，Compiler 将本地 G.4 根及完整本地 `$ref` 闭包规范化后写入 Artifact；若入口是仅含一个 `$ref` 的 OAS3 根别名，Compiler 不生成 G.4 Schema 副本，而是在 Manifest 中记录显式 pin 的 Source Bundle dependency identity、原始文件路径、根 JSON Pointer、完整可达 OAS3 资源及其 dialect。Source Bundle 的原版 YAML bytes 在 Published Skill Bundle 中保留一次，Artifact 只引用该快照，不改写、不投影、不远程读取。Skill 自有 Schema 源文件仍位于根目录 `schemas/*.schema.yaml`，以 YAML 1.2 表示 JSON Schema 数据模型。
- Contract.contexts 显式引用的 Schema-only Interface Package 必须进入 Schema dependency closure；其 0 Capability / 0 Callable exports 不生成 Capability Binding、Callable allowlist 或 Tool Effect。零 Capability roots 可以与非空 Schema dependency closure 同时成立。
- 有 when 的 Skill 携带标准 CheckedExpr Any 与 CEL DescriptorSet；DescriptorSet 始终包含 event.type，仅当表达式引用 input 时才包含该 Skill Request Schema 类型闭包。DescriptorSet 不替代完整 JSON Schema 断言。
- **1.6.0 Manifest 由 Compiler Owner 重新冻结唯一 Schema**，明确 Skill identity、source/compiled files、按 dialect 分型的 Request Schema 根与完整 resources[]、Script Registry 中被 Procedure / Predicate 引用的精确 entrypoint、Script I/O Schema、when CheckedExpr/DescriptorSet、唯一 Capability→Callable Binding（含 kind/Effect/Schema/依赖身份）及输出文件清单。Request Schema 元数据至少区分本地 G.4 与外部 OAS3：本地 G.4 资源记录规范化 Artifact path；外部 OAS3 资源记录 Source Bundle dependency identity、原始文件路径、JSON Pointer 和 OAS3 dialect，根/资源身份不得靠虚构 `$id` 补齐。外部 Source Bundle 必须属于精确 pin 的 dependencyClosure，原版 bytes 在 Bundle 中只保留一次；OAS3 源文件不列为 Compiler 生成的 compiledFiles/outputFiles。精确 wire 字段由 Compiler Owner 冻结。Manifest 必须引用 Package 根目录共享资源，不得假定 schemas/ 或 scripts/ 位于 assurance/；不得复制第二份脚本或 Schema。允许 Owner 复用合理的字段名称，但**不以兼容旧 Manifest 为目标**；旧版 Manifest、BuildRequest、BuildResult 均不得被新 Compiler/Agent 接受。不新增摘要、签名或 Trust Registry 体系。
- 建议版本化 Schema 路径为 contracts/2/artifact-manifest.schema.json 与 contracts/2/build-result.schema.json；具体字段由 Compiler Owner 在 Compiler 仓冻结后，Next 才按其消费。
- 新 Artifact 只使用新版本契约定义的文件清单；Build / Verify 仅检查路径、文件存在性、Schema、依赖闭包和语义结果，不计算或比较 SHA-256 / checksum / digest。Demo 不做签名、Trust Registry 或生产准入；**不得保留旧格式消费分支**。

### 3.1 新版单版本可评审输入/输出边界

- **Check 输入：**由 ca-skills 发布的唯一 1.6.0 作者 Schema、SKILL.md、根目录共享 schemas/ 与 scripts/manifest.yaml / Script 源码，以及可选 Assurance；源 Contract/Procedure 对外仅业务 Capability，Package-local Script 只引用 Registry Script ID；无旧版 Alias::Callable 或旧 Parser。
- **Link 输入：**明确的依赖 Package 闭包、Publisher/Owner identity、Capability exports、唯一公开 Callable membership、kind/Effect/Input/Output Schema、Schema-only Package 的显式 Schema exports、Skill Package 完整 Script Registry / 所有登记 Script entrypoint / Script I/O Schema 和 Reconcile 私有绑定信息；Schema-only Package 可有 0 Capability / 0 Callable，不产生任何 Skill-facing Binding；Compiler 不能从 provider backend catalog 推断授权。Script 的 purpose 只校验 Assurance 静态引用位置，不构成 LLM 可调用性过滤。
- **Build 输入：**单一 1.6.0 BuildRequest / DependencyInspection；旧 v1alpha5 BuildRequest 和 Development v1alpha1 请求均不得进入新 Compiler。所有外部字段由 ca-skills、Compiler、Owner/Provider 在各自发布 PR 冻结；文中示例路径均为设计候选，不是已发布 Schema。
- **Build 输出：**单一 1.6.0 BuildResult/Artifact，Manifest 包含已检查 `capabilityBindings`、Procedure、完整 Script Registry 及全部登记 Script 的精确 entrypoint / 输入输出契约、Assurance 引用的 Script I/O Schema closure、when CheckedExpr/DescriptorSet（若存在）、Request Schema 的 dialect-aware 根与完整闭包描述（若声明；本地 G.4 文件进入 Artifact，外部 OAS3 资源仅以精确 Source Bundle 引用进入 dependencyClosure）、contexts 引用的 Schema-only dependency closure、精确 Callable allowlist 和可用文件列表。所有登记 Script 均保留在 Bundle 中供 LLM / Assurance 共用；不得仅保留被 Procedure / Predicate 引用的子集。Schema-only Package 不生成 Capability Binding / Callable allowlist；无 Assurance 的 Package 不产生 Deterministic Artifact，但 Bundle 仍保留全部共享资源和完整 Script Registry。
- **Verify：**独立校验新 Artifact 的文件清单、Schema 与绑定确定性；不调用旧 Compiler 做兼容/迁移。构建或验证失败不组装部分 Bundle；发布后 Agent 只导入对应正式产物。
- **模块验收：**1.6.0 正例含唯一映射、OpenAMSM 事件 Capability 拆分、Provider 闭合 selector，以及 0 Capability / 0 Callable 的 Schema-only Package；负例含多成员/重复 Callable、非法空 Schema-only Package、缺 Schema、未声明 Schema 依赖、损坏 CheckedExpr、旧版本/旧 DTO/旧 Bundle/未知 API，必须全部按拒绝路径记录。真实 Release 的 tag/SHA/API/schema 由对应 Owner 提供；未发布时设计可评审但产品验收 `NOT_RUN`。

## 4. ca-skills CI 编译与 Bundle 组装

一次发布流水线必须固定单一 Compiler 输入，不能在同一次运行中动态漂移：

1. 解析当前最新稳定 Compiler Release。
2. 立即固定并记录 Compiler tag、commit SHA、release asset 身份和下载结果；后续所有 Skill 使用同一版本。
3. 检查 Compiler 支持的 Artifact API 与 CA-SL languageTarget。**新发布目标必须是正式 CA-SL 1.6.0**（机器标识待 ca-skills/Compiler 冻结）；不支持的 API/语言版本直接停止，不回退到冻结旧格式或 Development。
4. 对没有 assurance/ 的 Skill：发布 SKILL.md 与所有共享资源（schemas/、scripts/manifest.yaml、scripts/、references/、assets/）；它没有 contract.yaml，不声明 `when`；SKILL.md Front Matter 不得声明 `when`，若出现则由 Host Importer 按未知字段拒绝；不调用 Compiler、不生成 Runtime Artifact；Script Registry 的基本格式和资源引用由 Host Importer 在导入时检查。
5. 对含 assurance/ 的新 Skill：按 **CA-SL 1.6.0**（Issue #40 / SR-029）的 Capability-first 作者契约提交完整源，执行适配 1.6.0 的 Compiler Check、依赖/唯一 Binding 校验、Build 和 Verify；未发布新版编译器前该步骤 BLOCKED。历史 v1alpha5 Build 只属于历史证据。
6. 只有所有目标 Skill 的构建和验证通过，才进入 Bundle 组装。任何 Skill 失败都阻断本次发布，不发布部分成功的 Bundle。
7. 按 ca-skills 自己拥有的 Bundle 契约组装 SKILL.md、共享资源原始文件，以及（仅 Assurance Skill）Compiler Runtime Artifact；Artifact 精确引用共享资源闭包，Bundle 不重复复制 schemas/scripts；不在 Next 或 Compiler 设计中另造第二种 Bundle 格式。
8. 发布后保留作者源提交、Compiler tag/SHA、Artifact API、languageTarget、Bundle/Release 资产、构建与验证日志。没有发布授权时只可完成预检或候选构建，不得创建 Release。

Compiler Release 的解析必须在流水线开始时固定；禁止某个 Skill 使用较新 Compiler、另一个 Skill 使用旧 Compiler，或 Verify 时重新解析浮动的 latest。

## 5. 发布失败与恢复规则

| 失败点 | 行为 |
|---|---|
| 无稳定 Compiler Release 或无法固定资产 | 停止发布，记录 BLOCKED 和解除条件 |
| Artifact API / languageTarget 不支持 | 停止，不自动转换格式、不回退到 Development |
| Assurance 作者源或 Script Registry 引用无效 | Compiler 诊断回传作者，整个受影响发布批次不产生部分 Bundle |
| 无 Assurance Package 的 Script Registry / Schema / 文件引用无效 | ca-skills 发布检查或 Next Importer 拒绝该 Package；不调用 Compiler，不暴露 Host Script Execution Capability |
| Build 成功但 Verify 失败 | 不组装、不发布 Bundle |
| Bundle 组装失败 | 不发布 Release，保留已生成的本地证据 |
| 发布授权缺失 | 保留候选产物和日志，不创建 Release |
| Agent 导入失败 | 由 F02/SR-004/005 处理；不得要求 Agent 调用 Compiler 修复 |

## 6.1 1.6.0 Bundle 输入锁定、目录与原子发布

ca-skills 维护唯一输入锁文件 release/bundle-inputs.yaml（apiVersion: connectionagent.io/skill-bundle-inputs/1）。它不是包管理器，只记录本批构建使用的精确发布输入：

- languageTarget: connectionagent.io/v1.6.0；Compiler version: 3.0.0、40 位 commit、Release asset 名称、BuildRequest / DependencyInspection / BuildResult / Artifact API。
- Echo Interface Package 的 Package ID / SemVer；Owner Interface Package 与 Host Context Schema-only Package 的 Package ID / SemVer，分别取自 SR-008、SR-025、SR-030 的中央设计。
- 所有字段必须是固定值；空值、范围、latest、版本漂移或不在中央 SR 中的 Package identity 一律停止。

首批五个 Skill 根及处理方式固定：

| Skill 根 | Assurance | 依赖与处理 |
|---|---|---|
| echo-guide | 否 | 只校验并打包 SKILL.md 与声明资源；不得调用 Compiler |
| echo-assured | 是 | Capability example.echo.message.read；依赖 Next / SR-008 导出的 urn:example:echo:interface@1.0.0，Callable echo.read 不进入 Skill 作者源 |
| establish-pdu-session-mas | 是 | 使用 SR-029 固定的 Owner Capability 集及 SR-030 Host Context Schema-only Package |
| modify-pdu-session-mas | 是 | 使用 Owner Capability mas.ssm.n1.modify.parse、mas.upn.up.qos.delta；它们不是 SR-026 的协议级 Codec Capability |
| release-pdu-session-mas | 是 | 使用 SR-029 固定的 Owner Capability 集及 SR-030 Host Context Schema-only Package |

五个作者根必须来自同一个 ca-skills commit。对四个 Assurance 根分别执行同一 Compiler 3.0.0 的 Check、DependencyInspection、Build、Verify；echo-guide 不进入 Compiler。完整命令行以 Compiler 3.0.0 Release 文档为唯一依据，ca-skills 不复制或重实现 Compiler 逻辑。

每个发布 Skill 根采用以下结构：

~~~text
published-skills/<skill-id>/
  SKILL.md
  resources/...
  runtime-artifact/                 # 仅 Assurance Skill
    manifest.json
    skills/<skill-id>/compiled/...
~~~

runtime-artifact/ 是单个 Skill 的完整 Compiler Artifact 根，必须原样保留其 Manifest 和全部相对路径；不得只复制部分 .pb 或 JSON 文件。不得将作者 assurance/、Compiler 可执行文件、开发日志或临时文件混入已发布 Skill 根。

最终发布资产为单一 skill-bundle-1.6.0.zip，根目录仅含 published-skills/ 和五个 Skill 根。外层 Bundle 不另造第二套 Runtime Manifest；每个 Assurance Skill 的 runtime-artifact/manifest.json 仍由 Compiler 拥有。bundle-build-report.json 作为 CI / Release 证据附件，不作为 Agent 导入输入。

ZIP 使用仓库既有确定性归档规则：路径排序、统一 / 分隔符、固定时间戳、拒绝 symlink 与非普通文件；同一源 SHA、Compiler 和依赖输入重复构建必须逐字节一致。不得新增签名、Trust Registry 或额外完整性机制。

发布必须整批原子：五个 Skill 根全部通过源检查、四个 Artifact 全部 Verify、依赖闭包唯一、输出目录无缺失/额外/碰撞后，才生成一个 ZIP 并进入授权发布步骤。任一失败则本批发布资产为零，不上传部分成功目录。发布授权是最终 Release 门槛，不是设计或本地 Build 的前置。

## 8. OpenAMSM 原版 OpenAPI 3.0 Source Bundle 与直接引用闭环（IR-009）

1. **SR-031 Source Bundle**：ca-skills 原样代发布 OpenAMSM 实际支持的 OAS 3.0 YAML 和明确选定消费根的完整可达 `$ref` 闭包；保留原始 bytes、路径、相对引用和标准版本取证。当前 `PostSmContexts.requestBody` → `jsonData` → `SmContextCreateData` 闭包为四份原版 YAML / 102 个 Schema Component，不复制全部 472 份。Source Lock 固定 source commit、Git blob ID、byte length 和选定 surface；Publisher 直接 byte-compare，不新增 per-file digest / package hash。Source Bundle 不是 Interface Package，不导出 Capability / Callable。
2. **SR-010 Ingress**：Plugin 通过原生 OAS 3.0 consumer 解析选定 operation / requestBody / multipart / JSON / binary parts / Content-ID；仅 lazy resolve 选定 surface 的 refs。对 `PostSmContexts`，`n1SmMsg.contentId`、`n2SmInfo.contentId`、`n2SmInfoExt1.contentId` 分别精确关联 N1 / N2 / N2 Ext1 part；不完整解码 NAS / NGAP。
3. **SR-013 Compiler**：Skill-owned `requestSchema` 入口文件可以是本地 G.4 Schema 根（根对象闭合并声明 `additionalProperties: false`），也可以是仅含一个 `$ref` 的引用别名，直接指向显式 pin Source Bundle 中精确的 OAS 3.0 `components/schemas`；别名不得附加 G.4 兄弟关键字，外部目标按 OAS3 dialect 原生验证。Compiler 使用 dialect-aware Resolver / Validator，保留实际闭包中的组合、nullable、pattern、additionalProperties 等语义，不创建 Adapter、不改写或投影原版 YAML；OAS3 未声明 `additionalProperties` 时保留其默认允许额外属性的语义。外部引用 alias / path / pointer / Lock DTO 必须等正式 1.6.0 Schema / Golden 冻结。对 `PostSmContexts`，`input` 根对象是 `jsonData` 的 `SmContextCreateData`；其 `requestType` 引用 `RequestType` 字符串 Schema，枚举包含 `INITIAL_REQUEST` 等值，且该属性不是 required，因此 CEL 正例必须使用 `has(input.requestType) && input.requestType == "INITIAL_REQUEST"`；未守卫读取按 CEL_INVALID 拒绝，整数 `1` 按类型错误拒绝。固定来源为 OpenAMSM commit `dc83ccbf5be54dcc7112dd43ba95ea6fa5975550`、TS29502_Nsmf_PDUSession.yaml blob `3572be0315a782691ce8b5546b7bc1d5b22fcd64`。Artifact 表示必须遵循同一 dialect 边界：本地 G.4 根及本地闭包可作为规范化 Artifact 文件；OAS3 根别名及其跨文件可达闭包只能引用锁定 Source Bundle 的原始文件与 JSON Pointer，不得生成“规范化 G.4”副本。Manifest 的 dependencyClosure 必须固定 Source Bundle 的 source commit、Git blob IDs、文件路径和选定 roots；运行期只使用 Bundle 内快照，不访问远端。
4. **SR-026 Provider**：NAS / NGAP 解码 JSON 的 Output Schema 由 Provider 独立发行，固定 OpenAMSM 协议源版本和消息 Profile。首批 0xD1 不证明 0xC1 / 0xC9 / Create / N2 已支持；单 Capability 多 Profile 需证明单一封闭 Output Schema 与 selector 保持 1:1。
5. **SR-027 Bundle**：固定 Source Bundle snapshot、Compiler / Provider / Owner / Host Context dependencies 和选定根的完整可达闭包；无 3GPP 依赖的 Echo 不强制下载 Source Bundle / Codec。运行期不得下载 latest。
6. **Demo 不扩张**：T1 无 NAS-only 必填，T2 选中后经 Codec READ；没有正式 OAS3 Resolver / Provider / 1.6.0 作者源时，仅具体产品 AC BLOCKED，不把 Source Bundle 发布成功当系统 E2E PASS。

详见 [EC01.3GPP 设计](../EC01-3GPP公共Schema/3GPP公共Schema发布与Skill分阶段消费设计说明书.md)。CA-SL 1.6.0-only，不兼容旧版。
