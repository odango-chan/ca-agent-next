## 1. 编译核心与产物

CLI 与浏览器 Worker 共用编译核心。流水线解析作者源并构建 AST，解析 Schema、Capability 与 Callable 依赖，执行静态检查、过程图验证和链接，按版本化契约生成构建产物和诊断。Verify 按相应契约验证生成结果。已发布 v1alpha5 与 Development v1alpha1 各有冻结契约；Development 产物不进入 Next 运行时导入路径。

## 2. when 发布路径

[Compiler #61](https://github.com/odango-chan/ca-skill-compiler/issues/61) 跟踪新版发布产物。编译器复用 CEL 静态检查和 Schema 闭包，要求布尔结果及 G.4 合规，保留源码位置和类型。只在有 when 的 Skill 发布已检查程序与类型描述。Next 消费约束见 [F02 §11](../F02-Skill管理与选择/Skill管理与选择设计说明书.md#11-compiler-发布物与-python-cel-运行时互操作)；精确 Manifest 字段和类型 URL 由正式版本化契约确定。

## 3. ca-skills 发布边界

设计中，ca-skills CI 解析最新稳定 Compiler Release，将解析出的 tag、commit SHA 和发布资产固定在同一次运行中，使用该版本编译支持的 Assurance Skill，验证后才发布 Skill Bundle。解析、契约兼容、编译或验证失败时停止发布，保留诊断与构建证据。记录作者源 SHA、Compiler tag/SHA、契约版本、产物标识和发布证据。Next 消费正式产物，Compiler 负责其工具与 Artifact 契约。

当前状态：待设计评审。ca-skills Bundle 发布流水线实施尚未证实，跨仓验收记为 NOT_RUN。正式语言基线及新版 Compiler 发布输入依赖 [SR-023](../../SR/SR-023-技能作者源与语言规范移交.md) 和 [SR-013](../../SR/SR-013-Compiler已检查when与发布产物.md)。

## 4. 验收

按 SR-013 验证冻结产物回归、合法和非法 when、诊断位置、重复构建以及同一个 Go 产物被 Python 装载的正负向用例。Compiler、Python 互操作与完整 Next E2E 分别记录结果。
