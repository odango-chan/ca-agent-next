## 1. 目标与产品边界

本功能建立从 Skill 作者源到 Agent 可导入发布包的唯一编译/发布链路。Compiler 是外部独立产品，不属于 Agent Runtime，不在 Agent 内置，也不由 Agent 调用。Agent 只导入经过外部发布流程生成的 Skill Bundle。

~~~text
Skill Author Source (ca-skills)
  -> CA-SL v1alpha5 Check
  -> Compiler Build
  -> Compiler Verify
  -> published runtime Artifact
  -> Skill Bundle assembly / release
  -> Next Host Importer
  -> SkillCatalog
~~~

职责分工：

| 组件 | 所有权 |
|---|---|
| ca-skills | SKILL.md、CA-SL 作者源、Schema/业务 Skill 源和 Bundle 发布流水线 |
| ca-skill-compiler | CA-SL Parser/AST、Schema Closure、静态检查、依赖链接、Procedure Graph 校验、Build/Verify、运行时 Artifact 契约 |
| ca-agent-next F02 | 发布 Bundle 导入、基础格式/路径/依赖检查、内存 Catalog、when 运行时装载与求值 |
| ca-skill-studio-demo F09 | 作者体验、编辑、诊断、AI Change Set 和发布前检查界面；不复制 Compiler |

## 2. 版本基线

- CA-SL languageTarget 固定为 connectionagent.io/v1alpha5。
- ca-skill-compiler 当前 main 声明产品版本 v2.1.0。
- 冻结发布 Artifact v1alpha5 保留原 Manifest、布局、字节和 Verify 语义，不允许原地加入 when。
- Development Artifact v1alpha1 保留 executionStatus=NOT_ADMITTED 和 Development 专用 Host Requirements；它不是 Next 可执行 Skill Bundle，不能进入运行时导入路径。
- CA-SL 语言版本与 Compiler Artifact API 版本是两个独立维度。
- 不引入旧版兼容映射，不因 when 需求升级 CA-SL languageTarget。

## 3. Compiler 核心设计

Native CLI 与 Go/WASM Worker 调用同一 Go Core。公共能力包括：

| API | 作用 |
|---|---|
| Check | 解析并校验作者源，返回结构化诊断 |
| InspectDependencies | 展示 Schema、Tool、Capability、Owner、Evidence 等依赖和链接结果 |
| Build | 静态检查通过后生成确定性 Runtime Artifact |
| VerifyBuildResult | 验证 Build Result、Manifest、产物树和契约自洽 |

统一管线：严格输入/版本/路径检查 → YAML parse / AST → Contract/Predicate/Script 解析 → Schema 闭包 → Tool/Capability/Owner/Evidence Linking → CEL/赋值检查 → Procedure Graph、Wait、Mutation、Evidence 语义检查 → Artifact Assembly。

Compiler 不执行 Tool、Python Script、HTTP 请求、Owner mutation 或 Runtime Procedure。Build 失败不得返回部分产物。Native/WASM/Chromium 对相同输入应产生一致诊断和确定性产物。

## 4. when 的编译与发布

CA-SL v1alpha5 已正式定义可选 assurance/contract.yaml.when。它是 Skill 选择条件，不是执行期 Predicate。Compiler Issue #61 的目标是在发布阶段生成 Python Runtime 可直接加载的已检查程序。

目标流程：

1. 在同一 CA-SL v1alpha5 AST 管线中识别 contract.when。
2. 复用 cel-go Parser/Type Checker 与现有 G.4 AST 白名单。
3. Event 类型与 input 类型来自规范 Event Schema 和该 Skill requestSchema 的 G.4 Schema 闭包。
4. 对未知字段、无 requestSchema、非 bool、非法 G.4、optional/nullable 未守卫访问、数值语义不符输出 CEL_INVALID。
5. 保留 YAML SourcePath、line、column 与 CEL SourceInfo。
6. 生成标准 google.api.expr.CheckedExpr（以 Any 包装）和 FileDescriptorSet。
7. Python Runtime 使用固定版本 cel-expr-python 反序列化；不得重新解析原始 CEL 字符串或在每次 Event 上重新做静态类型检查。
8. 对同一 Expression/Program 可重复评估多个 Event activation；错误 fail closed。

建议的产物职责是 Compiler-owned 新版 Runtime Artifact Manifest 引用 CheckedExpr 与 DescriptorSet。具体 API 版本和文件名由 Compiler Owner 的正式 PR/Release 定稿；Next 不自行猜测路径或字段。

## 5. 冻结产物与新产物隔离

- 已发布 Artifact v1alpha5 不变。
- Development Artifact v1alpha1 不变且 NOT_ADMITTED。
- 新版可运行发布 Artifact 必须有独立版本化 Manifest、BuildResult 和 Verify 规则。
- 新发布 Artifact 不得带 Development 专用 executionStatus、hostAdmission 或 Skill Admission 状态。
- Build/Verify 对新版本产物执行确定性重建/比较；失败不返回部分产物。
- 不把 Development Artifact 重新命名后当成可执行发布包。

## 6. ca-skills 发布流水线

目标 CI 步骤：

1. 解析并固定本次使用的最新稳定 Compiler Release tag 与 commit。
2. 检查作者源、Schema、Tool Interface Package 和 Lock。
3. 调用 Compiler Check。
4. 调用 Compiler InspectDependencies，确认依赖闭包。
5. 对支持 Assurance 的 Skill 调用 Build。
6. 对 BuildResult 和 Artifact 调用 Verify。
7. 将 SKILL.md 与 Compiler 运行时 Artifact 组装成发布 Bundle。
8. 生成发布元数据，记录作者源 revision、Compiler release/commit、Artifact API version、Skill identity 和发布资产。
9. 任一检查失败时停止发布，不产出部分 Bundle。

流水线实现必须与 ca-skills 的现行目录和发布工作流核对，不得假定上述步骤已经上线。

## 7. Next 运行时消费

Next Host 只接收发布 Bundle：

- 检查支持的 Bundle/Artifact 版本和必需文件。
- 检查路径、引用、Schema/DescriptorSet 和 Tool/Capability 依赖可解析。
- 反序列化 when CheckedExpr 和类型环境，并在 Catalog generation 中缓存。
- 新 Event 到达时在内存中评估 when；不调用 Compiler、不启动 Compiler 子进程、不重新解析源码。
- Continuation 使用原 Run 与原 Catalog generation，不重新选择 Skill。
- SKILL.md-only Skill 不经过 Compiler；仅用于 LLM-guided。
- 有效 Assurance Skill 可用于 Deterministic 与 LLM-guided；Assurance 存在但无效时导入失败，不降级。

## 8. 失败与诊断

| 失败 | 行为 |
|---|---|
| CA-SL 作者源无效 | Compiler Check 失败，阻断发布 |
| Schema 闭包或 Tool Link 无效 | Compiler Build/Verify 失败 |
| when 类型错误 / 非 bool / G.4 不合规 | CEL_INVALID，阻断发布 |
| Compiler 版本或 Artifact API 不支持 | Bundle 发布/导入失败 |
| CheckedExpr / DescriptorSet 不能反序列化 | Skill 导入失败，不回退原始 CEL |
| when 运行期求值错误 | 当前候选不匹配或返回明确诊断；绝不提升为 true |
| Bundle 文件缺失 / 路径越界 | Host 导入失败 |
| 无匹配 Skill | 停止并返回无候选诊断，不走无绑定通用 Agent |

## 9. Demo 非目标

不把 Compiler 嵌入 Agent；不在 Agent 运行期调用 Compiler；不建设 Skill Admission、审批、生产资格、Owner Trust、签名、Trust Registry、额外 SHA-256、分布式 Artifact Registry、包管理器或自动更新服务。Compiler Build/Verify PASS 不等于 Owner/Provider Trust、OpenAMSM E2E 或 Production Qualification。

## 11. 验收门槛

- Compiler Native/WASM/Chromium 对同一输入保持一致。
- 冻结 Artifact v1alpha5 与 Development v1alpha1 的 Golden/Verify 不变。
- 新发布 Artifact 的 CheckedExpr/DescriptorSet 能被 Python Runtime 实际加载。
- Go 与 Python 对相同规范 fixtures 的 true/false/error 结果一致。
- valid/invalid when、optional/null 守卫、未知字段、非 bool、非法 G.4、共享 Lock 多 Skill 类型隔离均有正负向测试。
- ca-skills CI 从作者源生成并 Verify 完整 Skill Bundle。
- Next 只导入发布 Bundle，不调用 Compiler；SKILL.md-only 和 Assurance Skill 两种路径均有端到端测试。
- 每个 PASS 都记录源 SHA、Compiler release、Artifact API、命令、环境和原始日志；未执行项标记 NOT_RUN。
