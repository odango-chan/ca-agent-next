# ADR-0001 — 从 ca-sandbox 抽离 5GC Reference Simulator

Status: Accepted  
Version: v0.3  
Date: 2026-09-18

> Observation ownership 的后续细化见 [`ADR-0002-fact-owner-direct-observation.md`](ADR-0002-fact-owner-direct-observation.md)，Network Observation 见 ADR-0003。本文早期把 fault/evaluator responsibility 统称为 Sandbox 平台职责的表述，按当前跨仓冻结基线解释：Sandbox 只保留 Environment generation/scheduler 与自己拥有的 control facts；Benchmark/Fault/Evaluation/Fabric responsibilities 分别由其 owner 承担。

## Context

当前 `ca-sandbox` 同时承担 Sandbox 平台职责与内嵌 5GC reference simulation：

```text
Environment lifecycle
fault orchestration
trusted Observation / GroundTruth / Control
+
simulated UE/registration/session state
5GC deterministic business behavior
```

随着 ConnectionAgent 后续要接入 modified Open5GS，继续把 5GC domain model 固定在 Sandbox 内部会造成：

1. Sandbox 平台演进与 5GC domain 演进互相耦合；
2. simulation 与 real Open5GS 难以建立独立、稳定、可验证的 semantic parity contract。

## Decision

建立独立仓：

```text
odango-chan/env-5gc-sim
```

长期职责：

```text
env-5gc-sim
  = deterministic 5GC reference simulator
  = simulated 5GC source-state owner
  = deterministic 5GC reference behavior owner
```

抽离后平台职责进一步按 owner 分开：

```text
ca-sandbox
  = Environment generation / deterministic scheduler / Sandbox-owned control facts

ca-lab
  = process / resource materialization

ca-benchmarks
  = Benchmark Case / GroundTruth / FaultProfile authoring

ca-benchmark-engine
  = Intervention orchestration / Oracle / Validity / Verdict

ca-service-fabric
  = protocol-boundary enforcement / BoundaryFaultReceipt / Network Observation
```

5GC domain Observation 的 fact ownership 由 ADR-0002 进一步规定为 fact-owner direct。

Runtime 保留：

```text
ProviderContract / ProviderBinding
ObservationSource governance / Evidence
Authorization / Assurance
Outcome / Reconcile
Predicate verdict
Tool eligibility
```

Agent-facing MCP 仍由 `ca-mcp` 统一提供；不会在 `env-5gc-sim` 重建 MCP Server。

## Open5GS relationship

`env-5gc-sim` 的 domain model 参考 Open5GS 的真实 5GC 状态和生命周期语义，但：

```text
semantic alignment != implementation mirroring
```

因此不复制 Open5GS 内部 C struct 作为 simulator public contract。

长期目标：

```text
same ConnectionAgent semantic expectation
              │
        ┌─────┴─────┐
        ▼           ▼
  env-5gc-sim    ca-provider-5gc
                    │
                    ▼
             modified Open5GS
```

## Consequences

正面：

- 5GC domain model 可以独立演进和测试；
- Sandbox 回归平台/环境职责；
- simulator 可以针对 registration/session/PFCP/QoS/connectivity 建更真实的分层状态；
- Benchmark 可以逐步形成 simulation / real_nf 语义 parity；
- Open5GS 升级影响集中在 semantic mapping，而不是污染 Sandbox 平台模型。

代价：

- 需要拆分当前 `ca-sandbox/simulator` 中混合的 5GC 与非 5GC 状态；
- Sandbox Environment composition、Benchmark intervention/evaluation binding 与 Fabric simulated lane 需要适配新 simulator contract；
- Runtime Provider/read/ObservationSource integration 需要迁移；
- legacy Sandbox 5GC Observation relay 需要 consumer cutover 后清理；
- 需要短期 compatibility adapter 和明确删除 Gate。

## Rejected alternatives

### A. 继续把 simulator 留在 ca-sandbox

拒绝。会继续混合平台 ownership 与 5GC domain ownership，并妨碍 real Open5GS parity。

### B. 直接 fork/copy Open5GS 作为 simulator

拒绝。目标是 deterministic reference model，不是再维护一个简化版 Open5GS fork。

### C. 复制 Open5GS internal structs 作为公共模型

拒绝。内部实现变化会不必要地破坏 simulator、Skill、Benchmark 和 adapter contract。

### D. 新仓直接提供 Agent MCP

拒绝。ConnectionAgent 的单一 Agent-facing MCP surface 已由 `ca-mcp` owning；simulator 是 Runtime 后端/reference world。

## Invariants

```text
5GC domain state/reference behavior moves out of Sandbox.
Sandbox keeps Environment generation/scheduler and Sandbox-owned control facts; Benchmark/Fault/Evaluation/Fabric responsibilities stay with their owning repositories.
5GC Observation ownership follows ADR-0002 fact-owner-direct semantics.
Runtime execution/observation-governance/assurance authority does not move.
ca-mcp remains the single Agent-facing MCP surface.
Open5GS provides semantic reference, not public-struct authority.
Legacy code/relay is removed only after replacement integration is verified.
```
