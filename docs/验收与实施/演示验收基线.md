## 0. 评审范围

本文只定义当前 Demo 的机制验收。评审必须检查 EX/OM 中明确承诺的功能、架构边界和证据；不得因为缺少生产级 HA/DR、SLA、容量规划、企业级 IAM、Trust Registry、包签名或其他 Agent.md 明确排除的能力而阻塞验收。

Demo 不降低基本正确性要求：输入/Schema/版本/路径校验、fail-closed、Runtime Callable Scope、Owner Receipt/Commit Proof、UNKNOWN、Continuation、原始二进制载荷保真和真实 E2E 证据仍必须满足。具体问题分类和阻塞规则遵守《文档编写与治理规范》。

## 1. Example-first 规则

每个新增外部可观察机制，必须在同一变更中增加可运行 Example 和自动化 Acceptance。Example 位于本仓 examples/，不另建 ca-example 仓库。Example 必须使用公开 Plugin/Skill/Runtime 边界，不得导入 Agent Core 内部模块。

## 2. 第一垂直示例：Echo

一个独立运行的 Go Plugin 通过同一个 Plugin Manager 暴露 Event ingress、Delivery 和至少一个 Tool Operation。

Example 包含：

- 一个含有效发布 Assurance Artifact 的 Echo Skill，可运行 Deterministic 和 LLM-guided 两种模式。
- 一个只有 SKILL.md 的 Echo guidance Skill，只能 LLM-guided。
- 已发布 Artifact 导入用例：有效、格式错误、缺失文件、依赖未解析、类型数据无效。
- 用于选择和 LLM-guided Action 测试的确定性 Fake Model Client。

建议结构：

~~~text
examples/echo/
  plugin/
    plugin.yaml
    schemas/
  published-skills/
    echo-assured/
      SKILL.md
      <Compiler-generated runtime Artifact files>
    echo-guidance/
      SKILL.md
  interface/
  scenarios/
    deterministic/
    llm-guided/
    import-published-artifact/
    selection/
~~~

Compiler 源码编译/发布是外部工具链职责。Next Acceptance 使用预先发布的 Artifact fixture，不导入 Assurance 作者源，不调用 Compiler。

## 4. Skill 选择与执行模式

| 候选状态 | 必须行为 |
|---|---|
| 一个 when=true | 直接选择，不调用 LLM 消歧 |
| 多个 when=true | 只在精确匹配集合内由 LLM 消歧 |
| 没有 true | 只对未声明 when 的 Skill 进行 SKILL.md 语义选择 |
| 没有未声明 when 的候选 | 停止或请求缺失输入 |
| Request Schema 不匹配的新 Event | 排除该 Assurance Skill，记录输入校验诊断并跳过 CEL |
| when=false | 排除，不得重新加入语义候选 |
| when 运行期错误 | fail-closed，排除并记录诊断 |
| when 源码非法/非 bool/类型错误 | 外部 Compiler 在发布前拒绝 |
| LLM 返回未提供的 Skill ID | 拒绝 |
| Continuation | 恢复原 Run，不重新选择 |

Skill 选择总是在执行模式选择之前。无 Assurance Artifact 仅 LLM-guided；有效 Artifact 可 Deterministic 或 LLM-guided；无效 Artifact 导入失败。

## 5. Compiler 与 Tool Plugin 集成边界

- Next 不调用 Compiler 的任何命令。
- ca-skill-compiler 负责作者源解析、静态检查、链接、Artifact Build/Verify 和发布。
- Next 只消费已发布 Artifact，做基本结构、必需文件、类型数据和本地依赖检查。
- ca-skills PR #88 和 Compiler Issue #61 是外部发布契约依赖，不代表已实现。
- Python Runtime 在导入时加载 CheckedExpr Any 和 DescriptorSet，保留 Program/类型环境；Event 热路径不解析 CEL 源、不调用 Compiler。
- Echo Tool Interface Package 使用权威格式；不复制 ToolCatalog，不新增 Host 侧包完整性摘要。
- ca-client-tools 通过统一 Plugin Manager 的 tools Extension 适配；不建立 Provider Manager。

## 6. Demo 验收定义

只有当 EX-01～EX-29 全部 PASS，Assurance-backed Echo 两种模式通过，SKILL.md-only Echo 无 Compiler 调用通过，同一个 Plugin 进程支持 Event/Delivery/Tools，发布 Artifact 导入行为符合规范，SkillCatalog 驻留/代际测试通过，才能接受架构 MVP。

该结果不代表真实 OpenAMSM 资格认证、生产就绪或完整 3GPP 协议符合性。
