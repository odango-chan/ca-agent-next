## 2. 交付物与接口

### 2.1 唯一 Manager 门面

`src/ca_agent_next/plugins/` 只新增一个 Plugin Manager 子系统；包根 `ca_agent_next.__all__` 保持 SR-002 固定列表，不新增公共导出。

```text
PluginManager(host, *, timeouts=None, config=None, logger=None)
  .start(manifest_path, *, config=None) -> PluginProcess
  .invoke_tool(plugin_id, callable_id, arguments, *, invocation_id=None, timeout=None) -> ToolOutcome
  .invoke_tool_async(...) -> ToolInvocation | ToolInvocationHandle
  .dispatch_delivery(plugin_id, *, ...) -> DeliveryOutcome
  .cancel_operation(plugin_id, invocation_id, *, reason="caller_cancelled", timeout=None) -> CancelledOutcome
  .register_driver(driver) / .driver(plugin_id)
  .stop(plugin_id) / .shutdown_all()
```

调用关系：

```text
Plugin Process ──stdout NDJSON──> PluginProcess reader thread
  ├─ ingress.event  -> Manager 校验（声明/Source/Schema/幂等）
  │                    -> Host.handle_event(Event)   [唯一 Host 入口]
  │                    -> ingress.ack（仅 eventId/disposition/error）
  ├─ plugin.ready    -> 整包核对 -> 原子注册 Extension
  ├─ tools.result    -> correlation + invocationId 精确匹配 -> ToolOutcome
  ├─ delivery.result -> correlation + deliveryId 匹配 -> DeliveryOutcome
  ├─ plugin.cancelled-> correlation + targetOperationId 匹配 -> CancelledOutcome
  └─ plugin.stopped  -> 关联 host.shutdown -> 校验 inFlightCount -> shutdown 完成
Host 调用方 ──> Manager.invoke_tool / dispatch_delivery / cancel_operation
                -> tools.invoke / delivery.dispatch / host.cancel（stdin NDJSON）
```

Manager 不创建 Host、AgentLoop、ModelClient、Provider Manager、Tool Registry 或 Codec Manager；不执行 Skill 选择、Callable Scope 授权或 Owner Outcome 判断；不持有 Provider 凭据。

### 2.2 Provider v2 Driver 接口边界（P1-06 → 第二轮 P1-A 收敛）

`src/ca_agent_next/plugins/driver.py` 在唯一 Manager 内只固定**与协议无关的** Driver 缝：

- `ToolsExtensionDriver`：`plugin_id`、`protocol`、`extensions`、`state`、`pending_count`、`start`、`invoke_tool_async`、`dispatch_delivery`、`cancel_operation`、`close`。这是 Manager 唯一依赖的接口。
- `ProviderV2ToolsExtensionDriver`：只在上述接口之上固定 `protocol = ca-client-tools.provider/v2` 与 `extensions = {"tools"}`，作为 Provider v2 的**适配扩展点**；它不声明 Provider v2 专用抽象方法，也不导出任何 Provider v2 私有 DTO。
- `PluginManager.register_driver()` 只维护 `pluginId -> driver` 的进程内派发映射并拥有 `start`/`close` 生命周期；重复 `pluginId` 拒绝；没有第二个 Manager、Callable Registry、授权路径或自动 fallback。

**P1-A 决定（缩小承诺，而不是补齐）**：F03.05 v0.3.7 的文档头状态仍为“目标设计；待评审”，其 §6.4 的 Provider v2 数据合同（catalog 的 supported/unsupported 分区与 backend descriptor、Effect、request/response media type、参数或 generic Schema、Source Pin、Artifact Slot、绝对 RFC3339 UTC deadline、`producerInvocationId`、typed MAS 可选 `hostInvocation`）**不属于 SR-003 已冻结契约**。上一轮 `driver.py` 中的 `ProviderPackageDescriptor`、`ProviderBinding`、`ProviderLimits`、`ProviderInitializeResult`、`ProviderCatalogEntry/Result`、`ProviderInvocation`、`ProviderCancelResult` 与本轮一并撤回，因为它们的字段不足以覆盖 §6.4，若保留即等于伪造一个 SR-010 必须推翻的契约。完整数据合同、initialize/catalog/invoke/cancel 真实帧与跨仓适配由 **SR-010** 在 F03.05 设计门禁通过后定义并实施。

本 SR 的 Driver 测试验证的是：`ProviderV2ToolsExtensionDriver` 继承唯一 `ToolsExtensionDriver` 且抽象方法集合等于通用缝（未新增 v2 专用方法）；`driver` 模块公共导出不含量子 v2 DTO；Manager 源码不引用任何 Provider v2 私有 DTO；Manager 只用通用 Driver 即可完成 tool/delivery/cancel；Native Plugin 行为不变。

### 2.3 Manifest 与 Schema

- YAML：`ruamel.yaml` YAML 1.2、safe loader、`allow_duplicate_keys = False`；单文档、根 mapping。
- 结构：顶层/`metadata`/`process`/`extensions` 及子结构递归拒绝未知字段；版本、kind、身份、Extension 结构、必填字段精确校验。
- 路径：拒绝绝对路径、盘符、`..`、NUL；`Path.resolve()` 后必须仍在包根内（symlink/junction 逃逸拒绝）；可执行文件在 Windows 上按 `.exe` 解析仍受包根约束。
- Schema：UTF-8 JSON、Draft 2020-12 `check_schema`、离线；`$ref` 与 `$dynamicRef` 均只允许文档内 `#` 片段引用，远程/外部引用直接拒绝。
- 本地引用解析（P2-01）：`#` 指向文档根；`#/...` 按 RFC 6901 解析 JSON Pointer；`#name` 必须是同一文档中由 `$anchor` 或 `$dynamicAnchor` **实际声明**的 Anchor（Draft 2020-12 §8.2.3.2 允许 `$dynamicRef` 在无同名 `$dynamicAnchor` 时退回 `$ref` 语义）。`$anchor` 与 `$dynamicAnchor` 分开收集；既非空片段、也非 Pointer、也非合法 Anchor 名称的片段形式（如 `#node/child`、`#1abc`）直接拒绝，不静默放行。
- 顺序：全部静态校验通过后才允许启动进程。
