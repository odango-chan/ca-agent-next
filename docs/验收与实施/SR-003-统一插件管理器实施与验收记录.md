## 2. 交付物与接口

### 2.1 唯一 Manager 门面

`src/ca_agent_next/plugins/` 只新增一个 Plugin Manager 子系统；包根 `ca_agent_next.__all__` 保持 SR-002 固定列表，不新增公共导出。

```text
PluginManager(host, *, timeouts=None, config=None, logger=None)
  .start(manifest_path, *, config=None) -> PluginProcess
  .invoke_tool(plugin_id, callable_id, arguments, *, invocation_id=None, timeout=None) -> ToolOutcome
  .invoke_tool_async(...) -> ToolInvocation
  .dispatch_delivery(plugin_id, *, response_obligation_id, response_channel_id,
                     event_type, body, status_code=200, headers=None,
                     delivery_id=None, timeout=None) -> DeliveryOutcome
  .cancel_operation(plugin_id, invocation_id, *, reason="caller_cancelled",
                    timeout=None) -> CancelledOutcome
  .stop(plugin_id) / .shutdown_all()
```

调用关系：

```text
Plugin Process ──stdout NDJSON──> PluginProcess reader thread
  ├─ ingress.event  -> Manager 校验（声明/Source/Schema/幂等）
  │                    -> Host.handle_event(Event)   [唯一 Host 入口]
  │                    -> ingress.ack（仅 eventId/disposition/error）
  ├─ plugin.ready    -> 整包核对 -> 原子注册 Extension
  ├─ tools.result    -> correlation + invocationId 精确匹配 -> ToolOutcome
  ├─ delivery.result -> correlation + deliveryId 匹配 -> DeliveryOutcome
  ├─ plugin.cancelled-> correlation + targetOperationId 匹配 -> CancelledOutcome
  └─ plugin.stopped  -> shutdown 完成
Host 调用方 ──> Manager.invoke_tool / dispatch_delivery / cancel_operation
                -> tools.invoke / delivery.dispatch / host.cancel（stdin NDJSON）
```

Manager 不创建 Host、AgentLoop、ModelClient、Provider Manager、Tool Registry 或 Codec Manager；不执行 Skill 选择、Callable Scope 授权或 Owner Outcome 判断；不持有 Provider 凭据。

### 2.2 Manifest 与 Schema

- YAML：`ruamel.yaml` YAML 1.2、safe loader、`allow_duplicate_keys = False`；单文档、根 mapping。
- 结构：顶层/`metadata`/`process`/`extensions` 及子结构递归拒绝未知字段；版本、kind、身份、Extension 结构、必填字段精确校验。
- 路径：拒绝绝对路径、盘符、`..`、NUL；`Path.resolve()` 后必须仍在包根内（symlink/junction 逃逸拒绝）；可执行文件在 Windows 上按 `.exe` 解析仍受包根约束。
- Schema：UTF-8 JSON、Draft 2020-12 `check_schema`、离线；`$ref` 仅允许文档内 `#` 片段且必须可解析，远程/外部 `$ref` 直接拒绝。
- 顺序：全部静态校验通过后才允许启动进程。

### 2.3 Go Echo Plugin

- 来源固定为 `ca-agent-next@c1268b4fea4fa181edfac3236cbb103161586013` 的 `examples/echo/plugin/`；未迁入 A 批 Python 测试 Host、脚本或负例夹具。
- 默认参数 `[serve]` 逐帧复现 IPC §5.1 的 12 帧 golden（Host 发送 m1/m4/m5/m7/m9/m11，Plugin 发送 m2/m3/m6/m8/m10/m12）。
- 同一进程导出 `echo.read`、`echo.describe`、`echo.wait`；`echo.wait` 保持 pending 直到匹配的 `host.cancel`。
- 测试专用 `--fault` / `--extensions` / `--ingress` 只能经 Manifest `process.args` 注入；默认调用不使用，生产 Manager 不含测试分支。

## 11. 需设计负责人决策的问题

1. **运行时依赖与 SR-002 冻结断言的冲突。** SR-002 §2.1 固定 `dependencies = []`，其 `tests/test_host.py` 断言发行包无 `Requires-Dist`；SR-003 为实现 YAML 1.2 安全解析（明确禁止使用 PyYAML）和 Draft 2020-12 离线 Schema 校验，需要 `ruamel.yaml` 与 `jsonschema`。本 PR 在 `pyproject.toml` 声明这两项运行时依赖，并把上述断言收窄为“仅允许这两项”，未改动 Host 契约。请设计负责人确认：是由 SR-003 正式取代 SR-002 的“无运行时依赖”约束，还是要求另立 SR/调整依赖策略。
2. **固定 sheet 的 `$ref` 策略。** 本实现仅允许文档内 `$ref`，远程/外部 `$ref` 一律在加载期拒绝（满足“离线校验”）。若后续 SR 需要本地文件级 `$ref`，需另行定义解析根与允许范围。
3. **测试专用故障开关。** Go Echo 对端通过 `--fault` 等参数支持负例；默认调用与 golden 不受影响。若设计要求示例对端保持“零测试模式”，需要改为独立测试对端二进制。
