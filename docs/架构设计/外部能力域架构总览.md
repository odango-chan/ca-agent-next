## 1. 外部能力域分层

外部能力域不是 Next Agent Core 的业务子模块。它们提供作者源、编译工具、Tool/Provider、业务协议 Plugin、Owner、测试对端和工作台。Next Core 通过统一 Skill、Plugin、Tool Interface、Runtime Action Boundary 消费这些能力。

## 3. 跨域协作关系

~~~mermaid
flowchart TB
  AUTHOR[EC01 Skill 作者源] --> COMPILER[EC02 外部 Compiler]
  COMPILER --> BUNDLE[已发布 Skill Bundle]
  BUNDLE --> CORE[Next Python Host / SkillCatalog]
  STUDIO[EC06 Skill Studio] --> AUTHOR
  SBI[EC04 Event/Delivery Plugin] --> HOST[Next Plugin Manager]
  HOST --> CORE
  CORE --> RUNTIME[Next Runtime Action Boundary]
  RUNTIME --> TOOLS[EC03 Tool Interface / Provider]
  TOOLS --> OWNER[EC05 OpenAMSM Owner]
  MOCK[EC07 Mock AMF / Simulator] --> SBI
  REF[REF01 / REF02] -. 参考实现 .-> CORE
  STD[REF03 3GPP/OpenAPI] -. 协议依据 .-> SBI
~~~

边界规则：

1. 新 Event 先由 Host/F02 选择并绑定 Skill；Plugin 不提供 Skill ID、不选模式、不创建 Run。
2. Skill 通过 Tool Interface Package 声明的 Callable 调用 Provider；Provider 不是第二个 Manager。
3. Runtime 统一校验 Deterministic Procedure 与 LLM-guided Action，所有调用经过同一 Action Boundary。
4. Owner 是业务状态权威。HTTP/IPC 成功不等于 COMMITTED；UNKNOWN 不得提升。
5. 原始二进制由 Host ArtifactStore 持有。Event/Delivery staging 与 Host→Tool Artifact Channel 是两条不同通道。
6. 生产资格、完整 3GPP 协议支持和生产级 DFX 不属于当前 Demo 自动要求。
