## 1. 目标与定位

本文是外部能力域的领域级架构总览，不替代各域的详细模块架构、设计说明书和机器契约。项目群所有领域（包括由其他仓库实现的能力域）的架构与设计统一在 `ca-agent-next` 维护；外部仓仍是代码、测试、构建、发布、运行和部署的实现权威。

本目录允许多篇架构文档。总体架构只有一份；每个外部域、子系统或模块可以有独立架构文档。文档与功能树节点采用多对多关系，不按仓库数量或树深度强制一篇对一篇。

## 4. 跨域主流程

### 4.1 Skill 作者源到可执行发布物

1. 作者在 `ca-skills` 维护 `SKILL.md` 与可选 Assurance 源。
2. 对含 Assurance 的 Skill，`ca-skills` CI 解析最新正式稳定 Compiler Release，并在本次 Run 内固定版本。
3. CI 准备准确的 BuildRequest、不可变 Interface Package snapshots、完整依赖闭包和可信绑定；缺失时 fail-closed。
4. CI 运行 Check、Inspect、Build；成功后组装并发布由 `ca-skills` 拥有的 Skill Bundle。
5. Agent 导入发布后的 Runtime Artifact，不在运行时执行 Compiler。
6. 无 Assurance 的 SKILL.md-only Skill 不调用 Compiler。Development `NOT_ADMITTED` Artifact 不作为可执行发布物。

当前状态：`ca-skills` 的 Source Hygiene workflow 仍下载 Compiler v2.0.2，仅执行源语法/诊断和 fail-closed 检查；未执行可执行 Artifact Build/Bundle Release。Compiler v2.1.0 已发布，但 `when` 所需新版 Runtime Artifact 仍受 ca-skills PR #88 和 Compiler Issue #61 阻塞。详见 [F08 技能编译与发布设计说明书](../设计说明书/F08-技能编译与发布/技能编译与发布设计说明书.md)。该流程是目标架构，不标记为已实现。

### 4.2 OpenAMSM 请求执行

1. OpenAMSM SBI Plugin 接收外部 SBI 请求，执行协议层解析、Event 映射和二进制 handoff。
2. Agent Core 根据 Event 与已导入 Skill 元数据/选择规则选定 Skill；Runtime 按已声明的 Callable Scope 执行。
3. Plugin Manager 将 Tool 调用路由到 Tool Plugin / Provider。
4. OpenAMSM Owner 执行业务副作用并返回 Receipt/Commit Proof；Agent 不以 HTTP 200 或模型文本替代 Owner 结果。
5. Delivery Plugin 将响应按协议边界交回外部调用方。

### 4.3 Skill Studio 作者流程

Studio 读取作者规范、Schema 和精确依赖信息，帮助用户编辑 `ca-skills` 中的 Skill 源；AI Authoring 产生候选 Change Set，由用户审查后应用到源文件。Studio 不成为新的语言权威，不替代 Compiler 的静态验证，也不把模型建议直接视为已发布 Artifact。
