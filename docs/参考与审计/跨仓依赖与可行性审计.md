## 1. 当前架构决策

以下决策作为本仓当前基线，优先于本审计中任何早期建议：

- 每个 Skill 必须有 SKILL.md；Assurance 可选，位于 assurance/。
- 无 Assurance Artifact 仅 LLM-guided；有效发布 Assurance Artifact 支持 Deterministic 和 LLM-guided；无效 Artifact 导入失败。
- when 是 assurance/contract.yaml 的可选纯 CEL 选择表达式；predicates.yaml 仍是执行期业务判断。
- 作者源由外部 Compiler 构建并发布；Next 只消费发布 Artifact，不调用 Compiler Check/Build/Inspect/Verify，不建立 Skill Admission。
- LLM Action 经过统一 Runtime Action Boundary，不编译为临时 Procedure。
- 全系统只有一个 Plugin Manager；Tool 是 Plugin 的 Operation；ca-client-tools 作为 tools Extension 接入。
- 不建立 Domain Contract Package、TaskContract Package、第二 Skill Descriptor、Tool Registry 或 Provider Manager。
- SBI Event Plugin 负责 JSON/multipart 和 Content-ID；Host 托管原始二进制；Codec 由 Skill 按需调用。
- SkillCatalog 属于 Python Agent Core/Host，是进程内不可变快照；缓存 SKILL.md、候选元数据、发布 Artifact 引用和已反序列化 when 程序。
- when 在发布前编译和类型检查；Agent 导入时反序列化一次，每个新 Event 使用当前输入求值；不缓存 Event 结果。
- 显式 Skill import/update 构建新 Catalog generation 并原子激活；Invocation 固定 generation；不要求文件监视器或分布式缓存。

## 3. 成熟外部项目的复用决策

### 3.1 ca-skill-compiler：外部工具链，不复制

证据：

- v2.1.0 是独立 Go Compiler。
- 支持 CA-SL v1alpha5 的冻结 Build/Verify 和 Development Build/Verify v1alpha1。
- Compiler 负责源码静态检查、Interface Linking、Schema 闭包和 Artifact 发布。
- 当前 v2.1.0 尚未证明支持 PR #88 提议的 Contract.when 及 Python 可消费的 CheckedExpr Artifact。
- ca-skill-compiler Issue #61 跟踪 新版发布 Runtime Artifact、CheckedExpr Any 和 FileDescriptorSet。

决策：

- 不复制 Go Compiler 源码，不在 Python 重写 Parser、Type Checker、Linker 或 CEL Interpreter。
- Compiler/发布流程在 Agent 外部执行。
- Next 只消费正式发布 Artifact，做基本结构、必需文件、类型数据和本地依赖检查。
- Next 不调用 Compiler 命令，不做 Skill Admission。
- 运行时加载已发布 CheckedExpr 和类型环境，保存于 SkillCatalog；每个新 Event 独立求值。
- Issue #61 已明确 Development v1alpha1 保持冻结；新版发布产物独立版本化。[EC02 Compiler 设计](../设计说明书/EC02-Compiler/Compiler设计说明书.md)汇总职责与门槛。

### 3.2 ca-client-tools：Tool Plugin 外部依赖

证据：

- v1.2.0 是独立 Go Tool/Provider 发布物，Provider v2 使用长生命周期 stdio/NDJSON 进程协议。
- 已发布的 `ca-client-tools_interface_1.1.0.zip` 是正式 Interface Package，包含 11 项 public READ Tools / 2 个 Capabilities；[ca-client-tools#31](https://github.com/odango-chan/ca-client-tools/issues/31) 已完成。
- OpenAMSM MAS Owner v1alpha4 源位于 `contracts/owner/openamsm-mas/v1alpha4`，包含 `ToolCatalog`、`CapabilityContracts`、Schema 与 Evidence Guarantees；它是独立 Owner contract 源，不等同于 `ca-client-tools_interface_1.1.0.zip`。
- Owner backend、私有参数投影和 Owner Receipt 交互由 Go Provider 负责。ca-client-tools#37 的 Runtime-only 私有绑定不是 public CallableCatalog，不得被包装/导出为公开 Tool。
- protocol/nas5gsm 是有限范围纯 Go Codec 库，不自动等于 Agent 可调用 Codec Tool。

决策：

- 将 ca-client-tools 作为导出 tools Extension 的 Plugin。
- 初期可在唯一 Plugin Manager 内适配 provider/v2。
- 不把 Go 实现翻译到 Python，不复制 ToolCatalog 或私有 Owner binding。
- 供 Compiler v2.1.0 使用的 Owner 接口必须由 Owner 发布为正式 `connectionagent.io/interface-package/v1alpha1`，将适用的 ToolCatalog 逻辑载荷作为 `CallableCatalog` 导出，并显式导出 CapabilityCatalog、Schema、EvidenceDescriptor 等静态接口；保留 Package ID、版本、publisher 与原始字节来源。此工作不授权导出 Runtime-only 私有绑定。
- Codec Operation 必须先进入权威 Interface Package 并通过精确消息子集验收，Skill 才能调用。
- 不创建独立 Codec Plugin/Manager。

### 3.3 Skill Studio：作者导入、Compiler Request 与产品集成

证据：

- [ca-skill-studio-demo PR #267](https://github.com/odango-chan/ca-skill-studio-demo/pull/267) 已合并（`11b124679746644f79bd82e296e253b7c463c179`）：浏览器本地 ZIP 导入、Interface Package manifest/文件摘要校验、不可变快照、Package Explorer、只读源码、Schema Preview 与首批 LSP Completion。
- [PR #270](https://github.com/odango-chan/ca-skill-studio-demo/pull/270) 已合并（`d3b1d36e6574d7d9c87473a0ee2340727140fb71`）：默认 Example 载入真实 Create/Modify/Release MAS Skills，并预载 `mas`、`ca-context`、`ca-client` 三类依赖。
- Studio `skillc.lock/v0.1` 是项目导入/来源/原始快照锁；Compiler `interface-dependency-lock/v1alpha1` 应由每次 BuildRequest 从 Contract roots 与精确 Interface Package 快照派生，不应再持久化第二份项目锁。
- CA-SL Contract roots 当前为 `mas: urn:openamsm:mas:tool-contracts` 和 `ca-context: urn:connectionagent:ca:host-context`。Studio lock 中 `mas` 当前是 `tool-catalog`，`ca-context` 当前是 `schema-bundle`；只有额外的 `ca-client` 是正式 Interface Package，且不是这两个 Contract roots。
- Compiler v2.1.0 Development Build 只接受正式 Interface Package 快照。现有 Owner ToolCatalog 和 Host Schema Bundle 不能直接作为 BuildRequest snapshots；Studio 不得伪造 Interface Package manifest 或重写快照字节。
- [PR #272](https://github.com/odango-chan/ca-skill-studio-demo/pull/272) 与 [PR #276](https://github.com/odango-chan/ca-skill-studio-demo/pull/276) 历史 HEAD 曾通过其 CI/Chromium 验收，但当前 #272 落后 main 67 commits，#276 落后 #272 base 9 commits；必须刷新并重跑，历史 PASS 不作为当前合并门禁。

决策：

- Studio 继续维护 `skillc.lock/v0.1` 的不可变快照与来源信息；Compiler lock 只在 BuildRequest 中派生。
- Package Audit 与 AI Authoring 共享同一个 Compiler v2.1.0 Development Build/VerifyDevelopment request builder 与 Worker，不各自实现 Linker，也不静默回退冻结 v2.0.2。
- BuildRequest 只包含当前 Skill Contract 声明的 roots 与其传递闭包。项目内未被引用的额外依赖（如 IntelliSense-only `ca-client`）不得进入 roots；声明的 root 若对应非 Interface Package，必须明确 fail-closed。
- 当前 MAS Example 要达到 LINKED/BUILT，必须由 Owner 将 `urn:openamsm:mas:tool-contracts` 发布为正式 Interface Package，并由 Host 将 `urn:connectionagent:ca:host-context` Development Schema fixture 发布为明确标记 Development 的 Interface Package；保留原 Package ID/version/owner/source。不得把 Runtime-only 私有绑定导出。
- 没有 Contract roots 时，v2.1.0 的非空 snapshots/roots/packages 契约无法表达空闭包。Studio 显示 `NO_INTERFACE_ROOTS / BUILD_NOT_RUN`，不造包、不构造空请求、不回退、不产 Artifact，也不伪造 `NOT_ADMITTED`。若要支持零依赖 Assurance Artifact，需单独版本化 Compiler 契约。
- `ca-client-tools_interface_1.1.0.zip` 只能作为单独正例：synthetic Skill 必须显式声明 `ca-client` root；它不代表 MAS Example 已链接。

### 3.5 ca-openamsm-plugin：Event ingress/Delivery Plugin

证据：

- 主线 eb83c8f2 当时只有 README。
- PR #1 OPEN/DRAFT，为设计提案。
- 目标是对齐 Next Plugin Package/IPC v1alpha1 和 Host Artifact Handoff。

- 独立 Go Plugin 负责 SBI ingress、JSON/multipart、Content-ID、原始 N1/N2 暂存和响应 Delivery。

## 5. 可行性与关键风险

**总体判断：可行，但必须按 Echo → OpenAMSM 分阶段实施。**

主要风险不是 Python/Go 进程互操作，而是架构边界回退：

1. 重新引入 Provider Manager 或 Tool Registry。
2. Agent 运行时再次调用 Compiler，或引入 Skill Admission。
3. 把 Event→Root/Skill 路由表搬入 Core。
4. 将 OpenAMSM Owner、NsmfRunExecutor、Receipt/Reconcile 业务逻辑放进 Event Plugin。
5. 在 Agent Core 复制 3GPP Schema 或 Codec。
6. 将 Synthetic Owner G5 误报为真实隔离 Owner E2E。
7. 将有限 NAS/N2 codec coverage 误报为完整 NGAP 支持。

控制措施：先通过 Echo；每个机制有 Example/Acceptance；发布 Artifact 和 Tool Interface Package 以外部权威契约为准；真实 OpenAMSM E2E 独立验收。

## 7. 证据等级与使用限制

- EVIDENCE：直接核对的源码、发布物、PR/Issue 状态或测试结果。
- INFERENCE：基于证据作出的架构判断。
- PROPOSAL：建议的 Next 实施方向。
- NOT_RUN：没有执行证据。
- NOT_VERIFIED：尚未证明契约/链路成立。
- BLOCKED：存在明确外部依赖或环境阻塞。

本审计不是生产资格认证，也不是对所有仓库测试的重新执行。实施时必须刷新所有外部状态并记录准确 SHA。
