## 1. 当前架构决策

以下决策作为 Next 当前基线，优先于外部参考仓或 OPEN PR 中的早期提案：

- Agent Core、Host、Model Loop、Skill Importer、Skill Resolver 和 Runtime 使用 Python。
- 每个 Skill 必须有 SKILL.md；Assurance 可选。没有 Assurance 只支持 LLM-guided；有效已发布 Assurance Artifact 支持 Deterministic 和 LLM-guided；Artifact 无效则导入失败。
- when 是 CA-SL v1alpha5 的可选 Skill 选择表达式；predicates.yaml 仍是执行期业务判断。
- 作者源由外部 Compiler 构建和发布；Next 只消费已发布 Bundle，不调用 Compiler Check/Build/Inspect/Verify，不建立 Skill Admission。
- LLM Action 和 Deterministic Procedure 都经过同一个 Runtime Action Boundary。
- 全系统只有一个 Plugin Manager；Tool 是 Plugin 的 Operation；ca-client-tools 作为 tools Extension 接入。
- Tool Interface Package、Owner Contract、Provider Runtime Bindings 是不同权威层；Provider 私有 Backend ID 不暴露给 Skill/模型。
- SBI Event Plugin 负责 JSON/multipart、Content-ID 和原始字节 staging；Host 拥有 ArtifactStore；Codec 按需作为 Tool Callable。
- Event/Delivery staging 与 Host→Tool Artifact Channel 是两条不同路径。ca-host.artifact-store/v1 已冻结；Provider v1.2.0 consumer 与 ca-agent Go Host P1 已有外部实现，Next Python Host 尚未实现；artifact-bearing Provider binding 未配置 artifactChannel 时必须 NOT_CONFIGURED，并在远端 I/O 前拒绝。
- SkillCatalog 是 Python Host/Core 进程内不可变快照；已发布 when 程序导入时反序列化一次，每个新 Event 使用当前输入求值；不缓存 Event 求值结果。
- 显式 Skill import/update 构建新 Catalog generation 并原子激活；Invocation 固定 generation；references 按需加载。

## 3. 成熟外部项目的复用与依赖决策

### 3.1 ca-skill-compiler：外部工具链，不复制

- v2.1.0 是独立 Go Compiler。
- 冻结 Build/Verify v1alpha5 与 Development Build/Verify v1alpha1 分离。
- Issue #61 OPEN，跟踪 when 的 CheckedExpr / DescriptorSet 发布型 Runtime Artifact、Go/Python 产品互操作和新版 Artifact Schema。
- AC-013-01 隔离 PoC 已在 Compiler 255ab85 隔离副本完成：真实 Schema Registry 管线、Go 生成 CheckedExpr Any / FileDescriptorSet、Python 直接反序列化、Go/Python 18/18 一致；三态、布尔组合、嵌套路径、int64/finite double 边界、6 类非法输入和多 Skill 隔离有证据。该 PoC 不代表 Compiler 产品 Core、Artifact Schema、Build/Verify/Release 或 Next Consumer PASS。

决策：不复制 Go Compiler，不在 Python 重写 Parser/Type Checker/Linker/CEL Interpreter。Agent 只消费正式发布 Artifact；不调用 Compiler 命令，不建立 Skill Admission。

### 3.2 ca-client-tools：Tool Plugin 外部依赖

- v1.2.0 是独立 Go Tool/Provider 发布物。
- Provider v2 是 Provider 进程/协议，不是 Next Plugin IPC。
- Tool Interface Package 定义 Callable ID、IO Schema、Effect、Capability 和 Artifact IO；Owner Contract 定义权威业务结果、Receipt/Proof/Reconcile；Provider Runtime Bindings 映射私有 Backend operation。
- PR #39 OPEN：Phase A Codec 审计与缺陷修复有证据；Phase B Worker/Facade 有证据；Phase C Consumer Migration NOT_STARTED。
- Codec 只有在正式 Tool Interface Package 发布 Callable、Schema 和消息范围后，才是 Agent 可调用 Tool。

决策：通过唯一 Plugin Manager 的 ProviderV2 Driver 接入；不建立第二 Provider Manager、Tool Registry 或 Codec Manager。

## 5. 关键风险与控制

1. **设计分叉**：所有架构/设计/规范/ADR 统一在 Next；兄弟仓只留实现资料和链接。
2. **第二 Manager**：Tool 是 Plugin Operation；ProviderV2 Driver 归唯一 Plugin Manager。
3. **Compiler 越界**：Agent 只消费发布 Bundle，不调用 Compiler、不做 Admission。
4. **when 不一致**：Issue #61 未完成前，不解析 CEL 原文、不使用 DynType、不声称跨语言 Runtime PASS。
5. **Artifact 通道混用**：Event staging 与 Host→Tool Artifact Channel 分离；ca-host.artifact-store/v1 已冻结且 Provider v1.2.0 / Go Host 有外部实现证据，但 Next Python Host server 尚未实现；Next artifact-bearing Provider binding 必须 NOT_CONFIGURED 并 fail closed。
6. **Owner 结果误判**：HTTP/IPC 成功不等于 COMMITTED；UNKNOWN 不提升；Reconcile 绑定原始 Invocation。
7. **Codec 覆盖夸大**：只声明发布和测试过的消息子集；NGAP full PDU 不作未证实声明。
8. **参考实现误迁移**：不将 ca-agent-demo 的 5GC 业务路由、Artifact SHA-256 内容寻址或完整 Planning Context 体系复制到 Next。

## 6. 可行性判断

**总体可行，建议按 Echo → Skill 导入/选择 → Runtime → OpenAMSM 分阶段推进。** 当前外部能力基础已具备部分必要条件：CA-SL v1alpha5 已发布、Compiler v2.1.0 已发布、ca-client-tools v1.2.0 已发布、OpenAMSM Owner v1alpha4 已发布、Mock AMF 进入 main、ca-agent-demo 有 Development E2E 参考证据。

尚未闭合的关键依赖：
- Compiler #61 when 发布型 Artifact 与 Python 产品消费；
- Next Host / Plugin Manager / Skill Importer / Resolver / Runtime 尚未实现；
- ca-openamsm-plugin main 无实现；
- ca-client-tools PR #39 Phase C Consumer Migration 未开始；
- Next Host→Tool ca-host.artifact-store/v1 channel server 尚未实现；
- 当前 Owner-linked Skill revision 的 Development E2E 需重新验证；
- Next Echo 和真实 OpenAMSM E2E 尚未运行。

因此外部基础成熟不代表 Next 已可直接实施。各 SR 必须达到 READY，明确目标仓、固定 SHA、Issue、代码路径、测试命令和验收门槛后，才能生成 DeepSeek Harness Goal 提示词。

## 7. 证据等级与使用限制

- EVIDENCE：直接核对的源码、发布物、PR/Issue 状态或实际测试结果。
- INFERENCE：基于证据作出的架构判断。
- PROPOSAL：Next 的候选实施方向。
- NOT_RUN：没有执行证据。
- NOT_VERIFIED：尚未证明契约/链路成立。
- BLOCKED：存在明确外部依赖或环境阻塞。

本审计不是生产资格认证，也不是对所有外部仓测试的重新执行。实施前必须刷新外部状态并记录准确 SHA。外部仓 PASS 不计入 Next PASS。
