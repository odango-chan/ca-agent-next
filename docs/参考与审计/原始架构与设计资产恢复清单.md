## 1. 目的与恢复规则

本清单记录从各实现仓恢复到 ca-agent-next 的原始架构、设计和决策资产，并将它们与 Next 的目标设计、当前实现证据分开管理。

每个功能必须形成三层材料：

1. **原始设计资产**：源仓实际存在的架构、设计、ADR、契约及其固定提交。保留原文和原始状态；历史、废弃或提案不能改写成现行设计。
2. **Next 目标设计**：按尚未实现视角完整说明目标、范围/非目标、决策、组件、接口/Schema、数据与控制流、状态/错误、配置、部署、测试/验收和依赖。它是 Next 的设计权威。
3. **实现审计**：独立核对当前 main 的代码、测试、PR、Commit、发布物和运行证据，逐项标记 IMPLEMENTED / PARTIAL / NOT_IMPLEMENTED / NOT_RUN / UNVERIFIED，并说明差异。源仓实现不自动等于 Next 实现。

不得用 README 摘要替代设计；不得把当前代码反推成历史决策；不得虚构未存在的原始设计；没有正式设计文档时，必须明确标记“实现派生重建”，并列出代码定位和推导依据。

- 每份迁入原始资产保留源仓、源路径、固定 SHA、PR/Release（如有）、原状态和原文修订历史。

- 所有源仓旧链接和 Next 内部链接经过校验；功能树、文档索引、SR 设计依据、修订记录同步。
- 文档静态检查通过不等于 DeepSeek Harness 实际执行通过。Harness 验证必须记录实际模型 ID、reasoning effort、Goal 模式、执行时间和原始结果；本轮尚未执行 Harness 时保持 NOT_RUN。
- 只有某一功能对应的完整设计与 SR 达到门禁后，才生成该功能的 DeepSeek Harness Goal 提示词。
