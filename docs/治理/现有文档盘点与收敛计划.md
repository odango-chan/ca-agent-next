## 4. 本轮统一的架构边界

- Agent Core、Host、Model Loop、Importer、Resolver 和 Runtime 使用 Python；独立 Plugin 可使用 Go。
- 全系统只有一个 Plugin Manager。Plugin 可导出 Event ingress、Delivery、Tools Extension；Tool 是 Plugin 导出的 Operation。
- Tool Interface Package 是 Callable ID、Schema、Effect、Capability 归属和 Owner 结果语义的权威来源。
- 每个 Skill 必须有 SKILL.md；Assurance 可选。无 Assurance 仅 LLM-guided；有效发布 Artifact 支持两种模式；无效 Artifact 导入失败，不得静默降级。
- Skill 选择只使用 assurance/contract.yaml 的可选 when；predicates.yaml 仅用于执行期业务判断。
- Agent 只导入已发布 Skill 包，不导入 Assurance 作者源，不调用 Compiler，不建立 Skill Admission。
- SkillCatalog 由 Core/Host 拥有；启动或显式更新时读取并构建不可变 generation；新 Event 对内存中的 when 程序求值；在途 Invocation 固定 generation。
- Deterministic 与 LLM-guided Action 共享同一个 Runtime Action Boundary。
- SBI 可携带 JSON/multipart/二进制。Event Plugin 负责外部协议与 Content-ID；Host 管理 ArtifactStore；Codec 按需作为 ca-client-tools 的 Tool Operation 调用。
- 不增加 activation.yaml、constraint.yaml、第二份 Skill Descriptor、Domain/Task Contract Package、额外 Registry/Manager 或旧版兼容层。
- Demo 不做生产级可靠性和安全 DFX；但基本校验、明确错误、fail-closed、Owner 结果语义和自动化验收不可省略。

## 6. 后续收敛原则

1. 新增机制优先扩展现有五份设计说明书或六份规范。
2. 新字段先进入唯一规范，再更新设计说明书和消费者。
3. 新机制必须有可运行 Example 和 Acceptance。
4. 跨仓只引用权威契约，不复制字段表。
5. 生产可靠性和安全 DFX 暂不展开；Demo 功能正确性要求不能省略。
6. 每次文档更新同步维护索引、状态、版本依据和交叉链接。
7. 被替代文档先迁移有效内容、核对链接，再删除旧路径；不保留重复英文副本。
