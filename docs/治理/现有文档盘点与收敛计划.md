## 1. 盘点结论

本轮盘点时，PR #1 原有 9 份技术文档，另有 README.md 和 Agent.md 两个入口文件。内容已经覆盖总体架构、Plugin Package/IPC、Artifact Handoff、SkillCatalog/Compiler 互操作、验收、实施计划和复用审计，但存在以下问题：

1. 文档混用英文与中文，部分正文和文件名为英文。
2. 总体架构、Plugin 规范和 Artifact 机制的细节交叉重复。
3. Plugin Package 是规范性契约，却与总体架构混放。
4. SkillCatalog/Compiler 互操作设计位于“集成设计”目录，与架构/设计目录层级不一致。
5. DeepSeek Harness 提示词和实施计划部分重复，且早期提示词要求 Next 调用 Compiler。
6. 缺少集中规范目录，Skill、Plugin、公共契约、文档目录和术语没有统一索引。
7. README 和 Agent.md 仍引用旧英文路径，容易导致后续实现读错文档。

- 术语与命名规范：统一 Agent、Host、Runtime、Plugin、Tool、Skill 等术语。

## 4. 本轮必须统一的最新架构边界

最新验收修订将 Next 的职责收敛为“消费已发布 Skill Artifact”：

- Compiler/发布流程负责 CA-SL 作者源编译、静态检查、链接、Artifact 验证和发布。
- Next 不调用 Compiler Check/Build/Inspect/Verify。
- Next 不设置独立 Skill Admission 或生产级授权阶段。
- Next 只检查发布包的基本结构、必需文件、格式、路径、类型数据和本地 Tool/Capability 依赖。
- when 在发布前由 Compiler 静态检查；Agent 导入时反序列化一次，保存在 SkillCatalog 中；每个新 Event 独立求值。
- Runtime 仍做当前 Skill 声明 Callable Scope 的基本检查，并通过统一 Action Boundary 调用 Tool。
- Assurance 不存在时仅 LLM-guided；存在有效发布 Artifact 时 Deterministic 和 LLM-guided 都可用；Artifact 无效时导入失败，不降级。

该边界必须同步体现在总体架构、Skill 设计、规范、验收、实施计划和 Agent.md 中。

## 6. 后续收敛原则

1. 新增机制优先扩展现有四份设计说明书或六份规范，不轻易新建文档。
2. 新字段先进入唯一规范，再更新设计说明书和消费者。
3. 新机制必须有 Example 和 Acceptance。
4. 跨仓只引用权威契约，不复制字段表。
5. 生产 DFX 暂不展开；Demo 正确性门槛不得省略。
6. 每次更新文档都同步维护总目录和 README/Agent 入口。
7. 旧英文路径删除前，先确认新文档保留了其全部有效设计和证据。
