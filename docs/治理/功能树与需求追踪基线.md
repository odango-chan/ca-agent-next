## 1. 目标与设计原则

功能树是 CA Agent 系统的统一入口。它同时覆盖：

1. ca-agent-next 自有功能：由 Next 负责需求、架构、设计、实现和验收。
2. 外部能力域：由其他仓库实现和发布，设计集中到 Next。
3. 外部参考与演进目标：用于代码复用、标准对照和后续晋级，不作为 Next 的运行时功能。
4. 工程治理支撑：文档、SR、评审上下文自动生成等非运行时能力。

必须遵守：

- **设计文档按功能维护，不按 SR 或 Issue 拆分。** 功能树允许不定深度；领域、子系统、模块可按职责和验收边界继续分解。功能节点与架构及设计文档可以多对多。分类节点无需单独建文档或 SR。
- SR 是可独立实施、验收和追踪的需求记录；SR 文档不是第二份设计说明书。
- 从 [IR 总登记册](../IR/IR%20总登记册.md) 查需求意图及协作入口，从 SR 查实施范围及验收证据。
- 外部能力设计按功能整合到 Next，保留发布基线、实现归属及消费接口。
- 架构设计和设计说明书在 docs 下同级；总体架构只有一份。
- SR ID 不重排、不复用；废弃需求保留记录和原因。

## 9. 按功能识别与按需阅读

所有 Agent/Harness 先读本文，再按任务读取：

1. 从用户任务、Issue、PR 或变更文件识别 Feature。
2. 找到对应 SR 和状态；DRAFT 或 BLOCKED 不得直接实施。
3. 读取该 Feature 的功能设计说明书相关章节。
4. 读取该功能引用的规范。
5. 涉及跨仓时，按 §5.1 定位权威入口。先核对 Next SR 是否明确覆盖目标仓和改动；登记并达到 READY 后，再进入对应仓实施。
6. 读取对应 Acceptance 和测试。
7. 完成后回填 SR、Issue、PR、Commit、Test 和状态。

示例：Skill when 改动读取 F02 设计、Skill 格式规范和 EC01/EC02；Plugin IPC 改动读取 F03 设计和 Plugin IPC 规范；OpenAMSM multipart 改动读取 F05/F06、EC04 和 REF02。不要让每项任务加载所有功能文档。
