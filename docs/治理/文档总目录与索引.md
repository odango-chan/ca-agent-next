## 1. 文档体系与目录原则

架构设计与设计说明书在 docs 下同级。全局总体架构只保留一份；允许按领域、子系统和模块增加多篇架构设计文档。功能树节点与架构/设计文档是多对多关系，不实行“一个 Feature 一篇文档”。详细机制进入设计说明书；文件结构、字段、协议和公共契约进入规范。治理、验收实施、参考审计各自独立，不再保留散落在 docs 根目录或英文目录中的第二份权威说明。

~~~text
docs/
├── 架构设计/
│   ├── CA Agent Next 架构设计.md             # 唯一总体架构
│   ├── 外部能力域架构总览.md
│   ├── 自有功能域/                          # 可按模块继续分层
│   └── 外部能力域/                          # EC01/EC02/...，可按子模块继续分层
├── 设计说明书/
├── 规范/
├── IR/               # 需求项总登记册
├── SR/               # 独立编号的软件需求记录
├── 决策记录/          # 重大决策记录；当前没有单独 ADR
├── 治理/
├── 验收与实施/
└── 参考与审计/
~~~

README.md 是人工阅读入口；Agent.md 是自动化协作规则。两者不计入正式文档数量。

## 4. 推荐阅读路径

- 首次了解系统：README.md → 总体架构 → 本索引。
- 实现 Plugin：插件管理设计说明书 → 插件包与进程通信协议规范 → 演示验收基线。
- 实现 Skill 导入/选择：Skill管理与选择设计说明书 → 技能与确定性保障格式规范 → 公共契约与所有权规范。
- 实现 Compiler/Python CEL 互操作：Skill 管理与选择设计说明书 §11 → Skill管理与选择设计说明书。
- 实现 Runtime：Runtime执行设计说明书 → 公共契约与所有权规范 → 演示验收基线。
- 接入 SBI 二进制：Context与Artifact管理设计说明书 → 插件包与进程通信协议规范。
- 开始编码：Agent.md → SR 总索引 → READY 的对应 SR → 设计说明书/规范 → 验收基线 → 当前实现和测试。
- 设计刷新：对比文档版本 → SR 影响分析 → 新建/替代 SR → 更新总索引与实施状态。
- 发起独立评审：Agent.md review_scope → 文档编写与治理规范 → 本次 SR/Acceptance → CI 生成评审上下文（实施后）→ 统一评审提示词。 

## 5. 后续新增文档规则

新增文档前先判断现有文档是否能扩展。只有具备独立权威职责、独立消费者或独立验收边界时才新建文件。

每次新增、移动或废弃文档必须同步更新：

1. 本索引和文档数量。
2. 现有文档盘点与收敛计划。
3. README.md 导航（入口变化时）。
4. Agent.md 必读清单（协作规则或必读范围变化时）。
5. 受影响文档中的交叉链接。

不得增加第二份系统总体架构；允许增加领域/子系统/模块架构文档，并按功能树节点建立多对多映射。不得把字段级规范复制进设计说明书；不得把历史审计材料当作当前规范源。
