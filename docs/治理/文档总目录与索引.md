## 1. 文档体系与目录原则

架构设计与设计说明书在 docs 下同级。总体架构只保留一份；功能设计说明书按功能长期维护；协议、字段和公共契约进入规范；重大不可逆决策进入 ADR。IR 记录需求意图，SR 记录可独立实施/验收的需求，不按 SR 数量复制设计文档。

ca-agent-next 是 CA Agent 项目群的统一设计与治理中心。外部仓库的架构、设计、规范和关键决策迁入本仓；外部仓保留实现代码、测试、发布、部署、运行和故障排查资料，并链接到本仓对应功能设计。迁入的原文必须标明来源仓、源路径、固定 SHA 和源状态；原文是历史/参考资料，不自动成为 Next 目标契约。

~~~text
docs/
├── 架构设计/       # 唯一总体架构、外部能力域架构和参考架构
├── 设计说明书/     # F01～F09/G02 功能与工程工具链设计、EC02 Compiler 设计、迁移的原始设计
├── 规范/           # CA-SL、公共契约、Plugin IPC、文件/文档/SR 治理规范
├── 决策记录/       # ADR
├── IR/             # 需求意图登记册
├── SR/             # 独立编号的软件需求记录
├── 治理/           # 功能树、文档索引、状态和收敛台账
├── 验收与实施/     # Acceptance、实施路线和 Harness 交付门槛
└── 参考与审计/     # 源码复用、跨仓依赖、迁移审计和实现证据
~~~

README.md 是人工阅读入口；Agent.md 是自动化协作规则。两者计入 Markdown 总量，不计入下述 47 份正式设计/治理文档。

## 5. 后续新增文档规则

新增文档前先判断现有功能设计是否能扩展。只有具备独立权威职责、独立消费者或独立验收边界时才新建文件。功能增强刷新原设计并增加修订记录；新增功能才新增设计文档。

每次新增、移动或废弃文档必须同步更新：

1. 本索引和文档数量。
2. 功能树与需求追踪基线。
3. 现有文档盘点与收敛计划、原始资产恢复清单和跨仓迁移审计。
4. SR 总索引与实施状态总览（影响需求或状态时）。
5. README.md 导航（入口变化时）。
6. Agent.md 必读清单（协作规则或必读范围变化时）。
7. 受影响文档中的交叉链接。

不得增加第二份总体架构设计；不得把字段级规范复制进设计说明书；不得把历史审计材料当作当前规范源；不得在未评审的状态下向 DeepSeek Harness 发出 READY 实施提示词。
