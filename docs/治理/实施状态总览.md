## 5. 状态维护规则

1. 各 SR 状态发生变化时，先更新 SR 文件，再更新本表和 SR 总索引。
2. PR OPEN 只能证明工作进行中；代码合并后可进入 IMPLEMENTED，验收通过后才能 VERIFIED。
3. 设计文档迁移完成不代表设计评审通过；静态链接检查通过也不代表实现通过。
4. 任何未运行的测试必须保持 NOT_RUN；外部依赖不确定时标记 BLOCKED 或 NOT_VERIFIED。
5. 子阶段 READY 不提升父 SR 状态；只有完整 SR 的范围、依赖和验收全部满足时才能进入 READY。
6. 本表为快照，不得脱离 SR 文件独立修改状态。
