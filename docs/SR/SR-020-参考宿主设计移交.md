## 2. 实施范围

- 保留当前参考宿主的运行方式和既有演示证据；逐项核对复用，与历史 admission 和 v0.5 未交付方案分离。
- 将 Host-owned subject Context Schema fixture 发布为 Compiler v2.1.0 可消费的正式 `connectionagent.io/interface-package/v1alpha1` 包，供 Contract root `ca-context: urn:connectionagent:ca:host-context` 使用。
- 固定 Package ID `urn:connectionagent:ca:host-context`、Language Target `connectionagent.io/v1alpha5`。声明 Publisher `odango-chan/ca-agent-demo`（仓库身份，不是 Owner Trust principal）。Compiler v2.1.0 要求 formal Interface Package version 是 exact SemVer；建议 `1.0.0-dev.1`，原始 Schema ID 版本 `v1` 保留在 provenance。**该映射尚待用户确认；未确认前本 SR 不得 READY。**
- 正式 `package.json` 严格遵循 Compiler v2.1.0 `contracts/development/v1alpha1/interface-package.schema.json`：`apiVersion`、`packageId`、`version`、`languageTarget`、`publisher`、`dependencies`、`exports`、`files` 为完整字段集合；不得添加 `sourceStatus` 等字段。Compiler parser 要求 snapshot key version 为 SemVer，且 package.json.version 与 key 完全相等；源版本 `v1` 不能直接作为 package version。
- ZIP 仅包含根 `package.json` 与原始 `subject.schema.json`；发布一个 `Schema` export，ID 精确等于 `$id=urn:connectionagent:ca:context:subject:v1`，路径为 `subject.schema.json`。Schema 原始字节不得重写或重新序列化。正式 `package.json` 的 `dependencies: []`，`exports` 仅含上述 Schema，`files[]` 仅列出 `subject.schema.json` 的精确 SHA-256（不列 package.json）。
- 新增 `scripts/build_host_context_interface_package.py`，支持：
  ```bash
  python scripts/build_host_context_interface_package.py build --out dist/ca-agent-demo_host-context_interface_v1.zip
  python scripts/build_host_context_interface_package.py verify --package dist/ca-agent-demo_host-context_interface_v1.zip
  ```
  从固定 fixture 读取原始字节，验证 Git blob / `$id` / draft / required shape，按固定字段生成 package.json。ZIP 文件顺序、时间戳、权限和压缩方式固定；重复 build 必须逐字节相同。
- 来源身份固定为 repository `odango-chan/ca-agent-demo`、path `tests/fixtures/compiler/mas-v1alpha5-scheme-c/trusted/snapshots/ca-context`、source Revision `57e277ff9094dad93543df46910a12a1dbbaf560`、Schema source blob `4faee66642b8bc5eb2e45c131be4688b982037d8`、sourceVersion `v1`。Publisher Release tag/commit 与 Schema source Revision/blob 分别记录，不混为同一身份。
- 在 Host 仓新增固定 Compiler schema fixture：`tests/fixtures/compiler/v2.1.0/interface-package.schema.json`，逐字节复制 Compiler v2.1.0 官方文件，blob `f4cd831d21afd15665c92e99ffe2c3b31a3583df`。使用仓库已有 jsonschema 依赖离线验证 package.json；构建过程不联网下载 Compiler 或 Schema。
- 新增 `ca-agent-demo_host-context_interface_v1.provenance.json` Release sidecar，记录 formal Package ID/version/publisher、Publisher Release tag/revision/ZIP asset digest，以及 source repository、source Revision、source path、sourceVersion `v1` 和 Schema blob。Sidecar 不进入 ZIP 或 `package.json.files[])，但纳入 `SHA256SUMS)，供 Studio 导入时恢复 source provenance。
- 当前 `release.yml` / `release-request.yml` 的 SHA256SUMS、preflight artifact 和发布后下载校验均未覆盖 ZIP。两条 Workflow 都必须生成并 verify ZIP + provenance sidecar，将两者纳入 `SHA256SUMS` 和 preflight artifact；Windows preflight 也验证 ZIP；发布后下载 ZIP、sidecar、SHA256SUMS，校验摘要、包内容和 identity。若当前项目版本仍为 `0.4.0`，下一次 Host code release tag 为 `v0.4.1`。
- Host 的 `sourceStatus=DEVELOPMENT_FIXTURE` 只由 Studio 写入 `skillc.lock/v0.1` 的 source metadata；不得写入正式 package.json 或 provenance sidecar。Compiler BuildRequest 的 `profile=DEVELOPMENT` 是构建档位，不授予 Host Admission。Publisher 声明和 Build PASS 均不构成 Host Trust 或 Admission。

## 3. 依赖与启动条件

- 依赖 Compiler v2.1.0 冻结 Interface Package schema、F09 §4.5 和 Studio #269 的 BuildRequest/Import 集成。
- Publisher 必须从上述固定 Revision 读取原始 Schema 字节；不从 Studio 项目导出、重新生成或修订 Schema。
- `make verify` 包含 Publisher 单元测试；构建脚本不联网。Release workflow 使用官方 Compiler v2.1.0 binary（SHA-256 `11da056ae5fff416de1fcfacd0a3535a4392a2b2d7349d928f41e1928398b568`）对只声明 `ca-context` root 的 synthetic Skill 执行 Development Build + VerifyDevelopment。
