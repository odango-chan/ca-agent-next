## 3. 目标设计约束

- Theia Browser-Only / 静态 Pages 为主要入口，复用原生 Explorer、Editor、Outline、Problems 和 Markdown Preview。
- 默认双栏：左源码、右预览；不保留常驻第三栏。
- Package View 默认打开；依赖只读；源码是唯一权威数据。
- Source-first 编辑；可视化图、ELK 布局、React Flow 和 Inspector 均为源码投影。
- Patch 必须绑定精确 source span、文档版本和 Package generation；Apply 前显示 Diff、用户确认、原生 WorkspaceEdit、Undo/Redo。
- LSP 导航、补全和诊断只覆盖明确支持的语言特性；不替代 Compiler 或完整 Python 类型检查。
- AI Authoring 输出结构化 Change Set，不直接写文件；应用前校验 Schema、Operation allowlist、base revision 和 Compiler gate。
- Gateway 凭据不进入浏览器或模型上下文；无 Gateway / 无 Compiler 时明确禁用对应能力。
- 只保留最新 CA-SL v1alpha5 入口，不支持旧版本兼容。

## 4. 必须核对的设计差异

Studio 源文的 Plugin-managed configuration v0.1 目标取消固定 lib/output 目录；当前 main 实现和历史用户工作区仍有 skills/lib/output 布局。必须分别记录当前实现与目标契约，不能静默删除或迁移用户文件。此差异在评审决定前不得据此修改现有 Package 文件。

AI Workbench 使用 Editor Tab 和受控 Change Set；其内部 Context、Diff、Plan/Flow 等内容不得演变成违背双栏原则的常驻第三列。
