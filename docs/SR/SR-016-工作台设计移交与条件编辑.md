## 2. 目标功能与交付边界（唯一 CA-SL 1.6.0）

- 交付者：`odango-chan/ca-skill-studio-demo`；主功能 F09 / EC06。历史 Studio #267/#270 ZIP 导入和 Example preload 已合入旧基线，**本 SR 不重新实施已有旧功能，也不保留旧 v1alpha5 兼容入口**。
- 新 Studio 项目只接受 CA-SL 1.6.0 作者源和 1.6.0 正式 Interface Package；Package Explorer 对 Skill 作者仅暴露 Package→Capability，内部 Caller/Backend Operation 不作为作者节点。Schema/SourcePath/LSP、AI Change Set、源码/预览均复用同一 Buffer。
- Studio 仅管理持久项目依赖锁（新版本的 wire Schema 由 Compiler/Studio Owner 冻结），Compiler BuildRequest/依赖快照/结果由此锁与当前候选源码精确派生；不复制 Compiler Linker/Schema Registry。
- Package Audit、AI Authoring、Preview 均调用唯一已发布的**新 1.6.0 Compiler Check/Build/Verify Worker**；禁止从旧 v2.1.0 `build-development`、Development v1alpha1 Lock 和老的 `skillc.lock/v0.1` 协议兼容升级。新语言目标与 Runtime 不内置 Compiler 的边界独立，Studio 只是作者工具。
- 新 Build 契约必须区分 Capability roots 与 Schema dependency closure：没有外部 Capability、也没有外部 Schema 引用时允许空 Package dependency closure；若 Contract.contexts 引用 SR-030 Schema-only Package，则只纳入精确 Schema export / $ref 闭包，Capability roots 与 Callable bindings 仍为空。有外部 Capability 使用但无声明依赖必须静态失败。只有 SKILL.md 的 Skill 不构建 Assurance；正式 Compiler Schema / DTO 未冻结时对应 AC 保持 BLOCKED，不编造格式。
- 设计依据以 [F09 §5～§6、§9](../设计说明书/F09-技能工作台与AI编写/技能工作台与AI编写设计说明书.md) 与 [SR-029](SR-029-Capability-first-Skill作者接口与Callable一对一绑定.md) 为唯一生效目标；F09 §4 和本文 §1 所列旧 Compiler v2.1.0/Owner v1alpha4/Studio ZIP 属历史证据，不作为新版机器契约。
