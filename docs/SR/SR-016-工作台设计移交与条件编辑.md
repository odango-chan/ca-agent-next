## 1. 目标仓与基线

`odango-chan/ca-skill-studio-demo`，`main`，基线 `5b666c0ef754ed32fa37c97ce2429f328c70477f`。CA-SL v1alpha5 为唯一作者语言基线。PR #267（Interface Package Import）与 #270（真实 MAS Example 依赖预载）已合并；#261 仍跟踪编辑器 UX/Schema LSP 剩余验收。Compiler v2.1.0 Development Build request/Worker 分别由 #272/#276 推进，但两个 PR 的测试 HEAD 已落后当前 main/base，不能作为当前合并门禁。

## 2. 实施范围

- 迁移 Theia/source-first、LSP、Package View、Interface Package 导入和 AI Authoring 设计。
- 固定 Studio 项目锁 `skillc.lock/v0.1` 与 Compiler `interface-dependency-lock/v1alpha1` 的职责边界；Compiler lock 由 BuildRequest 从 Contract roots 和精确快照派生，不另建持久项目锁。
- Package Audit 与 AI Authoring 共用 Compiler v2.1.0 Development Build/VerifyDevelopment request builder 和 Worker；不复制 Linker、不静默回退 v2.0.2。
- 显式处理无 Assurance、零根依赖、未链接、未构建、已构建但 NOT_ADMITTED 等不同状态。
- 保留浏览器、Native IDE、Worker/WASM 和 Compiler exact-head 回归；不得把 synthetic fixture PASS 当成真实 MAS/Owner/Runtime qualification。

## 3. 依赖与启动条件

- 依赖 SR-023 的 CA-SL 作者规则、SR-013 的 Compiler 接口、SR-025 的 MAS Owner Development Interface Package 发布和 SR-024 的 Host Context Development fixture 发布；Compiler Development v1alpha1 冻结契约不可由 Studio 修改。
- 目标仓实现前必须刷新 main、PR #272/#276，先将请求构造器与 Worker 变更 rebase/reapply 到当前基线，再执行完整 exact-head CI。
- 当前 Example Contract roots 为 `mas: urn:openamsm:mas:tool-contracts` 和 `ca-context: urn:connectionagent:ca:host-context`；Studio lock 当前分别记录为 `tool-catalog` 与 `schema-bundle`。Compiler v2.1.0 只接受正式 Interface Package snapshots。MAS Owner Publisher 由 SR-025 负责，Host Context Development fixture 发布由 SR-024 负责；两者按 F09 §4.5 生成符合冻结 `interface-package.schema.json` 的 `package.json`，固定各自 Package ID、首版 `1.0.0` 及 publisher；复制的文件保持源字节，生成的 CapabilityCatalog 按 SR-025 验证。Host 的 `source.sourceStatus=DEVELOPMENT_FIXTURE` 只记在 Studio `skillc.lock/v0.1` 的 `source` provenance，不添加到正式 `package.json`。当前 Studio main `5b666c0` 的 #267 导入代码 `experiments/ide-host/vscode/src/dependency-integration.mjs::acquireInterfaceZip` 只保存 `type=interface-zip`、`upload`、ZIP `contentDigest`、`packageId`、`version`、`publisher`，尚未写入 `sourceStatus`；`project-configuration.mjs` 会原样持久化 `source` 对象，但没有生成该字段的逻辑。因此该能力仍是 SR-016 / Studio #269 的待实施项。导入流程必须显式写入 `source.sourceStatus=DEVELOPMENT_FIXTURE`，不得从 Package ID 或 publisher 推断；源 Revision/Git blob 由 SR-024 固定并在 Publisher 证据中复核，不要求重复写入当前项目锁。Studio 不得合成/转换包。
- `ca-client` v1.1.0 Interface Package 是 IntelliSense-only 依赖，不是 MAS/Host Contract root。其真实 ZIP 需要通过显式声明 `ca-client` 的 synthetic Skill 独立验收。
- Compiler v2.1.0 的 BuildRequest/Lock 要求非空 snapshots/roots/packages。Assurance Skill 没有 Contract roots 时，Studio 不调用 Compiler、不生成 Artifact、不回退、不伪造 NOT_ADMITTED。若需零依赖确定性 Artifact，必须另行版本化 Compiler 契约。
- 拟定验收需评审确认后进入 READY；未达到 READY 不提供 DeepSeek Harness 执行提示词。

## 4. 验收

- MIG-016-01：记录逐文件来源 SHA、目标章节、归档或替换决定和失效链接检查，保留指向中央设计的入口。
- AC-016-02：Studio `skillc.lock/v0.1` 保存精确原始快照并在 reload/build 前复核；Compiler Lock 只由 BuildRequest 派生，不创建第二个持久项目锁。
- AC-016-03：BuildRequest 只包含当前 Skill Contract roots 与传递闭包；未被引用的项目依赖不进入 roots；声明为 `tool-catalog` / `schema-bundle` 的 root 明确 fail-closed。
- AC-016-04：无 Assurance 与 Assurance 零根依赖分别处理；零根不调用 Compiler、不产 Artifact、不显示 `NOT_ADMITTED`，且无 v2.0.2 fallback。
- AC-016-05：Package Audit 和 AI Authoring 使用同一 BuildRequest/Worker/VerifyDevelopment；候选或 lock generation 变化使旧结果失效；Apply/Undo 恢复精确原生 Buffer。
- AC-016-06：真实 `ca-client-tools_interface_1.1.0.zip` 作为显式 `ca-client` synthetic Contract root，通过官方 Compiler v2.1.0 Build + VerifyDevelopment，Node/WASM/Chromium 结果一致；不得冒充 MAS Example Qualification。
- AC-016-07：当前 MAS Example 的 `mas` 与 `ca-context` Interface Package 分别满足 SR-025 / SR-024；SR-015 是 F03.05 设计依据，不是 Owner Publisher 代码任务；`package.json` 严格符合 Compiler v2.1.0 schema，导出身份来自源契约，公开 Schema/Callable/Evidence 保持源字节；由 SR-025 确定性生成的 CapabilityCatalog 按成员集合及 Publisher 输出字节核对。Host 的 `source.sourceStatus=DEVELOPMENT_FIXTURE` 必须由导入流程显式写入 Studio `skillc.lock/v0.1` 并在关闭/重开工作区后保持；不得扩展正式 `package.json` schema。当前 #267 main 尚未写入该字段，未完成前本 AC 不得 PASS。源 Revision/Git blob 分别由 SR-025 / SR-024 的固定输入与 Publisher 验收负责，不要求项目锁重复保存。两个 package.json.version 及其对应 snapshot key 均须为 `1.0.0`，按各自 packageId 解析；源版本 `v1alpha4` / `v1` 不得直接进入 BuildRequest。不得公开 Runtime-only 私有绑定或推导授权。
- AC-016-08：刷新后的 exact HEAD 完成 PR Verify、Native Windows、IDE Host、Theia Browser-Only、Theia Browser Host、Pages Chromium；历史旧 HEAD PASS 不满足门禁。
- AC-016-09：状态/诊断区分 Source、Interface Link、Artifact、Host Admission Requirement 与 Runtime Execution Requirement；Build 成功不得表示执行资格。
- AC-016-10：Studio 导入 SR-024 生成的 Host Context ZIP 后，`source.sourceStatus=DEVELOPMENT_FIXTURE` 随 `skillc.lock/v0.1` 持久化并在 reload 后保留；该字段不进入 `package.json`，不创建第二份项目 Lock。BuildRequest 仍从 Contract roots 和精确快照派生 Compiler lock；成功 Build + VerifyDevelopment 只能报告 `VALIDATED / LINKED / BUILT / NOT_ADMITTED`。
