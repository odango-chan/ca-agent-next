## 1. 目标

实现 Python Agent 对外部已发布 Skill 包的消费端导入。支持无 Assurance Package（必须含 SKILL.md，可携带根目录 schemas/、scripts/、references/、assets/），以及由 Compiler 和 ca-skills 正式发布流程共同生成的 Runtime Artifact Bundle。

Agent 只导入和检查已发布产物；不编译作者源、不调用 Compiler、不导入作者源 Assurance 作为运行时能力、不实现 Skill Admission。导入器只产生经过验证的 Skill import candidate；Catalog generation、原子激活和在途 Invocation 固定代际由 SR-005 负责。

## 2. 实施范围

### 2.1 无 Assurance Package 路径

- 接收调用方已物化的单 Skill 包根目录；本 SR 不负责网络下载、Release 解析或压缩包解包。
- 按 [Agent Skills Specification](https://agentskills.io/specification) 解析必需的 `SKILL.md` YAML Front Matter；CA-SL v1alpha5 只定义 `assurance/` 作者源，不定义 SKILL.md Front Matter。
- 必需字段：`name`、`description`；`name` 为 1～64 字符、仅小写字母/数字/连字符、不得以连字符开头或结尾、不得包含连续连字符，且必须与包根目录名一致；`description` 为 1～1024 字符的非空字符串。
- 可选字段：`license`（字符串）、`compatibility`（1～500 字符）、`metadata`（字符串键到字符串值的映射）、`allowed-tools`（空格分隔字符串，实验性）。未知顶层字段按 Next 严格消费策略拒绝。
- `allowed-tools` 仅作为源文档元数据保留；不得把它解释为 Provider/Callable 授权或 Capability Grant。实际执行权限只来自受支持的 Assurance Artifact 与既有 Owner/Provider 契约。
- 允许 `schemas/`、`scripts/`、`references/`、`assets/` 根目录共享资源；导入检查 Package 相对路径、Schema 文件、`scripts/manifest.yaml`、Script 文件 / 顶层 entrypoint 和 I/O Schema 引用；只做静态结构检查，不执行脚本、不把脚本加入业务 ToolCatalog。正文 Markdown 保持原文。
- Host 为当前 Run 提供 F05 §2.1 定义的 `host.skill-resource.read`；若 Script Registry 非空，则提供 `host.skill-script.execute`，所有登记 transform / predicate Script 均可由 LLM 调用并与 Assurance 共用同一 Runner。
- 不存在 Assurance Runtime Artifact 时，产出仅供 LLM-guided 使用的 import candidate。
- 不调用 Compiler，不创建 Procedure，不授予任何 Callable Scope。

### 2.2 已发布 Assurance Artifact 路径

仅在 ca-skills 正式发布 **CA-SL 1.6.0** Capability-first 作者规范及真实 Skill 示例、Compiler #61 / SR-013 / SR-029 对齐 1.6.0 的 Runtime Artifact API 与 Capability Binding、且 ca-skills / SR-027 发布与该 API 匹配的正式 Bundle 后启用：

- `SKILL.md` 与 Compiler Runtime Artifact 必须由同一个正式 Bundle 契约关联。
- Artifact 的 `apiVersion`、`languageTarget`、Manifest、文件清单、Schema/when 元数据均以 Compiler 正式 Release 的机器契约为准；Next 不自造字段、文件名或 API 版本。
- `languageTarget` 必须与 ca-skills / Compiler **正式冻结的 CA-SL 1.6.0 机器标识**完全一致；当前标识仍未发布，禁止凭文本自行假定或接受 `connectionagent.io/v1alpha5` 作为目标版本。
- 导入时只做消费端基本结构、必需文件、相对路径、引用、类型数据可加载性及本地依赖解析；不重做 CA-SL 静态检查、Procedure Graph、Linking 或 Compiler Verify。
- 解析成功后返回包含 SKILL.md 内容、受支持 Artifact 引用和已解析依赖身份的 import candidate；Catalog 是否激活由 SR-005 决定。

### 2.3 失败语义

- 包根目录、SKILL.md、Front Matter 或路径不合法：明确拒绝。
- 存在 Assurance 作者源但没有受支持的已发布 Runtime Artifact：明确拒绝。
- 存在 Artifact 但 API/语言版本不受支持（包括全部历史 v1alpha5 / Development v1alpha1 / v1alpha6 候选）、Manifest/必需文件/引用/类型数据/依赖无效：明确拒绝，不转换旧结构。
- Assurance 导入失败不得降级为无 Assurance Package；不得把损坏或不支持的 Artifact 当成普通指导包。
- 失败不得改变 SR-005 当前活动 Catalog generation；该原子性由 SR-005 验收。

## 3. 非目标

- 不调用 Compiler Check/Build/Inspect/Verify，不启动 Compiler 子进程，不在 Agent 中复制 Compiler。
- 不导入 `assurance/contract.yaml`、`procedure.yaml`、`predicates.yaml` 作者源作为运行时 Artifact。
- 不实现 SkillCatalog generation、原子切换、Invocation generation pinning（SR-005）。
- 不实现 when 候选选择、语义消歧或 Continuation（SR-006）。
- 不实现 Runtime Action Boundary、Procedure 执行或模式执行器（SR-007）。
- 不实现 ca-skills CI、Bundle 组装、Compiler Release 或自动发布（SR-027 / F08）。
- 不增加 Skill Admission、Owner Trust、签名、Trust Registry、生产授权、额外包完整性体系或新的 SHA-256。
- Agent 不解析 1.6.0 作者源语法；只消费 Compiler 对 1.6.0 Capability-first 生成的正式 Binding。**不支持任何旧版作者源、历史运行包、旧 Manifest、旧 Runtime Artifact、兼容别名、fallback、版本协商或自动迁移**，也不建立兼容层。历史 v1alpha5 保留只读审计，不是新 Agent 合法输入。

### 4.4 版本与依赖解析规则

1. **目标只消费 CA-SL 1.6.0 的编译产物**：Contract/Procedure 对外仅使用 Capability ID，Skill-facing Capability 与公开 Callable 一对一；Compiler 按显式依赖解析唯一 Binding。历史 v1alpha5 的 `tool: alias::CALLABLE_ID` 只在冻结规范及旧发布物中保留；Importer 不增加旧版作者语法兼容。
2. 对 Compiler/ca-skills 正式发布的 **1.6.0 Runtime Artifact**，Manifest 必须提供 Compiler 确认的唯一 Capability→Callable Binding、准确依赖身份、kind、Effect、Schema 引用及受控 Callable Scope；字段名、路径和机器标识须由 SR-029 与 Compiler #61 / SR-013 联合冻结。Importer 不重新解析作者源，不从 Provider backend Catalog 推断或扩权，也不复用 v1alpha5 Artifact 字段。
3. Provider Interface Package 与 Owner Contract Package 是两类不同依赖。Provider Interface 快照按 `provider.yaml.interfacePackagePath` / `interfaceSnapshotDigest` 固定；Owner Contract publication 按 Runtime Bindings sidecar 的 stable ID、version、publicationDigest、manifestDigest 固定。已安装 Owner publication 必须与 sidecar identity 一致。Artifact 到这两类依赖的引用字段由新版 Compiler Manifest 正式契约确定。
4. 不把 Owner ToolCatalog 误作 Provider Interface Package；不把 Provider 私有 `backendOperationId` 当作 Skill-facing Callable；不在导入时启动 Provider 或调用动态 Catalog 来扩大依赖。
5. 历史冻结 Artifact API v1alpha5 的 dependency closure 不含 dependency version / snapshotDigest，且该 API 不作为本 SR 的 Assurance 输入；Development v1alpha1 Lock 也因 NOT_ADMITTED 不得作为运行时输入。新版 Runtime Artifact 是否携带额外依赖身份字段，按 Compiler #61 最终契约，不自行推断。
6. **Issue #40 / SR-029 的 Capability-first 1.6.0 是唯一下一正式语言目标**，不是 v1alpha6；当前尚未发布，故本 SR Assurance 部分继续 BLOCKED。历史 v1alpha5 冻结语义与字节不改；无旧格式兼容、静默重解释或自动迁移。

只有 Contract.contexts 可通过显式 alias 使用 Host Context 的导出。Importer 按正式 Manifest 和安装快照核对 Package identity、alias、Schema export 及全部传递 $ref，将精确 Schema 闭包连同来源保存到 candidate。缺 alias、缺 export、零 Schema 导出、断裂或歧义 $ref、伪造 Callable 均拒绝整份 candidate。Schema-only 不产生 Capability Binding、Action Scope 或 Tool Effect。requestSchema 根必须属于本 Skill。

有 when 时在返回 candidate 前构造一次 Program 和类型环境；交由 SR-005 连同精确依赖闭包保存。
