## 1. 目标

实现 Agent 对 SKILL.md-only 包和外部已发布 Assurance Artifact 包的消费端导入，不在 Agent 内编译或发布 Skill。

## 2. 实施范围

- 导入 SKILL.md-only Skill 并读取其 Agent-facing 指导。
- 导入包含有效已发布 Assurance Artifact 的 Skill 包。
- 检查基本格式、Manifest、必需文件、路径、引用、类型数据和本地 Tool/Capability 依赖。
- 无效或不完整发布包明确失败，不降级为 SKILL.md-only。

## 3. 非目标

- 不调用 Compiler Check/Build/Inspect/Verify。
- 不导入 Assurance 作者源 YAML 作为运行时 Artifact。
- 不增加 Skill Admission、Owner Trust 或生产级授权。

## 4. 依赖与前置条件

SR-002；外部依赖为 ca-skills 作者格式与 ca-skill-compiler 发布契约。涉及新版 when Bundle 的验收，使用 [SR-013](SR-013-Compiler已检查when与发布产物.md) 的 AC-013-05 所记录的正式发布资产与 SHA。现有冻结包和 SKILL.md-only 的可独立检查仍按本 SR 既有门槛执行。

进入 READY 前必须确认所有前置 SR 已 VERIFIED，或在 SR 中明确记录并批准并行实施理由；外部依赖必须有可核对的版本、接口和可用证据。

## 5. 验收条件

1. SKILL.md-only 包无需 Compiler 即可导入，且只能 LLM-guided。
2. 有效发布 Artifact 包可以导入并解析本地依赖。
3. 缺文件、格式不支持、路径越界、类型数据错误和未解析依赖均明确失败。
4. Agent 代码和进程不调用 Compiler。

另验证 EX-11 模式派生，以及 EX-12 中 Next 的发布消费边界。LLM 编辑与外部发布流程使用外部证据，Next 验收记录仍须验证导入结果。

验收时必须引用演示验收基线中的对应 Acceptance ID，并记录真实执行命令、测试结果、Example 和覆盖范围。未执行项保持 NOT_RUN。

### 实施位置与复验入口

以下路径为本 SR 的目标交付物。在 ca-agent-next 仓根运行，测试通过公开入口调用受测组件。目标位置为 `src/ca_agent_next/skills/importer.py`、`examples/echo/published-skills/`。先导入仅含 SKILL.md 的包；再用固定的 ca-skills 发布样本验证有 Assurance 的路径。分别删必需文件、破坏引用、换成 Development Artifact；逐例要求导入失败、旧代际可读、Compiler 子进程数为 0。缺少可引用的发布样本时停止对应正例，不接受测试临时编造的成功包。

验收命令为 `python -m unittest discover -s tests -p test_importer.py -v`。必须发现并执行本节正反例；发现 0 个测试或跳过必需用例时，退出码 0 也不能计入 PASS。逐个 Acceptance ID 回填受测 SHA、命令、预期与实测值及日志位置。
