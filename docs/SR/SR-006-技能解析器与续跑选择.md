## 1. 目标

实现 Skill-first Resolver，保证新 Event 在模式选择和执行前绑定 Skill，continuation 精确恢复原 Run。

## 2. 实施范围

- 按规范顺序评估 when 候选。
- 单个显式候选直接选择；多个候选只在精确集合内消歧。
- 新 Event 先检查各候选声明的 Request Schema；校验不通过时诊断并排除。无显式候选时，从无 when 且符合资格的 Skill 中语义选择。
- when=false/error 的 Skill 排除；无候选时澄清或拒绝。
- continuation 优先恢复原 Run、Skill 和 generation，不重新选择。

## 3. 非目标

- 不增加 Event→Skill 表、Event→Mode 表或 Generic Agent 无绑定回退。
- 不把 when false/error 的 Skill 放回语义候选。

## 4. 依赖与前置条件

SR-005；使用正式 CA-SL 发布记录复核 M.3 与 SA-012 的语义和固定 SHA。

设计核对正式 CA-SL M.3/SA-012 和 F02 选择顺序。连接活动目录时消费 SR-005 的 generation 与候选集合；模块测试可输入固定 generation，比较候选集合、模型选择次数和 continuation 原 Run。系统组合使用实际 Catalog。 设计可按 SR 管理规范 §6.1 单独评审。

## 5. 验收条件

1. 一个 when=true 候选直接绑定。
2. 多个 when=true 候选只在精确集合内消歧并校验 Skill ID。
3. EX-10 包含同一无 when 的 Assurance Skill 在 Request Schema 匹配时可进入语义候选、失配时记录输入校验诊断并排除的对照；跳过失配 Skill 的求值。false/error 候选保持排除。
4. 无候选时明确澄清/拒绝，不启动无绑定 Agent。
5. continuation 恢复原 Run 和 generation，不重新选择 Skill。

验收时必须引用演示验收基线中的对应 Acceptance ID，并记录真实执行命令、测试结果、Example 和覆盖范围。未执行项保持 NOT_RUN。

### 实施位置与复验入口

以下路径为本 SR 的目标交付物。在 ca-agent-next 仓根运行，测试通过公开入口调用受测组件。目标位置为 `src/ca_agent_next/skills/resolver.py`。固定同一规范化 Event，分别给出真、假、求值错误及无 when 候选。另用同一无 when 包做 Request Schema 匹配/失配对照。多真仅在精确候选集消歧；候选外 ID 被拒绝。重复 Event 或已匹配的 Continuation 均不得增加选技次数。

验收命令为 `python -m unittest discover -s tests -p test_resolver.py -v`。必须发现并执行本节正反例；发现 0 个测试或跳过必需用例时，退出码 0 也不能计入 PASS。逐个 Acceptance ID 回填受测 SHA、命令、预期与实测值及日志位置。
