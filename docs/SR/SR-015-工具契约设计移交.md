## 5. 核心设计决议

1. Tool 是 Plugin 导出的 Callable Operation，不是独立进程、Manager 或 Registry。
2. Provider Tool Interface Package 拥有 Provider 自身导出的 Callable ID、Capability membership、输入/输出 Schema 和 Effect；ca-client-tools v1.2.0 当前只导出 11 个 READ Tools。
3. Owner Contract Package 独立拥有 Owner ToolCatalog Callable、IO Schema、CapabilityContracts membership、Evidence Guarantees、Owner Outcomes、Receipt、Commit Proof 和 Reconcile。CA-SL v1alpha5 MAS Skill 的 `dependencies.mas` / `mas::` 引用该 Owner snapshot；它不是 ca-client-tools Interface ZIP。
4. Provider Runtime Bindings 是私有执行 sidecar，映射 runtime/owner callable 到 backendOperationId，并声明 HostInvocation、privateArguments、observation/receipt 定位；它不授权 Skill，也不重定义 Owner。Provider Backend Binding Catalog v2 只在 Provider 内部执行，不由 Host 解析或复制。
5. ca-client-tools v1.2.0 的 Provider v2 由唯一 Plugin Manager 内部 ProviderV2 Tools Extension Driver 适配；Native Plugin 继续使用 Plugin IPC v1alpha1。
6. Runtime 在 dispatch 前检查当前 Skill 的精确 operation/observation export Scope、Schema、Effect 和 Artifact 来源；冻结 v1alpha5 Capability ID 是 Build-time 约束而非运行时 Artifact 字段；sidecar Reconcile binding 从普通 Skill dispatch 排除。Plugin Manager 不做授权。
7. Provider/HTTP/IPC 成功不等于 COMMITTED；只有 Owner Receipt 与 Commit Proof 精确绑定原 Invocation 才能产生 COMMITTED。UNKNOWN 保持 UNKNOWN，并按原 Invocation Reconcile，不重发 mutation；MAS.RECONCILE 的普通 Skill Action 必须被 Runtime 拒绝，只有 Coordinator 内部入口可调用。
8. Codec 不单独建 Plugin/Manager；只在正式发布 Callable/Runtime Binding 后作为现有 Tools Extension 的 Operation 使用。
