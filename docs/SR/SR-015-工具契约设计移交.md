## 1. 目标仓与基线

`odango-chan/ca-client-tools`，`main`，当前审计基线 `7bcb2614aa3615d8358df31eecefd0909e894e40`。MAS Owner v1alpha4 契约源位于 `contracts/owner/openamsm-mas/v1alpha4`，source tag `v1.2.0` 对应 Revision `fc44c3a745c68443fcfb12054c7eadf0ed7cc3f7`。其 `manifest.json` / ToolCatalog 是 Owner 权威来源，但不是 Compiler v2.1.0 可直接导入的正式 Interface Package。

已发布 `ca-client-tools_interface_1.1.0.zip` 是 Provider v2 的 READ Interface Package，不是 MAS Owner Contract root。现有 `contracts/mas-owner-candidate/v0.3.0` 发布资产 `openamsm-mas-compiler-contract-v0.3.0.zip` 也不是正式 Owner 包：其 Package ID 为 `wtlab:packages:openamsm:mas-compiler-contract`、owner 为 `wtlab`，且明确 `compilerLinkable=false`、`deployable=false`、`NOT_QUALIFIED`。两者均不得替代 `urn:openamsm:mas:tool-contracts`。

## 2. 实施范围

- 保留 Provider v2、现有 `ca-client` READ Interface Package 和 Runtime binding 的职责；不改变既有 `cmd/ca-client-tools-release generate` / `internal/interfacepkg` 的 Provider `provider-bindings/v2` 源语义。
- 新增独立 MAS Owner Publisher：新增 `internal/ownerinterfacepkg` 与 `cmd/ca-client-tools-owner-interface-release`，提供 `generate` / `verify` 两个子命令。固定命令为 `go run ./cmd/ca-client-tools-owner-interface-release generate --source contracts/owner/openamsm-mas/v1alpha4 --out dist/ca-client-tools_mas-owner_interface_v1alpha4.zip` 和 `go run ./cmd/ca-client-tools-owner-interface-release verify --package dist/ca-client-tools_mas-owner_interface_v1alpha4.zip`。输入固定为 `contracts/owner/openamsm-mas/v1alpha4`；不得从 `contracts/mas-owner-candidate` 或 Provider bindings 推导 Owner Contract。
- 正式包身份固定为 `packageId=urn:openamsm:mas:tool-contracts`、`version=v1alpha4`、`publisher=openamsm.smf.mas`、`languageTarget=connectionagent.io/v1alpha5`。Owner source Revision 为 `fc44c3a745c68443fcfb12054c7eadf0ed7cc3f7`，source build identity 为 `sha256:ac834080f31ff0fa91b9eb846fa47c889a94837fc1f37ec2034190e4e83085c0`。
- 正式 `package.json` 严格遵循 Compiler v2.1.0 `contracts/development/v1alpha1/interface-package.schema.json`。它是新生成的 Interface Package envelope；原 `manifest.json` 是 `connectionagent.io/toolcatalog/v1alpha4` Owner source manifest，不可直接改名或冒充 `package.json`。
- Publisher 必须先校验 Owner source `manifest.json` 中所有 artifact digest，再解析 ToolCatalog、CapabilityContracts、Evidence Guarantees 与 Schema 引用。当前 Owner manifest 记录 25 个操作，其中 7 个 `notPublished`；只允许导出其余 **18 个公开 Callable ID**。每个公开 Callable ID 对应一个 `CallableCatalog` export，路径为原始 `tool-catalog.yaml`。源文件保持原始字节；Compiler Development Linker 只索引 `package.json.exports` 明确声明的 ID。
- Owner `capability-contracts.yaml` 是 `connectionagent.io/capability-contracts/v1alpha4`，使用 `spec.capabilities[].callables[]`，不能直接作为 Compiler Development `CapabilityCatalog`。Publisher 必须确定性生成 `capability-catalog.yaml`：根字段仅为 `capabilities`，每项为 `{id, members:[{callableId}]}`；成员仅保留 18 个公开 Callable 对应的成员；只导出至少包含一个公开成员的 Capability ID。不得写入 owner/effect/scopePolicyRef；该投影仅用于静态成员链接，不是 Grant、Scope Policy 或 Host Trust。原始 CapabilityContracts 仍是 Owner 权威来源。
- `EvidenceDescriptor` exports 从原始 `evidence-guarantees.yaml` 的顶层 fact-ID mapping 生成；只导出公开 Callable 实际引用的 fact ID。该文件按 Compiler v2.1.0 EvidenceDescriptor parser 的逻辑格式直接校验。
- `Schema` exports 覆盖 18 个公开 Callable 的 input/query/output/receipt/commit-proof 等字段所需的完整 `$ref` 闭包；每个 export ID 精确等于原始 Schema `$id`。只纳入公开闭包，不纳入无关或部署私有 Schema。
- 正式包文件包括原始 `tool-catalog.yaml`、生成的 `capability-catalog.yaml`、原始 `evidence-guarantees.yaml` 和公开 Schema 闭包；不包含 `deployment-binding.yaml`、部署私有配置、Runtime-only Provider bindings 或 Owner source `manifest.json`。源 `manifest.json` 只用于生成前验证，source Revision/buildIdentity 写入发布 provenance。
- 新增的 `capability-catalog.yaml` 是唯一的语义投影文件，必须确定性生成；其他公开 ToolCatalog、EvidenceDescriptor、Schema 文件保持原始字节。正式 `package.json.files[]` 对包内实际文件计算 SHA-256。
- 发布资产名固定为 `ca-client-tools_mas-owner_interface_v1alpha4.zip`，由 `release.yml` 生成、验证、纳入 `SHA256SUMS` 并执行发布后下载校验。当前 latest release tag 为 `v1.2.0`；若实施时无新版本，下一次 Publisher 代码发布使用 `v1.2.1`，Interface Package 自身版本仍为 `v1alpha4`。不得回写或改造既有 v1.2.0 发布资产。

## 3. 依赖与启动条件

- 依赖 Compiler v2.1.0 冻结 Interface Package schema、Development CapabilityCatalog / EvidenceDescriptor parser、F09 §4.5 和 Studio #269 的 BuildRequest/Import 集成。
- Owner source Revision 固定为上述 v1.2.0 tag 内容；新增 Publisher 代码可在下一 patch release 发布，但必须证明 Owner v1alpha4 源文件相对原 Revision 未变化。
- 正式包不包含 Owner Trust、Deployment Grant、Provider binding 或 Runtime Admission。Compiler Development BuildRequest 不接受 `trustedBuildContext`；静态 CapabilityCatalog 不替代可信 CapabilityContracts、Scope Policy 或 Host Admission。
- 评审确认验收和发布方式后进入 READY；未达到 READY 不发布 Harness 执行提示词。
