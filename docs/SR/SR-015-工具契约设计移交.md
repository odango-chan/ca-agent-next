## 1. 目标仓与基线

目标仓：`odango-chan/ca-client-tools`，`main`，当前审计基线 `7bcb2614aa3615d8358df31eecefd0909e894e40`。

MAS Owner v1alpha4 契约源位于 `contracts/owner/openamsm-mas/v1alpha4`。source tag `v1.2.0` 对应 Revision `fc44c3a745c68443fcfb12054c7eadf0ed7cc3f7`，Owner source build identity 为 `sha256:ac834080f31ff0fa91b9eb846fa47c889a94837fc1f37ec2034190e4e83085c0`。已核对当前 main 与 v1.2.0 tag：该目录 59 个文件（manifest + 58 artifacts）逐个 blob 相同。

已发布 `ca-client-tools_interface_1.1.0.zip` 是 Provider v2 的 READ Interface Package，不是 MAS Owner Contract root。现有 `contracts/mas-owner-candidate/v0.3.0` 发布资产 `openamsm-mas-compiler-contract-v0.3.0.zip` 也不是正式 Owner 包：其 Package ID 为 `wtlab:packages:openamsm:mas-compiler-contract`、owner 为 `wtlab`，且明确 `compilerLinkable=false`、`deployable=false`、`NOT_QUALIFIED`。两者均不得替代 `urn:openamsm:mas:tool-contracts`。

## 2. 实施范围

- 保留 Provider v2、现有 `ca-client` READ Interface Package 和 Runtime binding 的职责；不改变既有 `cmd/ca-client-tools-release generate` / `internal/interfacepkg` 的 Provider `provider-bindings/v2` 源语义。
- 新增独立 MAS Owner Publisher：新增 `internal/ownerinterfacepkg` 与 `cmd/ca-client-tools-owner-interface-release`，提供 `generate` / `verify` 两个子命令。建议命令：
  ```bash
  go run ./cmd/ca-client-tools-owner-interface-release generate --source contracts/owner/openamsm-mas/v1alpha4 --out dist/ca-client-tools_mas-owner_interface_v1alpha4.zip
  go run ./cmd/ca-client-tools-owner-interface-release verify --package dist/ca-client-tools_mas-owner_interface_v1alpha4.zip
  ```
  输入固定为 `contracts/owner/openamsm-mas/v1alpha4`；不得从 `contracts/mas-owner-candidate` 或 Provider bindings 推导 Owner Contract。
- Contract root Package ID 固定为 `urn:openamsm:mas:tool-contracts`；Publisher 固定为 `openamsm.smf.mas`；Language Target 固定为 `connectionagent.io/v1alpha5`。Compiler v2.1.0 要求 Interface Package version 为 exact SemVer。建议 formal package version 为 `1.0.0-alpha.4`，原始 Owner source package version `v1alpha4` 通过 provenance 原样保留。**该映射尚待用户确认；未确认前本 SR 不得 READY。**
- 正式 `package.json` 严格遵循 Compiler v2.1.0 `contracts/development/v1alpha1/interface-package.schema.json`。原 `manifest.json` 是 `connectionagent.io/toolcatalog/v1alpha4` Owner source manifest，不可直接改名或冒充 `package.json`。Compiler v2.1.0 parser 在 `internal/compiler/development_request.go` 中要求 snapshot key version 是 SemVer，且 package.json.version 必须与 key 一致；`v1alpha4` 不能直接进入 BuildRequest。
- Publisher 必须先校验 Owner source `manifest.json` 中全部 **58 个 artifact digest**，再解析 ToolCatalog、CapabilityContracts、Evidence Guarantees 与 Schema 引用。Owner manifest 的 `operationCount=25`，`operations` 列出 25 个已发布 Callable；`notPublished` 是另外 7 个旧 Callable。正式包只导出 25 个公开 ID，不导出：
  - `SC.UPDATE_SM_CONTEXT`
  - `UPN.MODIFY_UP_SESSION_INTENT`
  - `SSM.SIGNAL_UE_AN_MODIFY`
  - `SSM.SIGNAL_UE_AN_RELEASE`
  - `PA.DELETE_SM_POLICY`
  - `SC.RELEASE_SM_CONTEXT`
  - `SE.EMIT_RELEASE_EVENT`
- `CallableCatalog` exports 精确为 25 项，逐个使用 `manifest.operations[].callable` 对应的 ToolCatalog `spec.contracts[].id`，路径为原始 `tool-catalog.yaml`。Compiler v2.1.0 parser 支持 `connectionagent.io/toolcatalog/v1alpha4`；每个 export ID 必须在 ToolCatalog 文件中精确解析一次。ToolCatalog 原始字节保持不变。
- Owner `capability-contracts.yaml` 是 `connectionagent.io/capability-contracts/v1alpha4`，使用 `spec.capabilities[].callables[]`，不能直接作为 Compiler Development `CapabilityCatalog`。当前源文件有 24 个 Capability ID、25 个 Callable 成员，成员集合精确等于 25 个公开 Callable。Publisher 必须确定性生成 `capability-catalog.yaml`：根字段仅为 `capabilities`，每项为 `{id, members:[{callableId}]}`；保持 24 个 Capability ID 和 25 个公开成员。不得写入 owner/effect/scopePolicyRef；该投影仅用于静态成员链接，不是 Grant、Scope Policy 或 Host Trust。
- `EvidenceDescriptor` exports 精确为 25 项，来自原始 `evidence-guarantees.yaml` 顶层 fact-ID mapping。当前 25 个 Descriptor 的 `authority` 均为 `openamsm.smf.mas`，25 个 Producer ID 与 25 个公开 Callable ID 精确相同，且不与 7 个 `notPublished` ID 重叠。Publisher 必须验证每个 Producer 的 `provides.path` 与 ToolCatalog 对应 Callable 的 Evidence guarantee path 精确匹配；不匹配时 fail-closed，不得重新暴露未发布 Callable。
- `Schema` exports 精确为 53 项，覆盖 25 个公开 Callable 的完整 input/output/receipt/commit-proof/reconcile `$ref` 闭包。源目录有 54 个 Schema 文件；唯一不在公开闭包内的是 `deployment-binding.schema.json`，必须排除。每个 Export ID 精确等于原始 Schema 的 `$id`。
- 正式 ZIP 的 56 个 payload 文件由 55 个原始文件（ToolCatalog、Evidence Guarantees、53 个 Schema）和唯一生成投影 `capability-catalog.yaml` 组成；加根 `package.json` 后共 57 个快照文件。共 **127 个 exports**（25 Callable + 24 Capability + 25 Evidence + 53 Schema）。当前 55 个原始 payload 合计 80,479 bytes；加上 package manifest 与 projection 后仍远低于 Compiler v2.1.0 的 16 MiB aggregate request limit。
- 正式包不包含 `capability-contracts.yaml`、`deployment-binding.yaml`、`deployment-binding.schema.json`、部署私有配置、Runtime-only Provider bindings 或 Owner source `manifest.json`。源 manifest 只用于生成前校验，source Revision/buildIdentity 写入独立 provenance sidecar。公开 ToolCatalog、EvidenceDescriptor、Schema 文件保持原始字节；`capability-catalog.yaml` 是唯一逻辑投影文件。正式 `package.json.files[]` 必须精确列出全部 56 个 payload 文件（不含 package.json），并计算实际包内 SHA-256。
- 新增 `ca-client-tools_mas-owner_interface_v1alpha4.provenance.json` Release sidecar，记录 formal package identity/version、Publisher release tag/revision/ZIP digest，以及 source repository、source Revision `fc44c3a...`、source path、sourceVersion `v1alpha4` 和 source buildIdentity。Sidecar 不进入 Interface Package ZIP 或 `files[]`，但必须纳入 Release `SHA256SUMS`，供 Studio importer 恢复 source provenance。
- 固定 ZIP asset：`ca-client-tools_mas-owner_interface_v1alpha4.zip`。若实施时 latest release 仍为 v1.2.0，下一次 Publisher 代码 release tag 为 v1.2.1；Publisher release tag、formal Interface Package SemVer 和 Owner source version 是三个不同标识，不得混用。
- 现有 `release.yml` 已有 Compiler v2.1.0 binary gate（SHA-256 `11da056ae5fff416de1fcfacd0a3535a4392a2b2d7349d928f41e1928398b568`）和 `CA_SKILLC` 测试入口。扩展该 gate 覆盖 Owner Publisher：生成包后运行 Publisher verify，再用官方 Compiler 对 synthetic `mas` root 正例执行 BuildDevelopment + VerifyDevelopment；负例引用 `SC.UPDATE_SM_CONTEXT` 必须得到 export missing。Release `SHA256SUMS`、Release assets 和发布后下载复验必须覆盖 ZIP 与 provenance sidecar。

## 3. 依赖与启动条件

- 依赖 Compiler v2.1.0 冻结 Interface Package schema、ToolCatalog v1alpha4 parser、Development CapabilityCatalog / EvidenceDescriptor parser、F09 §4.5 和 Studio #269 的 BuildRequest/Import 集成。
- Owner source Revision 固定为 v1.2.0 tag 的 `fc44c3a745c68443fcfb12054c7eadf0ed7cc3f7`；当前 main 的源目录 59/59 blobs 相同。新增 Publisher 代码可在下一 patch release 发布，但必须继续证明 source manifest 所有 artifact digest 有效。
- 正式包不包含 Owner Trust、Deployment Grant、Provider binding 或 Runtime Admission。Compiler Development BuildRequest 不接受 `trustedBuildContext`；静态 CapabilityCatalog 不替代可信 CapabilityContracts、Scope Policy 或 Host Admission。
- **阻塞决策：** 用户确认 formal package SemVer `1.0.0-alpha.4` 与 sourceVersion `v1alpha4` 分离。若拒绝该映射并要求 package.version 原样为 `v1alpha4`，则需要另行升级 Compiler 契约/实现；本 SR 不得按 v2.1.0 实施。
- 评审确认验收和版本语义后进入 READY；未达到 READY 不创建目标仓实施任务、不发布 Harness 执行提示词。

- MIG-015-01：记录逐文件来源 SHA、目标章节、归档或替换决定和失效链接检查，保留指向中央设计的入口。
- MIG-015-02：验证第 2 节的兼容与行为要求，回填命令、受测 SHA、结果和范围；适用的既有 EX/OM 对照审计。
- AC-015-03：formal `package.json` 通过 Compiler v2.1.0 Interface Package schema；Package ID、publisher、languageTarget 固定；version 是经用户确认的 exact SemVer，sourceVersion `v1alpha4` 保留在 provenance sidecar。
- AC-015-04：Callable exports 精确 25 项；7 个 `notPublished` ID 不可被 Compiler resolve；CapabilityCatalog 精确 24 IDs / 25 members；EvidenceDescriptor 精确 25 facts，authority 等于 publisher，Producer 集合精确等于公开 Callable 集合且 `provides.path` 精确匹配；Schema exports 精确 53 项，$ref 闭包无缺失。
- AC-015-05：ZIP 精确包含 56 个 payload 文件及根 `package.json`；`files[]` 精确覆盖 payload，所有 SHA-256 与实际字节一致；不得包含 deployment/runtime 私有 binding、CapabilityContracts source、Owner source manifest 或 Owner Trust。
- AC-015-06：`go test ./... -count=1` 覆盖 Publisher 正负路径；generate/verify 对固定 source Revision 产生逐字节相同 ZIP；损坏 source manifest、遗漏/多余文件、错误 digest、重复 export ID、误导出 notPublished callable、错误 Capability projection、Evidence Producer 路径不匹配、缺失 Schema 和 tampered ZIP 均失败。
- AC-015-07：官方 Compiler v2.1.0 binary（固定 SHA-256）对真实 Owner ZIP 的 synthetic `mas` root 正例执行 `skillc build-development --request request.json --out out --json` 和 `skillc verify-development --request request.json --result result.json --json`；`SC.UPDATE_SM_CONTEXT` 负例必须 export missing。不得冒充真实 MAS E2E 或 Production Qualification。
- AC-015-08：`release.yml` 生成 ZIP 与 provenance sidecar，纳入 `SHA256SUMS` 和 Release assets；发布后重新下载，校验 SHA256SUMS、Package identity、source Revision/buildIdentity 和 ZIP 内容。
- AC-015-09：Studio #269 通过官方 Release 导入同一 ZIP + sidecar，lock 保存 Package SemVer、sourceVersion、sourceRevision、sourceBuildIdentity、Publisher release revision/tag、asset digest；Node/WASM/Chromium 对同一 snapshots 结果一致。
- AC-015-10：版本映射获得用户明确确认；未确认时保持 DRAFT，不创建实施 Issue、不执行。
