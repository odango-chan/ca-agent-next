迁移 ca-agent 当前 Go Native Agent Host 的任务机、Artifact Store 和 Host Contract 设计，明确其与 Next Python Host 的关系。该仓是后续晋级目标参考，不是 Next 当前实现。

## 3. 设计与实现审计

- Host 拥有 Intent、ProductTask、AgentInstance、Model Interaction、Skill Context、Host trajectory 和 Artifact Store。
- Agent-facing governed Tool path 通过 standard MCP client → tool-mcp-gw → RuntimeHost.v1 → ca-runtime。
- ProductTask 与 Runtime Run 分离，一个 Task 可关联零个或多个 Run。
- Tool catalog 在 AgentInstance/client generation 初始化时读取并缓存；Goal 到达不授予 Tool 权限。
- Host Artifact Store 负责 reference issuance/resolution、访问控制、quota、lifecycle 和 publication。
- Planning V2、GOAL_PLANNING、Context Loader、revisioned PlanningContext、ModelVisibleContext、ContextOffer/NEED_CONTEXT 在 README 中标为 vNext，不得写成已实现。
- 私有 Lab bridge 和 legacy direct RuntimeHost executor 已退役，不应重新引入。

## 4. 与 Next 的关系

Next 目标仍是 Python Host、唯一 Plugin Manager、Skill-first 和统一 Runtime Action Boundary。不得把 ProductTask v2、tool-mcp-gw、Planning V2 或 Go Artifact Store 直接复制为 Next 组件。是否晋级 Go Host 必须另立 IR/SR 决策。
