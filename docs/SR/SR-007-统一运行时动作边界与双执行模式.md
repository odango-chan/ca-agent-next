## 1. 目标

让 Deterministic Procedure Engine 与 LLM Model Loop 共用同一 Runtime Action Boundary，统一执行范围、输入、Effect、Artifact 和 Owner outcome 解释。

## 2. 实施范围

- 统一 Runtime Action Request。
- 校验当前 Skill 声明的 Callable Scope、Callable ID、输入 Schema、Effect、Artifact 引用和 Run 状态。
- 区分 READ Observation 与 MUTATION Owner Evidence。
- 按 Owner Receipt/Commit Proof 解释结果，UNKNOWN 保持 UNKNOWN。
- 支持 Wait、Resume、Reconcile 的正确 Run 关联。

## 3. 非目标

- 不允许 LLM 直接调用 Plugin 或扩大 Callable Scope。
- 不把 HTTP 200、IPC 成功或 Delivery 成功解释为 Owner Commit。
- 不复制 Owner 状态映射或业务枚举。

## 4. 依赖与前置条件

SR-003、SR-004、SR-006。

进入 READY 前必须确认所有前置 SR 已 VERIFIED，或在 SR 中明确记录并批准并行实施理由；外部依赖必须有可核对的版本、接口和可用证据。

## 5. 验收条件

1. 两种执行模式使用相同 Action Request 和授权路径。
2. 越权 Callable、Schema 不匹配、Effect 不符和错误 Artifact 引用均被拒绝。
3. READ 结果保留 Observation 来源。
4. MUTATION 按 Owner Receipt/Commit Proof 解释；UNKNOWN 不得变成 COMMITTED。
5. 重复或过期 continuation 不推进错误 Run 或重复 mutation。

验收时必须引用演示验收基线中的对应 Acceptance ID，并记录真实执行命令、测试结果、Example 和覆盖范围。未执行项保持 NOT_RUN。
