## 1. 目标

让 Deterministic Procedure Engine 与 LLM Model Loop 共用同一 Runtime Action Boundary，统一执行范围、输入、Effect、Artifact 和 Owner outcome 解释。

## 2. 实施范围

- 统一 Runtime Action Request。
- 校验当前 Skill 声明的 Callable Scope、Callable ID、输入 Schema、Effect、Artifact 引用和 Run 状态。
- 区分 READ Observation 与 MUTATION Owner Evidence。
- 按 Owner Receipt/Commit Proof 解释结果，UNKNOWN 保持 UNKNOWN。
- 支持 Wait、Resume、Reconcile 的正确 Run 关联。

## 3. 非目标

- 不允许 LLM 直接调用 Plugin 或扩大 Callable Scope。
- 不把 HTTP 200、IPC 成功或 Delivery 成功解释为 Owner Commit。
- 不复制 Owner 状态映射或业务枚举。

## 5. 独立模块验收条件（正例、反例与证据）

| 模块 AC | 固定输入/操作 | 预期、诊断与隔离 |

| AC-007-02 | Callable ID、backendOperationId、URL 或未绑定 Capability 由模型输入；另测多重 Binding | 全部在 IPC 前拒绝，Provider/Owner dispatch 次数 0 |
| AC-007-03 | 正确 operation 与 observation Capability；将 MUTATION Capability 填入 observation | 正确 kind/Effect/Schema 通过；Observation 非 READ 或阶段不符拒绝，零 dispatch |
| AC-007-04 | 错 Schema、缺 Scope、错误 Owner/Provider 包身份与跨 Invocation ArtifactRef | 每一种均 fail-closed；不推断/扩张 Tool/Owner 授权 |
| AC-007-05 | 两模式分别输入 READ、Owner 已提交且 Receipt/Commit Proof 完整的 MUTATION，以及缺失 Proof、仅 HTTP 2xx/IPC/Delivery 成功、Owner UNKNOWN；逐例替换 Proof 的 originalInvocationId、Owner、deployment 或 Scope 中一项 | READ 记录 Observation。只有可信 Owner 对本次原始 Invocation、部署和 Scope 的有效提交证明产生 COMMITTED。每一错误 Proof 或传输成功负例均维持未证实状态（UNKNOWN，未决证据为 UNRESOLVED），Owner UNKNOWN 保留。逐例比较两模式 Outcome，并重放原请求，新增 mutation=0。 |
| AC-007-06 | 原 Mutation 精确 Reconcile 与 LLM 直接 MAS.RECONCILE | Coordinator 使用原 Invocation/Scope/Correlation；LLM 请求 INTERNAL_RECONCILE_ONLY 且 IPC=0 |
| AC-007-07 | 重复/迟到 continuation、错 generation、取消后重放；旧 v1alpha5 Artifact | 拒绝错误 Run，重复 mutation=0；旧 Artifact 不做兼容导入；Continuation 仅用协议身份和 correlation 查原 Run。Skill、Artifact、generation、Node/Wait 位置均取自原 Run；消息夹带冲突身份、错 correlation 或已结束 Run 则拒绝，合法重复按原结果幂等应答，迟到消息隔离。以上路径均零重选、零 CEL 重算，拒绝或重放时新增 mutation 为零。 |
