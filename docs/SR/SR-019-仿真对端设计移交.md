## 3. 架构边界

- 5GC reference simulator 负责独立模拟 World、NF 状态和对外 Owner API。
- Mock AMF SBI Test Peer 是协议对端/测试驱动器，负责发送 SBI 请求和 N1/N2 continuation，不拥有真实 SMF 会话状态。
- OpenAMSM SMF MAS Owner 是被测业务状态权威。
- CA Agent / Runtime 是另一个被测调用者，不得把 Mock AMF 的测试 PASS 当成 Agent PASS。
- 一进程一 World、Owner-local core 和 Service Fabric Network Observation 以原始 ADR 为准。

## 4. Mock AMF 测试场景

- Create：发送 CreateSMContext 请求，支持 multipart N1/N2，等待 OpenAMSM 返回和后续对端交互。
- Modify：通过 UpdateSMContext 发送 0xC9 PDU Session Modification Request，接收并验证 N1/N2 Modify response。
- UE-requested Release：通过 UpdateSMContext 发送 0xD1 Release Request，接收 N1 Release Command，回送 0xD4 Release Complete 和 N2 PDU_RES_REL_RSP，验证 Owner 最终清理。
- 对每次场景记录 SUPI、PSI、PTI、generation、Run/request identity、N1/N2 message type 和 Owner outcome。
- 受控 reset 只影响明确的隔离 World，不触碰共享实验室状态。
