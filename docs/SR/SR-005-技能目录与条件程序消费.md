## 1. 目标

实现 Core-owned 的进程内 SkillCatalog，导入时驻留 Skill 内容与已检查 when 程序，避免每个 Event 重读 Skill 文件或解析 CEL。

## 2. 实施范围

- 构建不可变 Catalog generation，保存 SKILL.md、候选元数据、Artifact 引用、已反序列化 when 程序和类型环境。
- 显式导入/更新时构建候选 generation，成功后原子激活，失败保留旧 generation。
- 每个新 Event 使用当前 input 独立求值，不缓存跨 Event 结果。
- Invocation 固定其选择时的 Catalog generation。

## 3. 非目标

- 不建立独立 Skill Registry 服务、文件监视器、自动下载或通用热更新。
- 不在 Event 热路径读取 SKILL.md/Artifact、扫描目录或调用 Compiler。

## 4. 依赖与前置条件

SR-004；[SR-013](SR-013-Compiler已检查when与发布产物.md) 的 AC-013-01 和 AC-013-05 分别提供跨语言互操作证据与正式发布 Bundle。以发布记录中的精确 Compiler SHA、Artifact API 与 Python CEL/protobuf 版本验收 EX-23 和 EX-29。

设计核对 F02 的不可变代际、原子替换和失败回滚。接入导入器时消费 SR-004。EX-23/29 的真实 CEL 正例需要 AC-013-01 的跨语言证据和 AC-013-05 的正式资产；基本代际切换用不含 when 的输入独立测试。 设计可按 SR 管理规范 §6.1 单独评审。

## 5. 验收条件

1. SKILL.md 全文和候选元数据从内存读取。
2. when 在导入时反序列化一次，每个 Event 用当前 input 独立求值。
3. Catalog 更新原子激活；失败保留旧 generation。
4. Invocation 始终使用固定 generation。
5. Go CheckedExpr 发布物与 Python Runtime 的真实互操作 fixtures 通过。

验收时必须引用演示验收基线中的对应 Acceptance ID，并记录真实执行命令、测试结果、Example 和覆盖范围。未执行项保持 NOT_RUN。

### 实施位置与复验入口

以下路径为本 SR 的目标交付物。在 ca-agent-next 仓根运行，测试通过公开入口调用受测组件。目标位置为 `src/ca_agent_next/skills/catalog.py`。在 AC-013-05 的发布输入已固定后，让两个输入对同一程序分别得到 true/false；统计反序列化一次、热路径读取 Artifact 零次。激活新代际时保留在途旧 Run；注入损坏类型描述后断言活动代际不变。

验收命令为 `python -m unittest discover -s tests -p test_catalog.py -v`。必须发现并执行本节正反例；发现 0 个测试或跳过必需用例时，退出码 0 也不能计入 PASS。逐个 Acceptance ID 回填受测 SHA、命令、预期与实测值及日志位置。
