## 3. 归档缺陷与未决项

### AC013-A01：`audit.json` 与当前归档结果文件不一致

`audit.json` inventory 的 `py-results.json` 记录为 2460 字节、SHA-256 `17cdb49bc2d5cc4aa4e4cf94ec364a16bbc45bd3a0c40bdebcba896010bd23b6`；实际 Git blob 为 2333 字节、SHA-256 `f6abbc68db58590de3d4d261f02412ea2bcdb3f38765723c02d2cf5b9b62930f`。后者与 `SHA256SUMS` 第 57 行一致，所以不是检出换行问题。现有结果语义 18/18 一致不能消除其审计清单的陈旧登记。

### AC013-A02：校验清单路径不可直接搬移复验

`SHA256SUMS` 所有路径形如 `/artifacts/...`、`/cases.json`。`reproduction.md` 却指示在归档根直接执行 `sha256sum -c SHA256SUMS`。以 `/` 开头会被常见路径解析视为文件系统根，而非归档根。上述 58/58 通过是本轮**显式归一化路径**后的结果，不能声称原命令无需修正即可复验。修复应保留清单相对路径并实际运行文档命令。

### AC013-A03：报告引用的 vet 日志缺失

`EVIDENCE.md` §2 列出 `go vet` 退出码 0，并称日志为 `vet.log`、`go-test.log`、`python.log`；固定目录没有 `vet.log`，只有后两者。`go-test.log` 不含 vet 输出。因此历史 vet 结果仍是报告记录，缺少其声明的独立日志，不计为本轮 vet PASS。

这些差异不改变历史 PoC 的有限算法参考价值，但使“完整、内部一致、可按文档直接复验的归档”尚未闭合。本 Goal 不修改固定归档，也不把缺陷修复冒充完成。

## 4. 采用、排除与新目标差异

采用历史 CheckedExpr Any、FileDescriptorSet、nullable oneof、guard/short-circuit 和确定性序列化的**算法参考**。排除 Development Artifact 作为正式 Bundle、动态类型逃逸、默认 protobuf 非确定序列化和历史 CI 作为本轮验收。

[Compiler Issue #61](https://github.com/odango-chan/ca-skill-compiler/issues/61) 当前正文仍以 `connectionagent.io/v1alpha5` 为 when 目标，并建议尽量复用旧接口；固定 Next 的 EC02/F08/F02/SR-013 则要求 1.6.0-only、Capability Binding、无旧 DTO/Artifact/Bundle 兼容。`/2` Artifact/BuildResult 仍只是候选，机器 `languageTarget`、正式 Schema、Golden 与 Release 未冻结；不能拿本归档替代这些输入。
