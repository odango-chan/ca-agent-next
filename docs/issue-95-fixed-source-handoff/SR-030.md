## 2. 采用、排除与差异

采用：Publisher 必须从固定 Revision/path 读取原始字节并核对 blob；Package ID `urn:connectionagent:ca:host-context` 与 Publisher `urn:connectionagent:owner:ca-context` 仅是稳定逻辑身份；唯一 Schema export 精确使用源 `$id`，`dependencies=[]`，0 Capability / 0 Callable，供 Contract.contexts 的 Schema closure 使用。

排除：不从 Studio 工作区、编译 Artifact 或浮动 main 重建 Schema；不把 Host Context 当 Skill `requestSchema`；不加入 ToolCatalog、Evidence、Runtime Binding、运行期 Context、Admission、签名、包级额外 hash 或 Trust Registry；不把 SR-024 的历史 Development v1alpha1 / v1alpha5 Package、旧 `1.0.0` 或其 VERIFIED 结果当成 1.6.0 PASS。

Provenance 分层：sourceRevision/Git blob 仅作 Publisher 输入与 CI 证据；`sourceStatus`、ZIP upload metadata、Package identity/version/publisher 与安装快照归 Studio Project Lock / Import Provenance；不得把这些字段扩进 Package Manifest，Studio 也不必重复保存 Git blob。该分工由 SR-030 §4 与 F09 §5 共同确认，不能靠新增自定义 Package 字段补足。

差异/未决：1.6.0 正式 Package Schema、languageTarget、SemVer、BuildRequest/DependencyInspection、Golden 和 Publisher 实施 Issue/Release 均未发布。`connectionagent.io/v1.6.0` 与版本 `2.0.0` 仍只是候选，不能作为已冻结机器契约。本核验没有生成 ZIP、调用 Compiler Link、执行 Studio reload 或六宿主测试。
