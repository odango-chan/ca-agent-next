## 2. 采用、排除、差异与缺失

### 2.1 可采用

1. 候选明确采用 `connectionagent.io/plugin-package/v1alpha1` 与 `connectionagent.io/plugin-ipc/v1alpha1`，拒绝 `ca-agent-host.plugin/v0` 及兼容别名；Event/Delivery 共用一个长生命周期 NDJSON 进程，stdout 只传帧、stderr 传诊断。
2. 候选已有三个 Event 名称和六个 slot 词汇：`nsmf.create-sm-context`、`nsmf.update-sm-context`、`nsmf.update-sm-context.continuation`；`n1/n2.request`、`n1/n2.confirmation`、`n1/n2.response`。
3. 候选明确 multipart/related、Content-ID、原始字节 staging、相对路径、byteLength、禁止 Base64/路径逃逸/额外摘要/Plugin Artifact DB，以及 Plugin 不选 Skill、不直接调用 Owner。
4. F06 固定 OpenAPI 证实 operationId、path 参数和三个 N2 response enum 的真实来源，不由本报告或 Harness 发明。

### 2.2 必须排除的历史/过期内容

1. 候选 architecture §3 的“Plugin publishes Host Artifact references”、§4 的“Run ID and responseObligationId returned in ingress.ack”、§5 的“artifactRef returned in ingress.ack”，以及 acceptance OAP-07 同义句，**均被现行 F03/F05/F06/IPC 规范排除**：ack 不得返回 Run、Skill 或 artifactRef；Plugin 不接收/保存/发送 Run ID 或 responseObligationId；Host artifactRef 留在 Host 内。
2. 候选允许从 immutable protocol fields 推导 canonical `externalRequestId`，不能替代 F06 现行规则：只在受信 Demo peer 显式发送私有 `X-CA-Request-Id` 时填写，否则为空；不得以 `smContextRef`、Content-ID 或 stream handle 冒充。
3. 候选 CA-SL v1alpha5、旧 Compiler/Skill 发布状态及旧 Codec Phase 状态只作历史材料，不能成为本轮 1.6.0-only 实施契约。
4. 历史外部 PASS/CI 记录不是本次验收证据；本报告未执行任何 Plugin、NF、peer 或 Next E2E 测试。
