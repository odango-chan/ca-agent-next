## 3. 原实现符号与 Next 语义/权威差集

静态实读：[`action_kernel.go`](https://github.com/odango-chan/ca-runtime/blob/9db2230c172da8742ecfc5049cbfbd1a71b7828f/internal/execution/engine/action_kernel.go) blob `aa248acd862dff6ba0445a427316145da732b6b0` 的 `actionKernel.Execute`、`deriveOperationOutcome`、`prepareDispatch` 调用与 Reconcile 分支；[`dispatch.go`](https://github.com/odango-chan/ca-runtime/blob/9db2230c172da8742ecfc5049cbfbd1a71b7828f/internal/execution/engine/dispatch.go) `f780fd9296d2f4dc3da4206219d28ea395b01ee5` 的 `DispatchPreparer`、`DispatchMetadata`、`DispatchInvocationID`；`predicate_definition_evaluator.go` `f0247e23fcb4c025f97bff742a3854fc74211664` 的 `DefinitionPredicateEvaluator.Evaluate`；`observation_predicate_evaluator.go` `65dbbc84684e25c25f832a9e009bedb9adb3b5b9` 的 `ObservationPredicateEvaluator.Evaluate` 与 provenance/freshness 检查。

| 语义 | 采用/简化 | 排除、差异与权威归属 |
|---|---|---|
| Run / Procedure / Node | 采用冻结 Procedure、Runtime 私有 progression、确定性 transition、checkpoint 不重复已 dispatch Action 的思想 | Next 只消费外部已发布 1.6.0 Artifact；排除源文“LLM planned/fallback procedure”成为运行时输入、mutable workspace 读取及生产 Admission/Qualification 扩散 |
| Invocation / Action Boundary | 采用 `actionKernel` 单安全内核、Authorization/Assurance/Binding 后才 dispatch；Deterministic 与 LLM-guided 共用边界 | 参考代码以 `inv.Tool.Name`/`Call.Name` 校验和路由；Next 模型只给 Capability ID，Runtime 从 1.6.0 `capabilityBindings` 唯一解析内部 Callable。旧 Callable/Operation ID、`operationBindings`、Provider 选择均不是作者输入 |
| Pre-dispatch / Artifact | 采用 `DispatchPreparer` 在 dispatch fact 前冻结 binding、失败零 Provider 调用；Next 扩展为 Run/generation/Binding/kind/Effect/Schema/Package/Artifact/deadline/budget 全部 Plugin IPC 前 fail-closed | 不复制 Go DTO、input digest/idempotency 派生或私有 backendOperationId；ArtifactRef 归 Next Host，Runtime 只做 Run/Invocation 授权，不能当 Owner Evidence |
| Outcome / Receipt | 采用 Provider 只报告 knowledge、传输成功不等于 COMMITTED、UNKNOWN 不盲重试 | **关键差异：**参考 `deriveOperationOutcome` 可由 ProviderKnowledge/CommitKnowledge 直接分类；Next 不得照搬。Owner 才拥有业务最终事实，COMMITTED/NOT_COMMITTED 须匹配原 Invocation 的 Receipt/Commit Proof；Runtime 拥有执行分类和验证/解释，不发明业务状态；Agent 只有调用者知识 |
| Reconcile / UNKNOWN | 采用 Runtime trusted Reconcile 边界、保留原 UNKNOWN lineage、post-dispatch ambiguity 不得变 NOT_COMMITTED | Next 仅 Coordinator 按 originalInvocationId、原 Run/Owner Scope、Correlation 做 exact-original Reconcile；普通 Skill/LLM 在 IPC 前 `INTERNAL_RECONCILE_ONLY`。参考 controlled retry/compensation/fallback policy 不自动采用 |
| Observation / Evidence / Predicate | 采用真实 fact owner、source/binding/ref/provenance/freshness 校验、missing/stale/invalid→UNKNOWN、Predicate 三态归 Runtime；参考 evaluator 符号可定位 | ToolResult 只是规划输入，不等于 Predicate PASS；KNOWN_ABSENT≠UNAVAILABLE。排除 GroundTruth/evaluator-only fact、5GC 专用 PDU snapshot 作为通用 Core 语义；Skill 只通过 READ Capability 获取 Observation |
| Wait / Resume / Continuation | 采用 request replay≠当前 Run query、断开≠业务取消、恢复原执行而非新 mutation 的原则 | 十份参考设计没有完整定义 Next “Wait 是目标 Node 声明的 READ trigger、无作者 await/poll”及 SR-007 AC-007-07 全部分支；以 F04/SR-007 为权威，不能从旧引擎测试反推。Continuation 精确恢复原 Run/Skill/Artifact/generation/Node/Wait，无重选/CEL 重算 |
| Execution Profile / Skill Context | 仅采用 immutable identity、显式 provenance、无 latest-by-name fallback 的思想 | **排除 GOVERNED/DIRECT 双执行治理**：Next 双模式都不得绕过统一 Action Boundary；DIRECT 跳 Procedure/Predicate/Reconcile 不是 Next 目标。RuntimeHost/ProductTask/tool-mcp-gw、旧 RuntimeSkillIdentity DTO 不复制，Next SkillCatalog 归 Core/Host |

因此采用的是可靠执行与来源语义，不是 Go 包、RuntimeHost HTTP surface、旧 Artifact/Bundle、兼容 shim 或 DIRECT 旁路。当前 1.6.0 Artifact/Compiler/Package 未发布，不能被这些历史 Accepted 文档替代。
