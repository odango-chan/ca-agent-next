## 3. 采用、差异与缺失

### 可采用

1. **权威状态分离成立**：Reference Simulator 的一进程一 World/WorldStore/C2/C6 与 Mock AMF 的独立可执行 peer 是两条路径；peer `Session` 明确只保存本地协议进度，真实 SM Context 属于目标 SMF。
2. **网络事实分离成立**：Simulator 产生 domain/protocol candidate，Service Fabric 拥有 Network Observation 和 drop/delay/reorder；peer 的应用层延迟/拒绝不能冒充 Fabric receipt。
3. **基础场景真实存在**：Create/Modify/UE Release 的请求、响应、SUPI/PSI/PTI/QFI/URI/本地 transaction 及多类负例可定位到固定源码和 YAML，不是只有场景名称。
4. **fail-closed 基础能力存在**：重复/缺失 Content-ID、错误响应、无命令、错 PTI/QFI/PSI、重复请求、旧 key/reset 后 callback 等均有源码路径。

### AC-019-02 未闭合项

| 现行要求 | 固定源实际情况 | 判定 |
|---|---|---|
| F06 同一 modify 请求可同时携带 N1/N2 confirmation，并保留两路 Content-ID/slot/discriminator | `ue_release.go` / `ue_modify.go` 的 `postUpdate` 每次只接收一个 binary `Part`；N1 与 N2 是两个独立动作 | **缺同请求双路 fixture**，不能直接满足 SR-009 AC-009-04 该子例 |
| SR-009 联合重试：受信 peer 私有 `X-CA-Request-Id`，同次重试复用、新逻辑请求换值；同 body 两操作独立验证 | 本次逐读的 peer 主路径、go.mod 和场景/fixture 中未见该头或 `externalRequestId` 投影；现有 `runId/TransactionID` 是 peer-local，不是线上稳定请求身份 | **缺联合重试 fixture 与两端次数/头证据** |
| 0xD4/N2 精确绑定原 generation/transaction；重复、迟到、旧 generation 不污染新 Run | peer 有本地 generation/tombstone 和通用 Namf stale 测试，Release 有重复 Complete；但没有旧 Owner `releaseGeneration/releaseTxn` 的线上联合投影，也未见“旧 generation 的迟到 0xD4”专门 fixture | **缺跨代/迟到 0xD4 联合证明**；不得把本地 generation 当 Owner generation |
| malformed/unknown/unsupported/conflicting discriminator、`n2SmInfoExt1` | 有通用 multipart/codec/错误响应负例，但现行 F06 新旧 discriminator 冲突及 `n2SmInfoExt1` 的专门输入未形成固定 fixture | **缺现行分类负例子集** |
| 每场景记录 Owner outcome 并独立验证最终状态 | peer 记录本地结果；真实 Owner Receipt/Proof 和最终清理由 SR-011 另取 | 属联合证据，不得由 peer 自身 PASS 代替 |
